# 知识空间维度库

知识空间由五个维度构成，每个维度包含一组刻度，用于从不同角度刻画和组织知识。

---

## 1. 时间维度

**从时间角度描述问题的状态变化规律**，将知识按时间周期组织，支持从时间轴上观察问题的演变趋势和周期性特征。

| 刻度 | 含义 |
|------|------|
| 年月 | 以月度或年度为周期进行分析和对比，观察数据随时间的变化趋势 |

---

## 2. 空间维度

**从空间范围角度划分知识层级**，将知识按组织边界或物理范围归类，支持在不同空间粒度下审视问题。

| 刻度 | 含义 |
|------|------|
| 集团 | 按集团层级进行划分，如集团总部、子公司等，从不同组织层级分析问题 |

---

## 3. 抽象层级维度

**描述知识所处的抽象程度**，从宏观到微观逐层递进，连接业务目标与具体执行细节。

| 刻度 | 含义 |
|------|------|
| 逻辑 | 从逻辑层面抽象知识，关注业务逻辑和推理规则，适用于规则推理和逻辑分析场景 |

---

## 4. 视角维度

**从不同侧面刻画问题**，每个视角代表一种观察问题的切入点或关注领域，帮助全面理解问题的多面性。

| 刻度 | 含义 |
|------|------|
| 架构管理 | 关注系统的整体架构设计、技术选型和组件间的关系，适用于系统规划和架构评审等场景 |
| 战略 | 关注长期目标设定、战略规划和愿景制定，适用于高层决策和方向性分析场景 |
| 运营 | 关注日常运作的效率和质量，包括流程执行、运营监控和持续改进等场景 |
| 服务 | 关注对外提供的服务能力、客户体验和服务质量，适用于服务设计和交付管理等场景 |
| 人员 | 关注人力资源的配置、团队管理和人员能力发展，适用于组织建设和人力规划场景 |
| 资源 | 关注资源的合理分配和高效利用，包括资金、设备、物资等资源的统筹管理 |
| 安全 | 关注系统安全、风险防控和合规保障，适用于安全审计和风险评估场景 |
| 项目 | 关注项目全生命周期的管理，包括进度控制、资源协调和交付质量等场景 |
| 标准 | 关注规范、标准和合规性要求的制定与执行，适用于标准化管理和质量保障场景 |
| 实际资源 | 关注实体资源的调配和使用，包括物理设备、场地和物资等实际资源的管理 |

---

## 5. 方面维度

**从不同分析手段和思维框架出发看待问题**，每种方面提供一种分析问题的方法论，帮助从多个维度深入理解问题本质。

| 刻度 | 含义 |
|------|------|
| 动机 | 探究问题背后的原因和驱动力，回答"为什么"，适用于根因分析和需求溯源等场景 |
| 分类法 | 对知识进行分类和归纳，建立概念体系，适用于知识组织和领域建模等场景 |
| 结构 | 分析事物的组成方式和内部架构，理清各部分之间的关系，适用于系统设计和架构分析场景 |
| 连通性 | 分析元素之间的关联关系、依赖路径和信息流动，适用于网络分析和关系探索场景 |
| 流程 | 关注工作的步骤和流转过程，理清输入输出和决策节点，适用于业务流程梳理和优化场景 |
| 状态 | 关注事物当前所处的状况和阶段，跟踪状态变化，适用于监控预警和趋势分析场景 |
| 序列 | 关注事件发生的先后顺序和时序关系，适用于时序分析和依赖规划场景 |
| 信息 | 关注数据内容、信息结构和知识表达，适用于数据分析和信息管理场景 |
| 参数 | 关注影响系统的关键数值和性能指标，适用于指标监控和参数调优场景 |
| 约束 | 关注限制性条件和边界约束，分析在约束条件下的可行方案，适用于合规检查和约束求解场景 |
| 路线图 | 关注目标的实施路径和分阶段推进计划，适用于战略分解和阶段性规划场景 |
| 可追溯性 | 关注信息的来源、变更记录和历史追踪，适用于审计追溯和版本管理场景 |
