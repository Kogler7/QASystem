# 知识图谱问答模块 (QA) - 接口文档

## 1. 模块概述

知识图谱问答模块（QA）是一个基于 Neo4j 知识图谱的智能问答系统，采用模块化设计，包含三个核心组件：问题定义、方案规划和答案生成。该模块支持自然语言问题理解、实体链接、知识图谱检索和答案生成。

### 核心特性

- **模块化设计**：三个独立组件（问题定义、方案规划、答案生成）可单独调用或组合使用
- **多跳推理**：支持基于知识图谱的深度推理，自动探索实体间的关系路径
- **实体链接**：自动识别问题中的实体并链接到知识图谱
- **大模型驱动**：利用 LLM 进行关系选择、实体评分和答案生成
- **数据来源追踪**：自动提取并返回答案的数据来源信息
- **推理日志**：记录完整的推理过程，支持可追溯性分析

## 2. 核心组件

### 2.1 组件架构

```
用户问题
    ↓
┌─────────────────────────────────────┐
│  Neo4jQAService (answer_solve.py)   │
│  - 协调整个问答流程                  │
│  - 提供统一的服务接口                │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│  组件1: ProblemDefinitionTool       │
│  - 问题定义与结构化                 │
│  - 实体识别与链接                   │
│  - 问题模型生成                     │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│  组件2: SolutionPlanningTool        │
│  - 方案规划与推理                   │
│  - 知识图谱检索（ToG搜索）          │
│  - 推理路径生成                     │
└─────────────────────────────────────┘
    ↓
┌─────────────────────────────────────┐
│  组件3: AnswerGenerationTool        │
│  - 答案生成与优化                   │
│  - 数据来源提取                     │
│  - 最终答案输出                     │
└─────────────────────────────────────┘
    ↓
最终答案
```

### 2.2 组件说明

| 组件名称 | 文件位置 | 功能描述 |
|---------|---------|---------|
| **ProblemDefinitionTool** | `tools/problem_definition.py` | 问题定义工具，将自然语言问题转化为结构化的问题模型 |
| **SolutionPlanningTool** | `tools/solution_planning.py` | 方案规划工具，执行知识图谱检索和推理路径生成 |
| **AnswerGenerationTool** | `tools/answer_generation.py` | 答案生成工具，基于方案生成最终答案并提取数据来源 |
| **Neo4jQAService** | `answer_solve.py` | 问答服务封装类，协调三个组件完成完整问答流程 |

## 3. Python 接口

### 3.1 Neo4jQAService 类

**位置**：`algorithm/ans/QA/answer_solve.py`

#### 初始化

```python
from algorithm.ans.QA.answer_solve import Neo4jQAService

# 初始化服务（使用默认配置）
service = Neo4jQAService()

# 关闭连接
service.close()
```

#### 方法说明

##### answer_question

基础问答接口，直接返回答案字符串。

```python
answer = service.answer_question("公开采购与非公开采购金额构成如何？")
```

**参数**：
- `question` (str): 用户输入的自然语言问题

**返回值**：
- `str`: 最终答案字符串

**示例**：
```python
service = Neo4jQAService()
answer = service.answer_question("采购申请数量是多少")
print(answer)
# 输出: 基于给定的知识三元组和我的知识，采购申请数量可以通过CG_007 采购申请数量指标获取，该指标的数据来源表为ads_dzcg_company_apply_annual，计算SQL为SELECT SUM(apply_count) AS value FROM ads_dzcg_company_apply_annual WHERE year = #{year}。因此，可以回答采购申请数量是多少。 数据来源于：ads_dzcg_company_apply_annual。
service.close()
```

##### answer_question_with_details

带详细信息的问答接口，返回完整的推理过程。

```python
result = service.answer_question_with_details("公开采购与非公开采购金额构成如何？")
```

**参数**：
- `question` (str): 用户输入的自然语言问题

**返回值**：
- `Dict`: 包含答案和详细推理过程的字典

**返回结构**：
```python
{
    "success": True,
    "answer": "答案字符串",
    "raw_details": {
        "问题模型": {...},
        "方案模型": {...},
        "图谱路径": {...},
        "推理日志": [...]
    }
}
```

## 5. 输入输出格式详解

### 5.1 问题模型 (ProblemModel)

```json
{
  "问题ID": "QKB-001",
  "问题类型": "DESCRIPTIVE",
  "问题描述": "公开采购与非公开采购金额构成如何？",
  "关键实体": ["公开采购", "非公开采购", "金额构成"]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| 问题ID | string | 问题唯一标识符 |
| 问题类型 | string | 问题类型（DESCRIPTIVE/EVALUATIVE等） |
| 问题描述 | string | 问题的完整描述 |
| 关键实体 | array | 问题中识别出的关键实体列表 |

```json
{
  "answer_path": [

          }
        }

  ],
```

| 字段 | 类型 | 说明 |

| properties | object | 节点属性，包含数据来源表、计算SQL等信息 |

## 6. 使用示例

### 6.1 Python 完整流程示例

```python
from algorithm.ans.QA.answer_solve import Neo4jQAService

# 初始化服务
service = Neo4jQAService()

# 测试问题
questions = [
    "公开采购与非公开采购金额构成如何？",
    "公开采购标段数的属性什么",
    "电子采购异常标段数是多少",
    "采购申请数量是多少"
]

for question in questions:
    print(f"\n{'=' * 80}")
    print(f"问题: {question}")
    print("=" * 80)
    
    # 基础问答
    answer = service.answer_question(question)
    print(f"\n答案: {answer}")
    
    # 带详细信息的问答
    result = service.answer_question_with_details(question)
    if result.get("success"):
        print(f"\n推理日志数量: {len(result.get('raw_details', {}).get('推理日志', []))}")

# 关闭连接
service.close()
```

```python
import requests
import json

BASE_URL = "http://localhost:8000/api/component/answer-generation"

# 健康检查
response = requests.get(f"{BASE_URL}/health")
print(response.json())

# 基础问答
response = requests.post(
    f"{BASE_URL}/ask",
    json={
        "question": "公开采购与非公开采购金额构成如何？",
        "detailed": False
    }
)
print(response.json())

# 带详细信息的问答
response = requests.post(
    f"{BASE_URL}/ask",
    json={
        "question": "采购申请数量是多少",
        "detailed": True
    }
)
result = response.json()
if result.get("success"):
    print(f"答案: {result['answer']}")
    print(f"推理日志: {json.dumps(result['raw_details']['推理日志'], indent=2, ensure_ascii=False)}")

# 调用三个独立组件
# 1. 问题定义
response = requests.post(
    f"{BASE_URL}/tools/problem-definition",
    json={"question": "公开采购与非公开采购金额构成如何？"}
)
problem_model = response.json()
print(f"问题模型: {json.dumps(problem_model, indent=2, ensure_ascii=False)}")

# 2. 方案规划
response = requests.post(
    f"{BASE_URL}/tools/solution-planning",
    json={"problem_model": problem_model}
)
solution_result = response.json()
print(f"方案结果: {json.dumps(solution_result, indent=2, ensure_ascii=False)}")

# 3. 答案生成
response = requests.post(
    f"{BASE_URL}/tools/answer-generation",
    json={
        "solution": solution_result.get("solution"),
        "graph_paths": solution_result.get("graph_paths"),
        "question": "公开采购与非公开采购金额构成如何？"
    }
)
answer_result = response.json()
print(f"最终答案: {answer_result}")
```

## 7. 错误处理

### 7.1 错误响应格式

```json
{
  "detail": "错误描述信息"
}
```

### 7.2 常见错误

| HTTP状态码 | 错误类型 | 说明 |
|-----------|---------|------|
| 400 | Bad Request | 请求参数错误（如问题为空、问题模型为空等） |
| 500 | Internal Server Error | 服务器内部错误（如Neo4j连接失败、LLM调用失败等） |

### 7.3 错误示例

```json
{
  "detail": "问题不能为空"
}
```
