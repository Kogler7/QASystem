# AgentCode 接口参考

面向调用方的 HTTP / SSE 协议。启动、环境变量和容量见[部署运维指南](docs/部署运维指南.md)；运行时内部见[架构设计](docs/架构设计.md)。

**生产入口**：`http://<host>:8006/agent/...`（Compose 不把 Agent `9180` 映射到宿主机）。下文路径省略 `/agent` 前缀。本地直连 Agent 时把主机换成 `127.0.0.1:9180`。

## 1. 调用约定

异步任务模型：`POST /v1/query` 立刻返回 `task_id`（HTTP 202），Worker 后台执行。过程订 SSE，终态也可轮询 `GET /v1/task/{task_id}`。

所有子公司打到**同一套后台**，共享 FIFO 和 Worker 名额。任务互不共享对话历史、鉴权上下文或 MCP 连接。带 `Authorization` / `X-Tenant-Id` / `X-User-Id` 创建的任务，查询、订阅、取消必须带同一身份，否则 **404**。无身份头的任务仅供开发期开放访问。

HTTP 问答终稿固定为 `answer-v1` JSON，见[响应格式](#4-响应格式)。

CLI 参数、环境变量、Redis 与并发旋钮以[部署运维指南](docs/部署运维指南.md)为准。MCP 连接池在进程启动时建立，不支持按请求切换 `mcp_config_path`。

## 2. API 端点一览

| 方法 | 路径 | Content-Type | 说明 |
|------|------|-------------|------|
| `GET` | `/health` | — | 健康检查（含队列深度、worker 状态） |
| `POST` | `/v1/query` | `application/json` | 提交异步任务，返回 202 + task_id |
| `POST` | `/v1/query/wait?stream=false` | `application/json` | 提交并等待终态，返回任务快照 |
| `POST` | `/v1/query/wait?stream=true` | `application/json` | 提交并立即建立 SSE |
| `GET` | `/v1/task/{task_id}` | — | 查询任务状态；若创建时带身份头，须携带同一身份 |
| `GET` | `/v1/task/{task_id}/stream` | — | SSE 流式订阅；带身份创建的任务须携带同一身份 |
| `POST` | `/v1/task/{task_id}/cancel` | — | 取消任务；带身份创建的任务须携带同一身份 |

`/v1/query` 只负责入队，由内嵌工作线程消费队列并执行 Agent 循环。

## 3. 请求参数详解

### QueryRequest

```json
{
  "user_message": "string (必需)",
  "session_id": "string (可选，默认自动生成 UUID)",
  "trace_id": "string (可选，默认自动生成 UUID)",
  "mcp_config_path": "string|null (兼容字段，通常为 null)",
  "skill_ids": ["string (可选，过滤启用的 Skill)"],
  "tool_allowlist": ["string (可选，默认 [\"*\"])"],
  "max_turns": "int (可选，默认 50)",
  "max_tool_calls": "int (可选，默认 70)",
  "max_time_s": "int (可选，默认 1200)",
  "history": [{"role": "user", "content": "上一轮问题"}]
}
```

| 字段 | 类型 | 必需 | 默认值 | 说明 |
|------|------|------|--------|------|
| `user_message` | `string` | ✅ | — | 用户输入的自然语言问题 |
| `session_id` | `string` | 否 | `uuid4().hex` | 会话关联 ID，不自动恢复历史 |
| `history` | `list[{role, content}]` | 否 | `[]` | 调用方显式传入的多轮上下文 |
| `trace_id` | `string` | 否 | `uuid4().hex` | 链路追踪 ID |
| `mcp_config_path` | `string\|null` | 否 | `null` | 兼容字段；不同于启动配置时返回 HTTP 400 |
| `skill_ids` | `list[string]` | 否 | `[]` | Skill 白名单过滤；为空则加载全部发现的 Skill |
| `tool_allowlist` | `list[string]` | 否 | `["*"]` | 工具白名单（fnmatch 通配符），`["*"]` 表示全部允许 |
| `max_turns` | `int` | 否 | `50` | 最大 LLM 对话轮数 |
| `max_tool_calls` | `int` | 否 | `70` | 最大工具调用次数 |
| `max_time_s` | `int` | 否 | `1200` | 最大墙钟时间（秒） |

### tool_allowlist 示例

```json
// 只允许统一 MCP 中的图谱检索工具
{"tool_allowlist": ["qasystem-tools__locate_knowledge_space", "qasystem-tools__search_graph"]}

// 全部允许（默认）
{"tool_allowlist": ["*"]}
```

## 4. 响应格式

### GET /health

**响应 200：**

```json
{
  "status": "ok",
  "pid": 12345,
  "queue_depth": 3,
  "concurrency": 8,
  "pool": {
    "total": 8,
    "in_use": 3,
    "available": 5,
    "total_errors": 0,
    "total_borrows": 42
  }
}
```

| 字段 | 说明 |
|------|------|
| `status` | 服务状态 |
| `pid` | 当前响应请求的进程 ID（多 worker 时每次可能不同） |
| `queue_depth` | 当前队列中等待处理的任务数 |
| `concurrency` | 当前进程的工作线程数 |
| `pool` | ToolManager 连接池状态（仅当前进程） |

---

### POST /v1/query — 提交异步任务

**请求示例：**

```bash
curl -X POST http://127.0.0.1:8006/agent/v1/query \
  -H "Content-Type: application/json" \
  -d '{
    "user_message": "查询上个月的故障率",
    "session_id": "sess-001",
    "max_turns": 20
  }'
```

**响应 202 Accepted：**

```json
{
  "task_id": "a1b2c3d4e5f6...",
  "status": "queued",
  "queue_position": 3
}
```

**响应 503 — 队列不可用：**

```json
{"detail": "task_store unavailable: ..."}
```

---

### POST /v1/query/wait — 提交并等待

请求体与 `/v1/query` 相同。

普通等待：

```bash
curl -X POST 'http://127.0.0.1:8006/agent/v1/query/wait?stream=false' \
  -H 'Content-Type: application/json' \
  -d '{"user_message":"查询上个月的故障率"}'
```

任务进入 `completed`、`failed` 或 `cancelled` 后返回 HTTP 200 和完整任务快照。超过 `max_time_s + 120` 秒仍未进入终态时返回 HTTP 504，但这只结束 HTTP 等待，不会自动取消后台任务。

流式等待：

```bash
curl -N -X POST 'http://127.0.0.1:8006/agent/v1/query/wait?stream=true' \
  -H 'Content-Type: application/json' \
  -d '{"user_message":"查询上个月的故障率"}'
```

该模式立即返回 SSE，协议与 `/v1/task/{task_id}/stream` 相同。

### GET /v1/task/{task_id} — 查询任务状态

**响应 200 — 排队中：**

```json
{
  "task_id": "a1b2c3d4...",
  "status": "queued",
  "created_at": "2026-05-23T10:00:00",
  "updated_at": "2026-05-23T10:00:00",
  "result": null,
  "error": null,
  "queue_position": 2
}
```

**响应 200 — 执行完成：**

```json
{
  "task_id": "a1b2c3d4...",
  "status": "completed",
  "created_at": "2026-05-23T10:00:00",
  "updated_at": "2026-05-23T10:00:45",
  "result": {
    "payload": {
      "conclusion": "根据查询结果，最近一周故障率为 2.3%。",
      "evidence": [
        {"name": "故障率", "id": "ku-fault-rate", "detail": "近 7 日均值为 2.3%"}
      ],
      "assumptions": [],
      "gaps": [],
      "confidence": "high",
      "confidence_reason": "知识空间✓ 实体✓ 方案类✓ 工具✓",
      "charts": [],
      "solution_path": ["步骤1 查询近一周故障记录"]
    },
    "spent": {"turns": 5, "tool_calls": 8}
  },
  "error": null,
  "queue_position": 0
}
```

HTTP 问答的 `result.payload` 固定为 `answer-v1`（Worker 写入 `DeliveryConfig`，不合格则重试，预算内仍失败返回 `DELIVERY_NOT_SATISFIED`）。请求体不能改 schema。

| 字段 | 类型 | 说明 |
|------|------|------|
| `conclusion` | string | 对用户问题的直接回答 |
| `evidence` | object[] | 图谱/数据依据，项含 `name`、`detail`，可选 `id` |
| `assumptions` | string[] | 实际使用的假设，没有则为 `[]` |
| `gaps` | string[] | 知识缺口或工具失败 |
| `confidence` | `high` \| `medium` \| `low` | 证据门结论 |
| `confidence_reason` | string | 判定理由 |
| `charts` | object[] | `draw_*` 产物，项含 `path`，可选 `title` |
| `solution_path` | string[] | 方案类模板步骤；未展示路径则为 `[]` |

**响应 200 — 执行失败：**

```json
{
  "task_id": "a1b2c3d4...",
  "status": "failed",
  "error": "BUDGET_EXCEEDED: Turn budget exceeded",
  "result": null
}
```

**响应 404 — 任务不存在：**

```json
{"detail": "task not found: a1b2c3d4..."}
```

### POST /v1/task/{task_id}/cancel — 取消任务

请求体为空。排队任务立即进入 `cancelled`；运行中任务先进入 `cancelling`，随后由 Worker 协作式停止。

```bash
curl -X POST http://127.0.0.1:8006/agent/v1/task/a1b2c3d4/cancel
```

```json
{
  "task_id": "a1b2c3d4",
  "status": "cancelling",
  "cancel_requested": true,
  "result": null,
  "error": null,
  "queue_position": 0
}
```

已进入 `completed`、`failed` 或 `cancelled` 的任务保持原状态。不存在的任务返回 HTTP 404。

## 5. SSE 流式事件

`GET /v1/task/{task_id}/stream`（`POST /v1/query/wait?stream=true` 协议相同）。

```bash
curl -N http://127.0.0.1:8006/agent/v1/task/a1b2c3d4/stream
```

响应头：`Content-Type: text/event-stream`，`Cache-Control: no-cache`，`X-Accel-Buffering: no`。任务不存在时直接 **HTTP 404 JSON**，不会先建流再发 error。

格式：仅 `data: <JSON>`，无 `event:` 前缀；类型在 `data.type`。可选 `id:` 行。断线用查询参数 `cursor` 或请求头 `Last-Event-ID` 续传（不再重复首条快照）。空闲约 15 秒发 SSE 注释 `: heartbeat`。

未带游标时第一条是当前任务快照（`type: status`）。若已终态，发完该条即关闭。执行中持续推送，最后一条一定是 `done`。

`token` 是过程增量，正式答案以 `status: completed` 的 `payload`（`answer-v1`）为准。

| type | 何时出现 | 要点 |
|------|----------|------|
| `status` | 入队/开跑/终态 | `queued` / `running` / `cancelling` / `completed` / `failed` / `cancelled`。`completed` 带 `payload`、`spent` |
| `token` | LLM 输出正文 | `{ "text": "…" }`，连续多条 |
| `reasoning` | 思考链模型 | 可选，`{ "text": "…" }` |
| `tool_calls` | 本轮决定调工具 | `{ "calls": [{ "name", "input" }] }` |
| `tool_result` | 每个工具结束 | `name`、`is_error`、`content` 或 `error` |
| `solution_path` | 路径展示工具成功 | `{ "path": { "question", "solution_path", "reasoning_summary" } }` |
| `trace` | 每轮 LLM 判定后 | 诊断用：`turn`、`outcome`、`delivery_error` |
| `error` | LLM 流式异常 | 随后通常 `failed` + `done` |
| `done` | 始终最后一条 | 客户端应关连接 |
| `heartbeat` | 空闲保活 | 注释行，不是 JSON 事件 |

```
POST /v1/query                → 202 + task_id
GET  /v1/task/{id}/stream
  status queued → status running
  token* / reasoning* / tool_calls / tool_result / solution_path / trace
  status completed {payload: answer-v1} → done
```

## 6. 错误码

| 错误码 | 说明 | 触发条件 |
|--------|------|---------|
| `BUDGET_EXCEEDED` | 预算超限 | 达到 `max_turns`、`max_tool_calls` 或 `max_time_s` |
| `CONSTRAINT_VIOLATION` | 约束违规 | 尝试调用白名单之外的工具 |
| `DELIVERY_NOT_SATISFIED` | 交付格式不符 | 终稿不满足 `answer-v1` JSON Schema |
| `REPEAT_ACTION_DETECTED` | 重复操作 | 连续 N 次完全相同工具调用 |
| `CANCELLED` | 任务取消 | 调用取消接口或 CancellationToken |
| `LLM_ERROR` | 模型错误 | 模型连接、协议或响应异常 |
| `TOOL_UNAVAILABLE` | 工具不可用 | 模型请求了未注册工具 |
| `MCP_PROTOCOL_ERROR` | MCP 错误 | MCP 连接或工具调用失败 |
| `HTTP 404` | 任务不存在 | task_id 无效、过期或身份不匹配 |
| `HTTP 503` | Task Store 不可用 | 队列/存储操作失败 |
| `HTTP 504` | 等待超时 | `/v1/query/wait` 超过 `max_time_s + 120` 秒（只断 HTTP，不自动取消后台任务） |

## 7. 使用示例

下文以生产反代为例。把 `BASE` 换成实际地址；本地直连 Agent 用 `http://127.0.0.1:9180`。

```bash
BASE=http://127.0.0.1:8006/agent

TASK=$(curl -s -X POST $BASE/v1/query \
  -H "Content-Type: application/json" \
  -d '{"user_message": "查询最近一周故障率"}')
TASK_ID=$(echo $TASK | python3 -c "import sys,json; print(json.load(sys.stdin)['task_id'])")

# 轮询终态
curl -s $BASE/v1/task/$TASK_ID

# 或订过程
curl -N $BASE/v1/task/$TASK_ID/stream
```

```python
import json
import time
import httpx

BASE = "http://127.0.0.1:8006/agent"

def wait_result(message: str) -> dict:
    with httpx.Client(timeout=600) as client:
        task_id = client.post(f"{BASE}/v1/query", json={"user_message": message}).json()["task_id"]
        while True:
            info = client.get(f"{BASE}/v1/task/{task_id}").json()
            if info["status"] in ("completed", "failed", "cancelled"):
                return info
            time.sleep(2)

def stream(message: str):
    with httpx.Client(timeout=600) as client:
        task_id = client.post(f"{BASE}/v1/query", json={"user_message": message}).json()["task_id"]
        with client.stream("GET", f"{BASE}/v1/task/{task_id}/stream") as resp:
            for line in resp.iter_lines():
                if line.startswith("data: "):
                    print(json.loads(line[6:]))
```

运行时内部、连接池和 Redis 语义见[架构设计](docs/架构设计.md)。
