## 1. 启动方式

### 安装依赖

```bash
cd agent
pip install -e ".[api]"        # API 服务（内嵌 worker，推荐）
pip install -e ".[api,dev]"    # API + 测试依赖
```

### 一键启动（推荐）

```bash
agentcode-api
```

服务启动后自动初始化 ToolManager 连接池并拉起工作线程，无需额外启动 worker 进程。

```
API worker: pool 1/1 就绪
API worker: 发现 3 个 skill
API worker: 1 个工作线程已启动, pool_size=1
INFO:     Uvicorn running on http://0.0.0.0:9180
```

### CLI 参数

| 参数 | 环境变量 | 默认值 | 说明 |
|------|---------|--------|------|
| `--host` | — | `0.0.0.0` | 绑定地址 |
| `--port` | — | `9180` | HTTP 端口 |
| `--workers` | `AGENT_API_WORKERS` | `1` | uvicorn worker 进程数（多进程模式需 Redis） |
| `--concurrency` | `AGENT_WORKER_CONCURRENCY` | `1` | 每进程工作线程数 |
| `--pool-size` | `AGENT_WORKER_POOL_SIZE` | `=concurrency` | ToolManager 连接池大小 |

### 启动示例

```bash
# 开发环境（单进程，可使用内存队列）
agentcode-api

# 单进程高并发
agentcode-api --concurrency 8

# 生产环境：2 进程 × 8 线程 = 16 并发（需 Redis）
agentcode-api --workers 2 --concurrency 8

# 高吞吐：4 进程 × 16 线程 = 64 并发（需 Redis）
agentcode-api --workers 4 --concurrency 16
```

当前版本使用 API lifespan 内嵌 Worker；尚未提供独立 `agentcode-worker` CLI。

## 2. 并发模型

### 默认模式（API 内嵌 worker）

```
agentcode-api --workers 2 --concurrency 8

uvicorn 主进程
  ├── API worker 进程 0 (pid=1001)
  │     ├── lifespan → 初始化 ToolManagerPool × 8
  │     ├── 线程 0: dequeue → borrow → execute → update → 循环
  │     ├── 线程 1: dequeue → borrow → execute → update → 循环
  │     ├── ...
  │     └── 线程 7: dequeue → borrow → execute → update → 循环
  │
  ├── API worker 进程 1 (pid=1002)
  │     ├── lifespan → 初始化 ToolManagerPool × 8
  │     └── 线程 0..7 ...
  │
  └── 共享 Redis 可靠队列 + Redis Stream 事件流
```

**总并发 = `--workers` × `--concurrency`**

所有进程/线程竞争同一个 Redis 队列，无需额外协调。每个 uvicorn worker 进程独立管理自己的 ToolManager 连接池和工作线程，一个进程崩溃不影响其他。

### 队列选择

| 模式 | 队列 | 说明 |
|------|------|------|
| 单进程 (`--workers 1`) | MemoryQueue 或 Redis | MemoryQueue 自动降级，进程重启丢失 |
| 多进程 (`--workers >= 2`) | Redis（必需） | 跨进程共享，需设置 `TASK_STORE_REDIS_URL` |

## 3. 环境变量配置

服务统一加载仓库根目录 `.env`。

### LLM 配置

| 变量名 | 必需 | 默认值 | 说明 |
|--------|------|--------|------|
| `AGENT_LLM_BASE_URL` | 否 | `http://localhost:9999` | Agent 专用 LLM API 地址 |
| `AGENT_LLM_API_KEY` | 否 | — | Agent 专用 API 密钥 |
| `AGENT_LLM_MODEL` | 否 | `Qwen/Qwen3-8B` | Agent 专用模型名称 |
| `AGENT_TEMPLATE_TEMPERATURE` | 否 | `0.2` | LLM 温度参数 |
| `AGENT_TEMPLATE_MAX_TOKENS` | 否 | `4096` | LLM 单次最大输出 token |
| `AGENT_TEMPLATE_TIMEOUT_SECONDS` | 否 | `120` | LLM API 调用超时（秒） |

### 并发配置

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `AGENT_API_WORKERS` | `1` | API 服务的 uvicorn worker 进程数（`agentcode-api --workers`） |
| `AGENT_WORKER_CONCURRENCY` | `1` | 每进程工作线程数 |
| `AGENT_WORKER_POOL_SIZE` | `=concurrency` | ToolManager 连接池大小 |

### 队列/存储配置

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `TASK_STORE_REDIS_URL` | `redis://localhost:6379/0` | Redis 连接 URL（多进程模式必需） |
| `TASK_STORE_KEY_PREFIX` | `agentcode:task` | Redis key 前缀 |
| `TASK_STORE_TASK_TTL` | `86400` | 任务在 Redis 中的过期时间（秒） |
| `TASK_STORE_MAX_QUEUE` | `50000` | 队列最大长度 |
| `TASK_STORE_VISIBILITY_TIMEOUT` | `1500` | Worker 失联后任务重新入队的秒数；运行中任务会自动续租 |
| `TASK_STORE_EVENT_MAXLEN` | `10000` | 每个任务最多保留的流式事件数 |

### 其他

| 变量名 | 默认值 | 说明 |
|--------|--------|------|
| `COMPACT_TOKEN_THRESHOLD` | `100000` | 触发上下文压缩的 token 阈值 |

### .env 示例


### MCP 配置文件

服务需要 MCP 配置文件来连接工具服务器。默认路径为 `agent/agentcode/tools/mcp_tools/mcp_config.json`，可通过 `AGENT_MCP_CONFIG` 在服务启动时覆盖。连接池在启动时建立，因此不支持每个请求切换 MCP 配置。

MCP 配置文件格式：

```json
{
  "mcpServers": {
    "qasystem-tools": {
      "transport": "streamable_http",
      "url": "http://127.0.0.1:8000/mcp"
    }
  }
}
```

已加载的 MCP 工具按服务分组：

| MCP 服务 | 功能 | 说明 |
|----------|------|------|
| `qasystem-tools` | 统一业务工具 | 知识处理、知识空间定位、图谱检索、SQL 查询和数据可视化 |
| `base` | 命令行 | 在 Agent 运行环境中执行命令（含格式校验、黑名单和资源限制） |

## 4. API 端点一览

| 方法 | 路径 | Content-Type | 说明 |
|------|------|-------------|------|
| `GET` | `/health` | — | 健康检查（含队列深度、worker 状态） |
| `POST` | `/v1/query` | `application/json` | 提交异步任务，返回 202 + task_id |
| `POST` | `/v1/query/wait?stream=false` | `application/json` | 提交并等待终态，返回任务快照 |
| `POST` | `/v1/query/wait?stream=true` | `application/json` | 提交并立即建立 SSE |
| `GET` | `/v1/task/{task_id}` | — | 查询任务状态 |
| `GET` | `/v1/task/{task_id}/stream` | — | SSE 流式轮询任务状态 |
| `POST` | `/v1/task/{task_id}/cancel` | — | 取消排队任务或请求协作式取消运行中任务 |

`/v1/query` 只负责入队，由内嵌工作线程消费队列并执行 Agent 循环。

## 5. 请求参数详解

### QueryRequest

```json
{
  "user_message": "string (必需)",
  "session_id": "string (可选，默认自动生成 UUID)",
  "trace_id": "string (可选，默认自动生成 UUID)",
  "mcp_config_path": "string|null (兼容字段，通常为 null)",
  "skill_ids": ["string (可选，过滤启用的 Skill)"],
  "tool_allowlist": ["string (可选，默认 [\"*\"])"],
  "max_turns": "int (可选，默认 50)",
  "max_tool_calls": "int (可选，默认 70)",
  "max_time_s": "int (可选，默认 1200)"
}
```

| 字段 | 类型 | 必需 | 默认值 | 说明 |
|------|------|------|--------|------|
| `user_message` | `string` | ✅ | — | 用户输入的自然语言问题 |
| `session_id` | `string` | 否 | `uuid4().hex` | 会话 ID，用于追踪 |
| `trace_id` | `string` | 否 | `uuid4().hex` | 链路追踪 ID |
| `mcp_config_path` | `string\|null` | 否 | `null` | 兼容字段；不同于启动配置时返回 HTTP 400 |
| `skill_ids` | `list[string]` | 否 | `[]` | Skill 白名单过滤；为空则加载全部发现的 Skill |
| `tool_allowlist` | `list[string]` | 否 | `["*"]` | 工具白名单（fnmatch 通配符），`["*"]` 表示全部允许 |
| `max_turns` | `int` | 否 | `50` | 最大 LLM 对话轮数 |
| `max_tool_calls` | `int` | 否 | `70` | 最大工具调用次数 |
| `max_time_s` | `int` | 否 | `1200` | 最大墙钟时间（秒） |

### tool_allowlist 示例

```json
// 只允许统一 MCP 中的图谱检索工具
{"tool_allowlist": ["qasystem-tools__locate_knowledge_space", "qasystem-tools__search_graph"]}

// 全部允许（默认）
{"tool_allowlist": ["*"]}
```

## 6. 响应格式

### GET /health

**响应 200：**

```json
{
  "status": "ok",
  "pid": 12345,
  "queue_depth": 3,
  "concurrency": 8,
  "pool": {
    "total": 8,
    "in_use": 3,
    "available": 5,
    "total_errors": 0,
    "total_borrows": 42
  }
}
```

| 字段 | 说明 |
|------|------|
| `status` | 服务状态 |
| `pid` | 当前响应请求的进程 ID（多 worker 时每次可能不同） |
| `queue_depth` | 当前队列中等待处理的任务数 |
| `concurrency` | 当前进程的工作线程数 |
| `pool` | ToolManager 连接池状态（仅当前进程） |

### POST /v1/query — 提交异步任务

**请求示例：**

```bash
curl -X POST http://localhost:9180/v1/query \
  -H "Content-Type: application/json" \
  -d '{
    "user_message": "查询上个月的故障率",
    "session_id": "sess-001",
    "max_turns": 20
  }'
```

**响应 202 Accepted：**

```json
{
  "task_id": "a1b2c3d4e5f6...",
  "status": "queued",
  "queue_position": 3
}
```

**响应 503 — 队列不可用：**

```json
{"detail": "task_store unavailable: ..."}
```

---

### POST /v1/query/wait — 提交并等待

请求体与 `/v1/query` 相同。

普通等待：

```bash
curl -X POST 'http://localhost:9180/v1/query/wait?stream=false' \
  -H 'Content-Type: application/json' \
  -d '{"user_message":"查询上个月的故障率"}'
```

任务进入 `completed`、`failed` 或 `cancelled` 后返回 HTTP 200 和完整任务快照。超过 `max_time_s + 120` 秒仍未进入终态时返回 HTTP 504，但这只结束 HTTP 等待，不会自动取消后台任务。

流式等待：

```bash
curl -N -X POST 'http://localhost:9180/v1/query/wait?stream=true' \
  -H 'Content-Type: application/json' \
  -d '{"user_message":"查询上个月的故障率"}'
```

该模式立即返回 SSE，协议与 `/v1/task/{task_id}/stream` 相同。

### GET /v1/task/{task_id} — 查询任务状态

**响应 200 — 排队中：**

```json
{
  "task_id": "a1b2c3d4...",
  "status": "queued",
  "created_at": "2026-05-23T10:00:00",
  "updated_at": "2026-05-23T10:00:00",
  "result": null,
  "error": null,
  "queue_position": 2
}
```

**响应 200 — 执行完成：**

```json
{
  "task_id": "a1b2c3d4...",
  "status": "completed",
  "created_at": "2026-05-23T10:00:00",
  "updated_at": "2026-05-23T10:00:45",
  "result": {
    "payload": { /* 交付数据 */ },
    "spent": {"turns": 5, "tool_calls": 8}
  },
  "error": null,
  "queue_position": 0
}
```

**响应 200 — 执行失败：**

```json
{
  "task_id": "a1b2c3d4...",
  "status": "failed",
  "error": "BUDGET_EXCEEDED: Turn budget exceeded",
  "result": null
}
```

**响应 404 — 任务不存在：**

```json
{"detail": "task not found: a1b2c3d4..."}
```

### POST /v1/task/{task_id}/cancel — 取消任务

请求体为空。排队任务立即进入 `cancelled`；运行中任务先进入 `cancelling`，随后由 Worker 协作式停止。

```bash
curl -X POST http://localhost:9180/v1/task/a1b2c3d4/cancel
```

```json
{
  "task_id": "a1b2c3d4",
  "status": "cancelling",
  "cancel_requested": true,
  "result": null,
  "error": null,
  "queue_position": 0
}
```

已进入 `completed`、`failed` 或 `cancelled` 的任务保持原状态。不存在的任务返回 HTTP 404。

## 7. SSE 流式事件

### GET /v1/task/{task_id}/stream — 流式轮询

**请求示例：**

```bash
curl -N http://localhost:9180/v1/task/a1b2c3d4/stream
```

### 响应头

| 响应头 | 值 | 说明 |
|--------|-----|------|
| `Content-Type` | `text/event-stream` | SSE 流 |
| `Cache-Control` | `no-cache` | 禁止缓存 |
| `X-Accel-Buffering` | `no` | 禁用 nginx 缓冲 |

### 事件类型

#### `status` — 状态变更

```json
data: {"type":"status","task_id":"a1b2c3d4","status":"queued","queue_position":3}
```

状态可能依次为 `queued`、`running`、`cancelling` 和 `completed` / `failed` / `cancelled`。

#### `error` — 执行过程异常

```json
data: {"type":"error","error":"上游模型连接超时"}
```

任务不存在时，订阅端点直接返回 HTTP 404 JSON，不会先建立 SSE 再发送 error 事件。

### 时序

```
POST /v1/query                   → 202 + task_id（立刻）
GET  /v1/task/{id}/stream        → 开始 SSE 连接
  data: {type:status, status:queued}     ← 当前快照
  data: {type:status, status:running}    ← Worker 开始执行
  data: {type:token, text:...}           ← 模型输出
  data: {type:tool_calls, calls:[...]}   ← 可选
  data: {type:tool_result, ...}          ← 可选
  data: {type:status, status:completed}  ← 终态
  data: {type:done}
  连接关闭
```

## 8. 错误码

| 错误码 | 说明 | 触发条件 |
|--------|------|---------|
| `BUDGET_EXCEEDED` | 预算超限 | 达到 `max_turns`、`max_tool_calls` 或 `max_time_s` |
| `CONSTRAINT_VIOLATION` | 约束违规 | 尝试调用白名单之外的工具 |
| `DELIVERY_NOT_SATISFIED` | 交付格式不符 | LLM 输出不满足 delivery JSON Schema |
| `REPEAT_ACTION_DETECTED` | 重复操作 | 连续 N 次完全相同工具调用 |
| `CANCELLED` | 任务取消 | 调用取消接口或本地 CancellationToken 触发 |
| `LLM_ERROR` | 模型错误 | 模型连接、协议或响应异常 |
| `TOOL_UNAVAILABLE` | 工具不可用 | 模型请求了未注册工具 |
| `MCP_PROTOCOL_ERROR` | MCP 错误 | MCP 连接或工具调用失败 |
| `HTTP 404` | 任务不存在 | task_id 无效或已过期 |
| `HTTP 503` | Task Store 不可用 | 当前存储操作失败；单进程仅在启动阶段尝试降级内存 |
| `HTTP 504` | 任务超时 | `/v1/query/wait` 等待超过 `max_time_s + 120` 秒 |

## 9. 使用示例

### 9.1 提交任务 + 轮询结果

```bash
# 1. 提交任务
TASK=$(curl -s -X POST http://localhost:9180/v1/query \
  -H "Content-Type: application/json" \
  -d '{"user_message": "帮我查一下北京地铁1号线最近一周的故障情况"}')
TASK_ID=$(echo $TASK | python3 -c "import sys,json; print(json.load(sys.stdin)['task_id'])")
echo "Task: $TASK_ID"

# 2. 轮询直到完成
while true; do
  STATUS=$(curl -s http://localhost:9180/v1/task/$TASK_ID | python3 -c "import sys,json; print(json.load(sys.stdin)['status'])")
  echo "Status: $STATUS"
  [ "$STATUS" = "completed" ] || [ "$STATUS" = "failed" ] || [ "$STATUS" = "cancelled" ] && break
  sleep 2
done

# 3. 获取最终结果
curl -s http://localhost:9180/v1/task/$TASK_ID | python3 -m json.tool
```

### 9.2 SSE 流式等待

```bash
curl -N http://localhost:9180/v1/task/$TASK_ID/stream
```

### 9.3 Python 客户端示例

```python
import httpx
import json
import time

def sync_query(message: str) -> dict:
    """提交任务并阻塞等待结果。"""
    with httpx.Client(timeout=600) as client:
        resp = client.post("http://localhost:9180/v1/query", json={"user_message": message})
        task_id = resp.json()["task_id"]

        while True:
            resp = client.get(f"http://localhost:9180/v1/task/{task_id}")
            info = resp.json()
            if info["status"] in ("completed", "failed", "cancelled"):
                return info
            time.sleep(2)

def stream_query(message: str):
    """SSE 流式等待。"""
    with httpx.Client(timeout=600) as client:
        resp = client.post("http://localhost:9180/v1/query", json={"user_message": message})
        task_id = resp.json()["task_id"]

        with client.stream("GET", f"http://localhost:9180/v1/task/{task_id}/stream") as stream:
            for line in stream.iter_lines():
                if line.startswith("data: "):
                    event = json.loads(line[6:])
                    print(f"[{event['type']}] {event}")
```

## 10. 架构说明

### 10.1 请求处理流程（默认内嵌模式）

```
HTTP 请求
  │
  ├─ GET /health ─── 返回 {"status":"ok", "pid":..., "concurrency":..., "pool":...}
  │
  └─ POST /v1/query
       └─ task_store.enqueue(task_id, request_data)  ← ~1ms
            └─ Redis LPUSH / MemoryQueue append
       └─ 202 {"task_id": "..."}

                          ┌──────────────────────────────────────┐
                          │  FastAPI lifespan 拉起的工作线程       │
                          │                                      │
                          │  线程 0: while not stop:             │
                          │    task = task_store.dequeue()        │ ← Redis 可靠领取 + processing
                          │    pool.borrow(tm)                    │ ← 借 ToolManager
                          │    AgentRuntime.run_session()         │ ← 执行 Agent 循环
                          │    task_store.update()                │ ← 写回结果
                          │                                      │
                          │  线程 1..N: （同上，并发执行）         │
                          └──────────────────────────────────────┘

  GET /v1/task/{id}
       └─ task_store.get(task_id)  ← Redis HGETALL / MemoryQueue dict
       └─ 返回当前状态 + 结果

  GET /v1/task/{id}/stream
       └─ SSE 循环: 从 Redis Stream / Memory event log 按游标读取
       └─ 状态变化时推送 event
```

### 10.2 连接池模型

```
FastAPI lifespan (每 uvicorn worker 进程)
    │
    ├─ ToolManagerPool(size=N)      ← N = --pool-size
    │     ├─ ToolManager[0]         ← MCP 连接 (所有配置的服务器)
    │     ├─ ToolManager[1]
    │     ├─ ...
    │     └─ ToolManager[N-1]
    │
    └─ borrow/return: 线程安全的 Condition 等待
         线程 0 借 TM[0], 线程 1 借 TM[1], ...
         用完归还, 下一个线程复用
```

### 10.3 降级策略

| 组件 | 正常 | 降级 |
|------|------|------|
| task_store | Redis 可靠队列、租约与 Stream（多进程共享） | MemoryQueue（单进程，进程重启丢失） |
| ToolManager | 连接池 N 个 | 初始化数量为 0 时服务启动失败 |
| Worker | 内嵌线程（lifespan 管理） | 当前未提供独立 Worker CLI |
