# AgentCode 开发扩展指南

本文面向需要修改 AgentCode、接入新模型、新 MCP Server、新工具或新 Skill 的开发者。

## 一、开发环境

在仓库根目录执行：

```powershell
cd agentcode
..\.venv\Scripts\python.exe -m pip install -e ".[api,dev]"
$env:PYTHONPATH = "$PWD"
python -m pytest tests -q
```

也可以不安装 editable 包，从仓库根目录设置：

```powershell
$env:PYTHONPATH = "$PWD\agentcode"
.\.venv\Scripts\python.exe -m pytest agentcode/tests -q
```

修改原则：

- 通用控制逻辑放在 runtime；
- HTTP/队列逻辑放在 api、worker、task_store；
- 业务知识放在 Skill；
- 业务动作放在 MCP Server；
- 不要在 Agent loop 中添加某个业务领域的硬编码分支。

## 三、核心数据模型

源码：`agentcode/models.py`

### 3.1 SessionConfig

```python
from agentcode.models import (
    BudgetConfig,
    DeliveryConfig,
    SessionConfig,
    SkillRef,
    ToolPolicy,
)

config = SessionConfig(
    session_id="session-001",
    trace_id="trace-001",
    skills=[SkillRef(id="problem-solve")],
    tool_policy=ToolPolicy(allow=["qasystem-tools__*"]),
    budget=BudgetConfig(
        max_turns=50,
        max_tool_calls=70,
        max_time_s=1200,
        max_retries_per_tool=2,
        repeat_action_threshold=10,
    ),
    tool_execution="sequential",
    delivery=DeliveryConfig(
        output_schema_id="answer-v1",
        json_schema={
            "type": "object",
            "required": ["answer"],
            "properties": {"answer": {"type": "string"}},
        },
    ),
)
```

注意：`model` 字段当前是宿主可用的元数据，内置 Worker 仍从 `AGENT_LLM_MODEL` 读取实际模型。

### 3.2 FinalResult

成功结果：

```json
{
  "status": "ok",
  "payload": {"text": "..."},
  "warnings": [],
  "error": null,
  "spent": {"turns": 3, "tool_calls": 2},
  "trace_ref": "task://..."
}
```

失败或取消结果的 `error` 包含稳定的 `code` 和可读的 `message`。

### 3.3 错误码

| 错误码 | 含义 |
| --- | --- |
| `CANCELLED` | 显式取消 |
| `BUDGET_EXCEEDED` | 时间、轮次或工具次数超限 |
| `REPEAT_ACTION_DETECTED` | 连续重复同一工具动作 |
| `CONSTRAINT_VIOLATION` | 工具不在白名单 |
| `DELIVERY_NOT_SATISFIED` | 预算内无法满足终稿 Schema |
| `LLM_ERROR` | 模型请求或响应异常 |
| `TOOL_UNAVAILABLE` | 工具不存在 |
| `MCP_PROTOCOL_ERROR` | MCP 调用失败 |

## 四、实现 LLMBackend

协议定义：

```python
class LLMBackend(Protocol):
    def complete(
        self,
        messages: list[dict],
        tools: list[dict],
        cancel_token=None,
    ) -> dict:
        ...
```

返回值必须是 AgentCode 内部 assistant 格式。

纯文本示例：

```python
return {
    "role": "assistant",
    "content": [{"type": "text", "text": "最终答案"}],
}
```

工具调用示例：

```python
return {
    "role": "assistant",
    "content": [
        {
            "type": "tool_use",
            "id": "call-001",
            "name": "qasystem-tools__search_graph",
            "input": {"start_entity_id": "123", "depth": 1},
        }
    ],
}
```

适配器必须遵守：

- 保留稳定且非空的 tool call ID；
- 工具 arguments 解析失败时不要执行猜测后的参数；
- 在流式循环中频繁检查 `cancel_token.is_cancelled()`；
- 单次 HTTP timeout 不得大于 `cancel_token.remaining_seconds()`；
- 上游异常向外抛出，由 AgentRuntime 转为 `LLM_ERROR`。

内置实现位于：

- `worker.py::_StreamingWorkerLLM`；
- `worker.py::_BlockingLLM`；
- `cli.py::_StreamingLLM`。

## 五、接入 MCP Server

### 5.1 配置格式

HTTP：

```json
{
  "mcpServers": {
    "knowledge": {
      "transport": "streamable_http",
      "url": "http://backend:8000/mcp",
      "headers": {
        "X-Tenant-ID": "tenant-a"
      }
    }
  }
}
```

stdio：

```json
{
  "mcpServers": {
    "local-tools": {
      "transport": "stdio",
      "command": "python",
      "args": ["-m", "my_mcp_server"],
      "env": {
        "PYTHONPATH": "/app/tools"
      }
    }
  }
}
```

引用环境变量中的 Bearer Token：

```json
{
  "mcpServers": {
    "remote": {
      "transport": "streamable_http",
      "url": "https://example.internal/mcp",
      "auth_ref": "REMOTE_MCP_TOKEN"
    }
  }
}
```

`auth_ref` 是环境变量名，不是 Token 本身。

只有一个 MCP Server 时，`AGENT_MCP_URL` 可以覆盖配置文件中的 URL，便于同一运行包在本地和 Compose 网络中使用不同地址。

### 5.2 工具命名

注册到模型的名称是：

```text
{server_name}__{mcp_tool_name}
```

例如：

```text
qasystem-tools__search_graph
```

修改 Server 名称会同时改变所有工具名，需要同步更新 Skill 和白名单。

### 5.3 工具 Schema 建议

- 根类型使用 `object`；
- 明确 `properties` 和 `required`；
- description 写明单位、约束和错误含义；
- 避免同一参数同时接受多种完全不同的结构；
- 返回结构保持稳定；
- 写操作接受 `idempotency_key`。

AgentCode 向 OpenAI 兼容 API 发送工具前，会移除部分兼容性较差的 Schema 字段，如 `$schema`、`definitions` 和 `$defs`。

### 5.4 MCP 返回值

MCP SDK 的 `CallToolResult.content` 会被格式化为字符串：

- text 内容直接拼接；
- data 内容 JSON 序列化；
- 其他媒体类型保留 MIME 标识。

如果业务需要保留复杂结构，建议 MCP 工具把结构化结果编码成稳定 JSON 文本，并在 description 中说明 Schema。

## 六、添加内置工具

当前内置工具位于 `agentcode/tools/base_tools/`。

添加工具时应提供：

1. OpenAI/MCP 风格 Schema；
2. 同名 handler；
3. 稳定的错误前缀或结构；
4. timeout 和 cancel_token 传递；
5. 单元测试；
6. 在 ToolManager 中注册。

内部保留参数：

```text
_agent_timeout_s
_agent_cancel_token
```

这些参数由 ToolManager 注入，不应出现在模型可见的工具 Schema 中。

## 七、创建 Skill

目录约定：

```text
agentcode/agentcode/skillsets/<skill-id>/SKILL.md
```

示例：

```markdown
---
name: incident-analysis
description: 当用户需要分析故障原因和处置方案时使用。
inject_layer: developer
---

# 故障分析

## 触发条件

...

## 工具使用

...

## 输出要求

...
```

建议正文包含：

- 明确触发条件和不适用条件；
- 可用工具的完整名称；
- 参数来源和证据要求；
- 工具失败后的回退路径；
- 禁止编造的内容；
- 最终输出结构。

Skill ID 当前取 Skill 文件所在目录名。目录名必须稳定且唯一。

### 7.1 Skill 加载流程

1. 服务启动时扫描 metadata；
2. 请求可用 `skill_ids` 过滤；
3. system prompt 描述可用 Skill；
4. 模型调用 `Skill` 工具；
5. 运行时读取完整正文；
6. 正文作为内部消息写入当前上下文。

## 八、修改 Agent loop

修改 `runtime.py` 前先判断需求属于哪一层：

| 需求 | 应修改位置 |
| --- | --- |
| 新业务步骤 | Skill 或 MCP |
| 新模型协议 | LLMBackend/adapter |
| 新工具传输 | MCP wrapper |
| 新任务状态 | models、task_store、worker、API |
| 新预算/循环控制 | runtime |
| 新流式事件 | worker、trace、接口文档 |

修改 loop 时必须保持：

- 每次 LLM 调用准确增加 turn；
- 工具预算在执行前检查；
- 取消在阻塞操作前后检查；
- assistant tool call 与 tool result ID 一一对应；
- 每条路径最终返回 `FinalResult`；
- Delivery 修正不能绕过最大轮次。

## 九、任务存储扩展

新的 Task Store 实现需要提供：

```text
enqueue
dequeue
update
get
queue_length
cancel
is_cancel_requested
touch
publish_event
get_events
```

可靠实现还必须满足：

- 领取任务不会立即永久删除；
- Worker 崩溃后可重新投递；
- 终态确认会移除 processing；
- 多订阅者不会竞争同一事件；
- 事件读取有稳定游标；
- 任务和事件有保留上限。

## 十、测试策略

### 10.1 单元测试

重点覆盖：

- Runtime 的工具往返、终稿、预算、取消和异常；
- ToolManager 白名单、重试和结果映射；
- MCP 配置解析；
- Shell 参数解析和资源限制；
- MemoryQueue 状态与事件游标；
- API 参数和状态码。

### 10.2 Redis 集成测试

设置独立测试库：

```powershell
$env:TEST_REDIS_URL = "redis://127.0.0.1:6379/15"
python -m pytest tests/test_task_store_redis.py -q
```

测试会执行 `FLUSHDB`，不要指向开发或生产 Redis DB。

### 10.3 Linux 测试

以下能力必须在 Linux 验证：

- `resource` 限制；
- Shell 命令执行；
- 只读源码/根文件系统导入；
- 容器内 MCP 网络地址；
- Worker 优雅关闭。
