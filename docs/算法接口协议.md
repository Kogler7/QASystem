# 算法接口协议

本文档描述当前代码实际暴露的 HTTP 协议，面向调用方、联调人员和契约测试维护者。默认部署地址为：

```text
http://127.0.0.1:8006
```

端口可通过根目录 `.env` 中的 `BACKEND_HOST_PORT` 修改。容器内服务端口固定为 `8000`。

## 1. 接口清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/health` | 后端存活检查 |
| `POST` | `/api/knowledge/precipitation` | 文档解析、切片、知识抽取、图谱向量化及可选入库 |
| `POST` | `/api/component/nl2cypher/text-to-vectors` | 批量文本向量化 |
| `POST` | `/api/component/kg-update/calculate-confidence` | 图谱关系置信度计算 |
| `GET` | `/file/{file_id}/{file_name}` | 下载知识沉淀产生的本地产物 |

统一 MCP Streamable HTTP 服务挂载在 `/mcp`，不属于本文的业务 HTTP 协议。服务同时提供 FastAPI 的 `/docs`、`/redoc` 和 `/openapi.json`。

当前不提供单文本 `/api/component/nl2cypher/text-to-vector` 接口。

## 2. 通用约定

| 项目 | 约定 |
| --- | --- |
| 认证 | 当前无认证 |
| JSON 编码 | UTF-8 |
| 成功判断 | HTTP 为 `2xx` 且响应体 `code` 为 `0` |
| JSON Content-Type | `application/json` |
| 文件上传 Content-Type | `multipart/form-data` |
| 时间 | 接口不接收客户端时间；评估编号由服务器本地时间生成 |

除健康检查和文件下载外，响应使用统一外层结构：

```json
{
  "code": 0,
  "message": "success",
  "info": "success",
  "data": {},
  "error": null
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `code` | integer | `0` 成功；非 `0` 失败 |
| `message` | string | 面向调用方的结果信息 |
| `info` | string | 与 `message` 相同的兼容字段 |
| `data` | object/array/null | 成功数据；部分流水线失败时可能含已生成产物 |
| `error` | object/null | 失败时包含 `stage` 和 `details`；成功时为 `null` |

参数校验失败通常返回 HTTP `400` 或 `422`，流水线或未处理异常返回 HTTP `500`。调用方不能只依据 HTTP 状态或只依据 `code`，应同时检查两者。

### 2.1 错误码

| `code` | 名称 | 含义 |
| ---: | --- | --- |
| `0` | 成功 | 请求处理成功 |
| `1000` | 请求无效 | 表单、JSON、字段范围或业务前置条件不合法 |
| `1001` | 文档解析失败 | 文件类型不支持、依赖缺失、转换失败或解析结果为空 |
| `1002` | 知识抽取失败 | 至少一个文本切片抽取失败 |
| `1003` | 切片失败 | 切片参数错误或未产生切片 |
| `1004` | 向量化失败 | 本地向量模型加载或编码失败 |
| `1005` | 存储失败 | 本地产物、外部文件服务或 Neo4j 写入失败 |
| `1006` | 置信度计算失败 | 保留给置信度业务失败 |
| `1999` | 内部错误 | 未分类的服务端异常 |

通用参数校验错误示例：

```json
{
  "code": 1000,
  "message": "请求参数校验失败",
  "info": "请求参数校验失败",
  "data": null,
  "error": {
    "stage": "validation",
    "details": []
  }
}
```

## 3. 健康检查与本地产物

### 3.1 健康检查

```http
GET /health
```

成功响应：

```json
{"status":"ok"}
```

该接口只表示后端进程可响应，不探测 LLM、模型目录、Neo4j、Elasticsearch、MySQL 或文件服务的可用性。

### 3.2 本地产物下载

未配置 `FILE_SERVICE_URL` 且请求未传 `file_service_url` 时，知识沉淀产物保存在后端数据卷，并返回 `/file/...` 相对地址。调用方需用同一后端 Base URL 补全地址：

```http
GET /file/{file_id}/{file_name}
```

文件存在时返回原始文件流，不存在时返回 HTTP `404`。配置外部文件服务后，产物地址由外部服务返回，不使用本接口。

## 4. 知识沉淀

```http
POST /api/knowledge/precipitation
Content-Type: multipart/form-data
```

流水线顺序为：文档解析为 Markdown → 保存解析产物 → 文本切片 → 各切片并发知识抽取 → 合并图谱 → 可选写入 Neo4j → 保存抽取产物 → 对每个切片的图谱 JSON 批量向量化 → 保存向量产物。

### 4.1 请求字段

| 字段 | 表单类型 | 必填 | 默认值 | 说明 |
| --- | --- | :---: | --- | --- |
| `file` | file | 是 | — | 待处理文件，内容不能为空 |
| `ontology` | string | 是 | — | PlantUML 本体定义，去除空白后不能为空 |
| `parser_config` | string | 否 | `{}` | 严格 JSON 字符串；详见[文档解析行为规范](文档解析行为规范.md) |
| `chunk_character` | string | 否 | 内置分隔符 | JSON 字符串数组，如 `["。","\\n"]` |
| `chunk_size` | integer | 否 | `500` | 大于 `0` |
| `chunk_type` | integer | 否 | `0` | `0` 默认递归、`1` 指定符号、`2` 自定义递归、`3` Markdown |
| `similarity` | number | 否 | `0.6` | `0` 到 `1`；当前保留在协议中，现有切片实现未使用该值参与算法计算 |
| `save_to_db` | boolean | 否 | `false` | 是否把合并图谱写入 Neo4j |
| `model` | string | 否 | 环境配置 | 覆盖本次知识抽取的 LLM 模型名 |
| `base_url` | string | 否 | 环境配置 | 覆盖本次 OpenAI-compatible LLM 地址 |
| `knowledge_space_id` | string | 否 | 空 | 传给外部文件服务的知识空间 ID |
| `file_service_url` | string | 否 | `FILE_SERVICE_URL` | 覆盖本次产物文件服务地址；都为空时使用本地存储 |

支持扩展名：`.pdf`、`.docx`、`.doc`、`.pptx`、`.ppt`、`.png`、`.jpg`、`.jpeg`、`.md`、`.txt`、`.xlsx`、`.xls`、`.csv`、`.html`、`.htm`。

`parser_config` 禁止额外字段和类型自动转换。例如字符串 `"false"` 不能代替布尔值 `false`。本体方言、类型/属性标识规则和示例见[知识抽取说明](../algorithm/knowledge_extract/README.md)。

### 4.2 请求示例

```bash
curl -X POST 'http://127.0.0.1:8006/api/knowledge/precipitation' \
  -F 'file=@./demo.html' \
  -F 'ontology=<./ontology.puml' \
  -F 'parser_config={"engine":"auto"}' \
  -F 'chunk_type=0' \
  -F 'knowledge_space_id=ks-demo'
```

### 4.3 成功响应

`data` 字段：

| 路径 | 类型 | 说明 |
| --- | --- | --- |
| `name` | string | 原文件名，不含扩展名 |
| `understanding` | string | 基于合并图谱生成的节点/关系统计摘要 |
| `origin_url` | string/null | 解析后 Markdown 产物地址 |
| `extract_url` | string/null | 分片抽取结果及合并图谱 JSON 地址 |
| `vector_url` | string/null | 分片图谱 JSON 的向量结果地址 |
| `graphs.graphs` | array | 按切片返回的图谱；`graph.index` 为字符串形式的切片序号 |
| `stats.document` | object | 文件名、大小、类型、内容长度和精简解析信息 |
| `stats.extraction` | object | 抽取数量、图谱数量、LLM 尝试和调度参数；入库时还含 `database` |
| `stats.chunking` | object | 切片数、类型、大小、分隔符、向量维度及向量来源 |
| `stats.storage` | object | 三类产物的存储结果 |
| `stats.total_time_seconds` | number | 总处理耗时（秒） |

精简解析信息位于 `data.stats.document.parser`，字段定义见[文档解析行为规范](文档解析行为规范.md)。抽取调度信息 `stats.extraction.scheduler` 反映本次进程配置的最大并发数、QPS 和 QPM。

### 4.4 产物格式与序号对齐

`extract_url` 指向的 JSON：

```json
{
  "count": 1,
  "items": [
    {"index": 0, "text": "原 Markdown 切片", "raw": "LLM 原始结果", "graph": {}}
  ],
  "graph": {"nodes": [], "relationships": []}
}
```

`vector_url` 指向的 JSON：

```json
{
  "count": 1,
  "dimension": 1024,
  "items": [
    {"index": 0, "original_json": {}, "text": "序列化后的图谱 JSON", "vector": []}
  ]
}
```

`extract_url` 的 `items[].index`、响应的 `graphs[].graph.index` 和 `vector_url` 的 `items[].index` 表示同一个切片序号。响应中的序号是字符串，两个产物中的序号是整数。

### 4.5 失败与部分结果

知识抽取、Neo4j 入库等后续阶段失败时，`data` 可能返回已经保存的 `origin_url` 或已合并图谱。调用方应把 `code != 0` 视为整体失败，并按需记录这些部分结果用于排障，不能把部分结果当作完整沉淀结果。

## 5. 批量文本向量化

```http
POST /api/component/nl2cypher/text-to-vectors
Content-Type: application/json
```

请求体：

```json
{"texts":["知识地图","","接口烟测"]}
```

`texts` 必须是至少包含一个元素的字符串数组。接口保留输入顺序和空字符串，不静默删除元素。向量模型由 `VECTOR_MODEL_PATH` 指定，并以本地文件模式加载。

成功响应：

```json
{
  "code": 0,
  "message": "批量文本向量化完成，共 3 个向量",
  "info": "批量文本向量化完成，共 3 个向量",
  "data": {
    "count": 3,
    "texts": ["知识地图", "", "接口烟测"],
    "vectors": [[0.123], [0.0], [-0.234]],
    "items": [
      {"index": 0, "text": "知识地图", "vector": [0.123]},
      {"index": 1, "text": "", "vector": [0.0]},
      {"index": 2, "text": "接口烟测", "vector": [-0.234]}
    ]
  },
  "error": null
}
```

`vectors[i]`、`items[i].vector` 和 `texts[i]` 一一对应。空数组或字段类型错误返回 HTTP `422`、错误码 `1000`；模型加载或编码异常返回 HTTP `500`、错误码 `1999`。

## 6. 图谱关系置信度计算

```http
POST /api/component/kg-update/calculate-confidence
Content-Type: application/json
```

请求体顶层必须包含对象字段 `graph`。算法同时处理 `graph.relationships` 与 `graph.ontology_relations`，并把结果写入每条关系的 `properties.confidence`。

```json
{
  "graph": {
    "nodes": [
      {"uid": "term::采购金额", "label": "Term", "properties": {"name": "采购金额"}},
      {"uid": "metric::amount", "label": "Metric", "properties": {"name": "金额"}}
    ],
    "relationships": [
      {"from_uid": "term::采购金额", "to_uid": "metric::amount", "type": "MAPS_TO"}
    ],
    "ontology_relations": []
  }
}
```

成功响应：

```json
{
  "code": 0,
  "message": "置信度评估完成",
  "info": "置信度评估完成",
  "data": {
    "evaluation_id": "EVAL-20260715143000123456",
    "total_count": 1,
    "graph": {
      "nodes": [],
      "relationships": [
        {
          "from_uid": "term::采购金额",
          "to_uid": "metric::amount",
          "type": "MAPS_TO",
          "properties": {"confidence": 0.79}
        }
      ],
      "ontology_relations": []
    },
    "details": {
      "0": {
        "from_uid": "term::采购金额",
        "to_uid": "metric::amount",
        "type": "MAPS_TO",
        "text_score": 0.8,
        "path_score": 0.77,
        "text_weight": 0.7,
        "path_weight": 0.3,
        "confidence": 0.791
      }
    }
  },
  "error": null
}
```

`details` 的键按 `relationships` 在前、`ontology_relations` 在后的合并顺序从 `0` 编号。两类关系都为空或缺失时不加载评分资源，直接成功返回 `total_count: 0`、原节点及空关系列表。

置信度计算依赖本地语义模型、Elasticsearch 文本证据和 Neo4j 路径证据；实际权重来自 [`algorithm/confidence_calculate/config.yaml`](../algorithm/confidence_calculate/config.yaml)。字段缺失时算法会使用空字符串或空数组继续计算；如果调用方需要更严格的数据质量约束，应在调用前自行校验图谱结构。

## 7. 协议维护

以下实现是协议事实来源：

- 路由与请求模型：`backend/app/routers/`、`backend/app/schemas.py`
- 通用响应与错误码：`backend/app/responses.py`
- 知识沉淀响应：`backend/app/services/knowledge_precipitation.py`
- 契约测试：`backend/tests/test_knowledge_protocol.py`

修改路径、字段、默认值、错误码、序号类型或成功响应结构时，应同时更新本协议与契约测试。
