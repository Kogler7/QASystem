# 算法接口协议

本文描述当前代码实际暴露的 HTTP 接口。默认宿主机地址为 `http://127.0.0.1:8006`，容器内端口为 `8000`。

## 1. 通用约定

成功 JSON 统一为：

```json
{
  "code": 0,
  "info": "success",
  "data": {},
  "error": null
}
```

失败结构、错误码、HTTP 状态和重试规则见[错误码协议](错误码协议.md)。

## 2. 接口清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/api/v1/documents/parse` | 文档解析为 Markdown |
| `POST` | `/api/v1/documents/chunk` | Markdown 切片及原文偏移 |
| `POST` | `/api/v1/graphs/extract` | 按输入顺序批量抽取分片 graph |
| `POST` | `/api/v1/graphs/merge` | 对多个 graph 做确定性去重 |
| `POST` | `/api/v1/embeddings/texts` | 按输入顺序批量文本向量化 |
| `POST` | `/api/v1/embeddings/graphs` | 按输入顺序批量 graph JSON 向量化 |
| `POST` | `/api/v1/graphs/confidence` | 图谱关系置信度计算 |
| `POST` | `/api/v1/pipelines/knowledge-ingestion` | 聚合知识沉淀流水线 |
| `GET` | `/health` | 后端存活检查 |

## 3. 文档解析

```http
POST /api/v1/documents/parse
Content-Type: multipart/form-data
```

### 输入

```bash
curl -X POST 'http://127.0.0.1:8006/api/v1/documents/parse' \
  -F 'file=@./demo.docx' \
  -F 'options={"engine":"auto","mineru_options":{"language":"ch","ocr_mode":"auto","table_enable":true,"formula_enable":true}}'
```

`options` 是 JSON 字符串，结构如下：

```json
{
  "engine": "auto",
  "mineru_options": {
    "language": "ch",
    "ocr_mode": "auto",
    "table_enable": true,
    "formula_enable": true
  }
}
```

`engine` 支持 `auto`、`text`、`docling`、`vlm`、`mineru`、`pandas` 和 `beautifulsoup`，并接受 `excel`、`html`、`bs4` 别名。`engine=auto` 时，服务根据文件类型和内容特征选择首选解析器。显式指定 `engine` 时，该解析器必须与文件类型兼容；它可能成为首选解析器，也可能作为首选解析失败后的候选解析器。客户端不能仅根据请求配置推断实际使用的解析器，应读取响应中的 `data.parser`：

- `preferred_engine`：服务根据文件判断出的首选解析器。
- `requested_engine`：客户端显式请求的解析器；请求为 `auto` 时不返回。
- `request_handling`：本次请求解析器的处理方式，例如命中首选、作为 fallback 候选或因不兼容被忽略。
- `final_engine`：最终成功生成 Markdown 的解析器。
- `fallback`：实际发生回退时返回原解析器及失败原因；未回退时不返回。

`mineru_options` 是 MinerU/VLM 执行配置，只用于请求，不在 `data.parser` 中重复回显。

### 输出

```json
{
  "code": 0,
  "info": "文档解析完成",
  "data": {
    "file_name": "demo.docx",
    "file_size": 1024,
    "file_type": "docx",
    "markdown": "# Demo\n正文",
    "content_length": 9,
    "parser": {
      "preferred_engine": "docling",
      "requested_engine": "mineru",
      "request_handling": "fallback_candidate",
      "final_engine": "mineru",
      "fallback": {"from_engine": "docling", "reason": "Docling 解析失败"}
    }
  },
  "error": null
}
```

原子解析接口只返回 Markdown 和执行状态，不保存产物。

## 4. Markdown 切片

```http
POST /api/v1/documents/chunk
Content-Type: application/json
```

### 输入

```json
{
  "file_name": "demo.md",
  "markdown": "# Demo\n第一段。第二段。",
  "options": {
    "strategy": "recursive",
    "size": 500,
    "separators": ["。", "\n"],
    "similarity": 0.6
  }
}
```

切片策略：

| `strategy` | 机制 |
| --- | --- |
| `recursive` | 使用内置分隔符递归切分，优先保持段落和句子完整，适合作为默认策略 |
| `symbols` | 按 `separators` 中的符号切分，并按 `size` 组合片段 |
| `custom_recursive` | 使用调用方提供的 `separators` 执行递归切分 |
| `markdown` | 按 Markdown 标题和块结构切分，再受 `size` 约束 |

`size` 是目标切片字符数，不保证每片严格等长。`separators` 只对 `symbols` 和 `custom_recursive` 生效。`similarity` 是预留的语义切分阈值参数，当前四种策略尚未使用它。具体切分顺序、长度控制、参数限制和 `range` 定位规则见[文档切片算法说明](文档切片算法说明.md)。

### 输出

```json
{
  "code": 0,
  "info": "文档切片完成",
  "data": {
    "count": 1,
    "items": [
      {
        "text": "# Demo\n第一段。第二段。",
        "range": [0, 15]
      }
    ]
  },
  "error": null
}
```

偏移是输入 `markdown` 的 Python 字符索引。

## 5. 分片图谱抽取

```http
POST /api/v1/graphs/extract
Content-Type: application/json
```

### 输入

```json
{
  "ontology": "@startuml\nclass Term\n@enduml",
  "items": [
    {"text": "采购金额是采购合同的签约金额。"}
  ],
  "options": {"model": null, "merge": true}
}
```

接口为每个 `items` 元素独立调用 LLM，并允许多个切片并发抽取 graph，最终响应仍保持输入顺序。调用层使用服务端配置的共享并发、QPS 和 QPM 调度器；`options.model` 可选择服务端允许的模型，但请求不能覆盖 LLM Base URL。任一切片在重试后仍失败时，本次批量请求整体失败，并在错误详情中给出失败位置。

### 输出

```json
{
  "code": 0,
  "info": "分片图谱抽取完成",
  "data": {
    "graph": {
      "nodes": [{"uid": "Term::采购金额", "label": "Term", "properties": {"name": "采购金额"}}],
      "relationships": []
    }
  },
  "error": null
}
```

`merge` 默认为 `true`。此时节点按 `uid` 去重，关系按 `from_uid + to_uid + type` 去重，并返回单个 `graph`。该过程是确定性去重，不是实体消歧或知识融合。

当 `merge=false` 时不执行跨切片去重，响应不包含 `graph`，而是返回：

```json
{
  "graphs": [
    {"nodes": [], "relationships": []},
    {"nodes": [], "relationships": []}
  ]
}
```

`merge=false` 时，请求 `items[i]` 与响应 `graphs[i]` 按顺序一一对应。字符范围属于文档切片能力，不是图谱抽取参数；聚合流水线会独立保留切片产生的 `ranges`。

## 6. Graph 去重

```http
POST /api/v1/graphs/merge
Content-Type: application/json
```

### 输入

```json
{
  "items": [
    {"graph": {"nodes": [], "relationships": []}},
    {"graph": {"nodes": [], "relationships": []}}
  ]
}
```

### 输出

```json
{
  "code": 0,
  "info": "Graph 去重完成",
  "data": {
    "count": 2,
    "graph": {"nodes": [], "relationships": []}
  },
  "error": null
}
```

节点按 `uid` 去重并合并属性，关系按 `from_uid + to_uid + type` 去重。

## 7. 文本向量化

```http
POST /api/v1/embeddings/texts
Content-Type: application/json
```

### 输入

```json
{
  "items": [
    {"text": "知识地图"},
    {"text": ""}
  ]
}
```

### 输出

```json
{
  "code": 0,
  "info": "文本向量化完成，共 2 个向量",
  "data": {
    "count": 2,
    "dimension": 1024,
    "items": [
      {"text": "知识地图", "vector": [0.123, -0.456]},
      {"text": "", "vector": [0.0, 0.0]}
    ]
  },
  "error": null
}
```

空字符串保留，不会被静默删除。


```json
{
  "items": [
    {
      "graph": {
        "nodes": [{"uid": "Term::采购金额", "label": "Term", "properties": {"name": "采购金额"}}],
        "relationships": []
      }
    }
  ]
}
```

### 输出

```json
{
  "code": 0,
  "info": "Graph 向量化完成，共 1 个向量",
  "data": {
    "count": 1,
    "dimension": 1024,
    "items": [
      {
        "graph": {
          "nodes": [{"uid": "Term::采购金额", "label": "Term", "properties": {"name": "采购金额"}}],
```

## 9. 图谱关系置信度

```http
POST /api/v1/graphs/confidence
Content-Type: application/json
```

### 输入

```json
{
  "graph": {
    "nodes": [
      {"uid": "Term::采购金额", "label": "Term", "properties": {"name": "采购金额"}},
      {"uid": "Metric::金额", "label": "Metric", "properties": {"name": "金额"}}
    ],
    "relationships": [
      {"from_uid": "Term::采购金额", "to_uid": "Metric::金额", "type": "MAPS_TO"}
    ],
    "ontology_relations": []
  }
}
```

### 输出

```json
{
  "code": 0,
  "info": "置信度评估完成",
  "data": {
    "evaluation_id": "EVAL-20260715143000123456",
    "total_count": 1,
    "relationships": [
      {
        "text_score": 0.8,
        "path_score": 0.77,
        "text_weight": 0.7,
        "path_weight": 0.3,
        "confidence": 0.791
      }
    ],
    "ontology_relations": []
  },
  "error": null
}
```

`relationships[i]` 与请求 `graph.relationships[i]` 对齐，`ontology_relations[i]` 与请求 `graph.ontology_relations[i]` 对齐。响应不重复返回输入 graph，也不使用字符串形式的数组下标作为对象字段。

## 10. 聚合知识沉淀

```http
POST /api/v1/pipelines/knowledge-ingestion
Content-Type: multipart/form-data
```

该接口组合前述底层能力，按以下顺序执行：

1. 使用文档解析能力生成 Markdown，并记录实际解析器状态。
2. 使用文档切片能力生成有序文本块和原文字符范围。
3. 对每个文本块并发执行图谱抽取，根据 `extraction.merge` 决定是否跨切片去重。
4. 配置文件服务时，对文本块执行向量化并写入外部向量存储。
5. `storage.persist_graph=true` 时，将最终图谱写入服务端配置的 Neo4j。

聚合接口复用与底层接口相同的实现和配置语义，不定义另一套解析、切片、抽取或去重规则。

### 输入

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | :---: | --- |
| `file` | file | 是 | 原始文档 |
| `ontology` | string | 是 | PlantUML 本体 |
| `options` | JSON string | 否 | 严格流水线配置，默认 `{}` |

```bash
curl -X POST 'http://127.0.0.1:8006/api/v1/pipelines/knowledge-ingestion' \
  -F 'file=@./demo.docx' \
  -F 'ontology=<./ontology.puml' \
  -F 'options={"parser":{"engine":"auto"},"chunking":{"strategy":"recursive","size":500},"extraction":{"merge":true}}'
```

完整 `options`：

```json
{
  "parser": {
    "engine": "auto",
    "mineru_options": {
      "language": "ch",
      "ocr_mode": "auto",
      "table_enable": true,
      "formula_enable": true
    }
  },
  "chunking": {
    "strategy": "recursive",
    "size": 500,
    "separators": null,
    "similarity": 0.6
  },
  "extraction": {
    "model": null,
    "merge": true
  },
  "storage": {
    "persist_graph": false,
    "knowledge_space_id": null
  }
}
```

`parser`、`chunking` 和 `extraction` 分别采用文档解析、文档切片和分片图谱抽取章节定义的规则。`storage.persist_graph` 控制是否写入 Neo4j；`storage.knowledge_space_id` 会透传给外部文件与向量服务。客户端不能通过该接口覆盖 LLM `base_url` 或 `FILE_SERVICE_URL`。

### 输出

```json
{
  "code": 0,
  "info": "知识沉淀完成",
  "data": {
    "name": "demo",
    "parser": {
      "preferred_engine": "docling",
      "requested_engine": "mineru",
      "request_handling": "fallback_candidate",
      "final_engine": "mineru",
      "fallback": {"from_engine": "docling", "reason": "Docling 解析失败"}
    },
    "summary": "共抽取 1 个节点（1 个 Term）和 0 条关系。",
    "artifacts": {
      "markdown": {
        "id": "a1",
        "name": "demo.md",
        "path": "/files/demo.md",
        "url": "https://files.example/demo.md"
      },
      "vector_ids": ["44e9419e-ffc8-4b14-bd12-4c9e0950169f"]
    },
    "extraction": {
      "ranges": [[0, 17]],
      "graph": {
        "nodes": [
          {"uid": "Term::采购金额", "label": "Term", "properties": {"name": "采购金额"}}
        ],
        "relationships": []
      }
    },
    "stats": {
      "document": {
        "file_name": "demo.docx",
        "file_type": "docx",
        "content_length": 1024
      },
      "chunking": {
        "chunk_count": 1,
        "strategy": "recursive",
        "size": 500,
        "vector_dimension": 1024
      },
      "extraction": {
        "chunks_extracted": 1,
        "merge": true,
        "nodes_extracted": 1,
        "relationships_extracted": 0,
        "attempts": [],
        "scheduler": {"max_concurrency": 4, "qps": 2, "qpm": 60}
      },
      "total_time_seconds": 1.234
    }
  },
  "error": null
}
```

`data.name` 来自上传文件名去除最后一个扩展名。`data.parser` 与文档解析接口的执行状态格式一致。`data.extraction` 与分片图谱抽取接口遵循相同的 `merge` 返回规则。

服务不做本地产物存储。配置 `FILE_SERVICE_URL` 后，服务上传 Markdown，并把原始文本切片向量写入同一 Base URL 下的 `/third/vectors/store`。未配置时不会上传 Markdown 或执行向量存储，`artifacts` 为 `null`。

`ranges[i]` 与 `artifacts.vector_ids[i]` 按切片顺序对应；`merge=false` 时，`graphs[i]` 也与二者对应。`stats.extraction.attempts` 和 `scheduler` 是运行观测信息，不属于图谱抽取业务结果。

## 11. 健康检查

```http
GET /health
```

```json
{"status":"ok"}
```

健康检查只表示后端进程可以响应，不检查 LLM、Neo4j、Elasticsearch、向量模型或文件服务。

## 12. Deprecated aliases

| 历史路径 | 正式替代路径 |
| --- | --- |
| `POST /api/knowledge/precipitation` | `POST /api/v1/pipelines/knowledge-ingestion` |
| `POST /api/component/nl2cypher/text-to-vectors` | `POST /api/v1/embeddings/texts` |
| `POST /api/component/kg-update/calculate-confidence` | `POST /api/v1/graphs/confidence` |

历史 POST 接口只保留路径 alias，请求字段和响应 `data` 与对应 v1 接口完全一致。区别仅是 OpenAPI deprecated 标记和 `info` 中的迁移提示：

```json
{
  "code": 0,
  "info": "知识沉淀完成（Deprecated：请迁移至 /api/v1/pipelines/knowledge-ingestion）",
  "data": {},
  "error": null
}
```
