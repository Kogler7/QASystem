### 1.1 两类算法范围

#### 1.1.1 知识沉淀

`文档解析 → Markdown 标准化 → 文档切片 → 分片知识抽取 → Graph 合并去重 → 文本/图向量化 → 知识落库或外部持久化 → 结果与证据回溯`。

#### 1.1.2 问题求解

`问题理解 → ProblemFrame → Skill 选择 → MCP 原子工具调用 → 知识空间定位/实体链接/图谱逐跳探索 → 证据门 → 方案/数据执行 → 带证据结果`。

1. 知识沉淀 HTTP 能力：文档解析、切片、抽取、合并、文本/图向量化及知识摄取流水线。
2. 知识沉淀外部集成：按配置将知识资产交给外部应用服务持久化；未开通能力显式失败。
3. 问题求解 Agent loop：使用标准 MCP 和 Skill 集合完成问题理解、图谱导航、证据组织和执行。
4. 统一错误码、超时、重试、健康检查和服务契约。

## 8 集成和测试（对应 Sheet `8集成和测试1`）

### 8.1 集成策略

- 每日构建：提交后执行轻量契约测试和静态检查。
- 按需集成：算法 API 与 Backend/Agent/MCP 变更时执行接口联调。
- 迭代集成：Sprint 结束前进行端到端集成、数据链路和异常路径验证。
- 发布集成：统一验收前冻结版本，记录代码 commit、配置、模型版本和测试环境。

### 8.2 测试策略

| 类型 | 重点 | 方法/工具 |
|---|---|---|
| 单元测试 | 解析、切片、抽取解析、Graph 合并、剪枝逻辑 | pytest、固定 fixture、边界/异常测试 |
| 接口测试 | `/api/v1` 请求响应、错误码、幂等、超时 | pytest/http client、Postman 或等效工具 |
| 集成测试 | Backend→算法→Agent/MCP→应用服务 | 真实集成环境、Mock 外部依赖、队列回归 |
| 数据质量测试 | 实体、关系、证据、重复和孤立节点 | 规则校验、抽样人工复核 |
| 性能测试 | 解析、抽取、向量化、图检索时延和吞吐 | JMeter/Locust/项目统一工具，指标待确认 |
| 安全与可靠性 | 鉴权上下文隔离、敏感头不落盘、取消/重试 | 契约测试、故障注入、日志审计 |

未开通的图写入、置信度、文档证据等第三方能力，测试用例必须验证其返回明确错误，而不是模拟成功。

## 9 与 DoD 的对齐

进入迭代评审前，至少满足：需求/设计/测试用例已评审；核心算法代码已评审；代码已提交配置库；自动化/单元测试已执行；P0/P1 缺陷关闭或有批准例外；集成测试证据完整；文档、接口和数据结构与代码一致。组织级覆盖率、重复率、注释率和缺陷修复率按甲方最终口径填写。

## 10 历史 8 个月项目的补录规则

补录材料必须以 Git commit、现有测试、接口文档、发布日志和会议记录为证据；无法追溯的日期写“待核实”，不得倒填虚构时间。历史工作可按功能主题归并到 Sprint 1–4，但每条归并记录需标注“历史补录”和证据来源。
