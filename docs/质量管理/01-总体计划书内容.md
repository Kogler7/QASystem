### 1.1 两类算法范围

#### 1.1.1 知识沉淀

`文档解析 → Markdown 标准化 → 文档切片 → 分片知识抽取 → Graph 合并去重 → 文本/图向量化 → 知识落库或外部持久化 → 结果与证据回溯`。

#### 1.1.2 问题求解

`问题理解 → ProblemFrame → Skill 选择 → MCP 原子工具调用 → 知识空间定位/实体链接/图谱逐跳探索 → 证据门 → 方案/数据执行 → 带证据结果`。

1. 知识沉淀 HTTP 能力：文档解析、切片、抽取、合并、文本/图向量化及知识摄取流水线。
2. 知识沉淀外部集成：按配置将知识资产交给外部应用服务持久化；未开通能力显式失败。
3. 问题求解 Agent loop：使用标准 MCP 和 Skill 集合完成问题理解、图谱导航、证据组织和执行。
4. 统一错误码、超时、重试、健康检查和服务契约。

| 集中一次性集成 | Sprint 结束 / 发版前（Sprint 4） | 1. 冻结 Git 基线、`.env.example`、模型目录版本。2. 按上栏自动/手动打包。3. 目标机 `docker load` 环境镜像（仅环境变更时）及 Redis 镜像。4. 源码只读挂载 `QASYSTEM_SOURCE_DIR`，模型只读挂载 `HOST_MODELS_DIR`→`/models`。5. 配置 `GPU_DEVICE_IDS`（A40 主机常用 `4,5,6,7`）。6. 端到端验证：解析→切片→抽取/沉淀→问题求解；队列/取消/SSE；未开通图写入/置信度/文档证据须显式失败。7. 记录 commit、镜像名 `qasystem-env-v1`、健康检查 `GET /health?full=true`。 |

## 10 历史 8 个月项目的补录规则

补录材料必须以 Git commit、现有测试、接口文档、发布日志和会议记录为证据；无法追溯的日期写“待核实”，不得倒填虚构时间。历史工作可按功能主题归并到 Sprint 1–4，但每条归并记录需标注“历史补录”和证据来源。
