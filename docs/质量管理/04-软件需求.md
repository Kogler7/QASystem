# 知识图谱科研项目软件需求规格说明书（交大算法团队内容基线）

> 版本：V0.1；日期：2026-08-12；依据仓库实际接口与代码整理。数值型验收指标标记为“待确认”。

## 1. 总体说明

系统由 Backend HTTP/MCP 服务、algorithm 算法实现、统一 MCP domains 和 AgentCode 运行时组成。接口成功响应统一为 `code/info/data/error/execution`；长任务由统一队列、Worker、SSE 和任务结果接口承载。

## 2. 功能需求

功能需求分为两类：

- 知识沉淀类：SR-001～SR-007，覆盖文档解析至知识落库/外部持久化的流水线。
- 问题求解类：SR-008～SR-014，覆盖 Agent loop 驱动标准 MCP 与 Skill 集合的知识导航、证据组织和执行；SR-015 为两类算法共同的配置与部署边界。

### SR-001 文档解析

系统应通过 `POST /api/v1/documents/parse` 接收多格式文件并输出 Markdown、文件元数据和 `data.parser` 实际引擎信息。支持 `auto/text/docling/vlm/mineru/pandas/beautifulsoup` 等引擎、OCR/表格/公式选项及 PDF 页分片；强制模式下 `force=true` 不得使用 `engine=auto`。解析失败应返回协议定义错误码。

### SR-002 文档切片

系统应通过 `POST /api/v1/documents/chunk` 支持 `recursive/symbols/custom_recursive/markdown/semantic` 策略，支持字符或 token 长度、相似度阈值、重叠窗口和分隔符配置；输出按输入顺序排列的文本块及可选原文 `ranges`。`chunk_overlap` 必须小于 `size`。

### SR-003 分片图谱抽取

系统应通过 `POST /api/v1/graphs/extract` 按输入顺序对一个或多个切片调用 LLM 抽取 Graph JSON；支持 PlantUML ontology、模型选择和 `merge` 选项。任一切片重试后仍失败时，整体请求应可定位失败位置并返回错误。

### SR-004 图谱确定性合并

系统应通过 `POST /api/v1/graphs/merge` 对多个 Graph 执行确定性去重，保持节点/关系结构稳定；合并结果应记录来源切片索引（如流水线场景）。

### SR-005 文本向量化

系统应通过 `POST /api/v1/embeddings/texts` 批量向量化，响应项与输入顺序一致；空文本不得静默丢弃；数量不一致返回 `VECTOR_COUNT_MISMATCH`。

### SR-006 图谱向量化

系统应通过 `POST /api/v1/embeddings/graphs` 对 Graph JSON 批量向量化，保持输入顺序并校验向量数量。

### SR-007 知识沉淀流水线

系统应通过 `POST /api/v1/pipelines/knowledge-ingestion` 编排解析、切片、抽取、合并和可选外部文件/向量存储；支持单文件和多文件，返回统计、ranges、抽取结果和 artifacts。`storage.persist_graph` 当前必须为 false；未配置外部服务时不得伪造存储成功。

### SR-008 知识空间定位与实体链接

统一 MCP 应提供 `locate_knowledge_space`、`get_all_subspaces` 和 `link_entities`，返回候选实体、评分和判断理由；定位失败应可报告候选或知识缺口，不得静默生成业务事实。

### SR-009 图谱检索与属性查询

MCP `query_entity_properties` 应返回节点标签和完整属性；`search_graph` 仅执行 `depth=1` 一跳邻居查询，支持方向、关系类型、limit 和可选剪枝，多跳由 Agent 逐层完成并保留路径证据。

### SR-010 Agent 求解与证据门

Agent 应建立 ProblemFrame，依据 `problem-solve/semantic-align/plan-execute` Skill 调度原子 MCP；ProblemClass、SolutionClass、规则、字段和公式必须有图谱证据。图谱缺口必须显式输出。

### SR-011 异步任务、取消和事件

系统应支持 `POST /api/v1/jobs`、任务状态/结果查询、DELETE 取消和 SSE events；业务接口支持 `Prefer: respond-async` 与有界 `Prefer: wait=N`。队列记录仅保存 `auth_context_id`，Authorization 不得进入 payload、日志、SSE、execution 或结果。

### SR-012 错误、重试与降级

错误须使用《错误码协议》定义的 code/HTTP 状态；可重试错误按服务端策略重试并记录 attempt。图谱写入、置信度、维度刻度和文档证据等未开通能力必须返回 `EXTERNAL_CAPABILITY_UNAVAILABLE`（503 类别），不得直连 Neo4j/Elasticsearch。

### SR-013 权限与审计

外部调用通过 `external_services/application.py` 注册，使用统一鉴权上下文；结果提供 job/execution/events/result URL 以支持审计，敏感凭据不得落盘。

### SR-014 可观测性

任务应记录原子执行、队列、资源分配、重试和终态事件；健康检查 `/health` 至少反映进程存活，`full=true` 仅检查已配置能力。

### SR-015 配置与部署边界

源码从 `QASYSTEM_SOURCE_DIR` 只读挂载，模型从 `HOST_MODELS_DIR` 挂载到 `/models`；环境镜像不得包含应用源码、模型、密钥或运行时数据。保留 `GPU_DEVICE_IDS` 配置。

## 3. 非功能需求

| 编号 | 要求 | 当前口径 |
|---|---|---|
| NFR-001 | 接口兼容性 | v1 字段和错误码以 `docs/算法接口协议.md` 及契约测试为准 |
| NFR-002 | 性能 | 延迟、吞吐、并发、GPU 利用率目标待甲方确认 |
| NFR-003 | 可用性 | 队列容量、重试上限、恢复时间待确认 |
| NFR-004 | 安全 | 凭据隔离、只读挂载、权限过滤和审计必须满足部署规范 |
| NFR-005 | 可维护性 | HTTP 与 MCP 复用算法函数；算法模块不得创建 Server |
| NFR-006 | 可测试性 | 每个 SR 最小章节至少关联一个 TC，核心路径覆盖正常/边界/异常 |

## 4. 输入输出与错误

请求模型采用严格字段校验（extra=forbid）；关键约束包括 markdown/items 非空、size>0、ranges 非负且有序、force 与 engine 组合合法。统一成功 envelope 的 `error=null`；任务未完成时读取 result URL 返回 409。详细错误码见 `docs/错误码协议.md`。

## 5. 追溯与待确认

SR-001～SR-015 映射至《06-07-整体设计.md》对应章节；测试用例文件中每个最小 SR 章节至少一个 `TC-*`。待确认：业务指标、数据规模、角色权限、SLA、模型版本、合规与保留周期。
