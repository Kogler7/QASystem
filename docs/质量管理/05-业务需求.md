# 知识图谱科研项目业务需求说明书（交大算法团队内容基线）

> 版本：V0.1（Markdown 基线）  
> 编制方：交大算法团队  
> 日期：2026-08-12  
> 说明：本文件用于回填甲方《业务需求说明书》模板。正式项目名称、业务领域、验收指标和人员信息均待甲方确认。

## 1. 业务概述

项目建设一套以知识图谱为业务知识权威、由两类算法协同工作的系统：知识沉淀算法负责把文档转化为可检索、可追溯并可落库的知识资产；问题求解算法由 Agent loop 驱动标准 MCP 和 Skill 集合，基于图谱证据组织检索、数据查询和方案执行。

## 2. 业务前景与价值

- 将分散在 PDF、DOCX、表格和网页中的业务知识结构化沉淀，降低人工整理成本。
- 通过实体链接和确定性逐层检索，提高业务术语、规则、问题类型和方案的可解释性。
- 通过 Agent loop + 标准 MCP + Skill 集合支持自然语言问题求解，同时禁止模型记忆冒充业务事实。
- 为应用团队提供稳定的 HTTP v1 接口和异步任务能力，便于集成和审计。

## 3. 业务目标（BR）

| 编号 | 目标 | 验收口径 |
|---|---|---|
| BR-001 | 支持多格式业务文档解析 | 支持 PDF/OFD/DOCX/DOC/PPTX/PPT/PNG/JPG/MD/TXT/XLSX/XLS/CSV/HTML；解析结果为 Markdown；具体样本通过率待确认 |
| BR-002 | 支持知识沉淀流水线 | 完成解析→切片→分片抽取→合并→向量化→知识落库/外部持久化（若配置）的端到端链路 |
| BR-003 | 支持 Agent loop 驱动的问题求解 | 用户问题由 Agent loop 选择 Skill 并调用标准 MCP，经知识空间定位、实体链接、一跳检索和方案/数据执行形成带证据答案；业务场景清单待确认 |
| BR-004 | 结果可审计、可追溯 | 返回统一 code/info/data/error/execution，记录任务、原子执行、事件和结果 URL |
| BR-005 | 支持受控异步和资源调度 | 长任务入队、SSE 事件、取消和 GPU/LLM 资源调度可用；吞吐/延迟目标待确认 |

## 5. 业务流程

### 5.1 知识沉淀算法

业务人员上传文档 → 系统选择解析器（支持 fallback）→ 生成 Markdown → 按策略切片并保留原文 ranges → 对切片并发抽取图谱 → 确定性合并去重 → 文本/图 JSON 向量化 → 可选写入应用团队外部服务 → 返回统计和审计信息。

### 5.2 Agent loop 驱动的问题求解算法

用户提出问题 → Agent loop 建立 ProblemFrame → 选择 Skill → 调用标准 MCP → 定位知识空间 → 链接实体并读取属性 → 按一跳原子查询逐层探索 → 获取 ProblemClass/SolutionClass、规则和资源 → 证据门检查 → 映射 MCP 原子工具执行 → 返回事实、运行结果、假设和知识缺口。

## 6. 业务范围与不在范围

### 6.1 范围内

- 文档解析、切片、知识抽取、图谱合并、文本和图谱向量化。
- 知识空间定位、实体链接、实体属性查询、图谱一跳检索和 Agent 求解编排。
- 统一 HTTP/MCP 接口、异步任务、SSE 事件、取消、错误码和执行审计。

### 6.2 当前不在范围或须显式失败

- Neo4j/Elasticsearch 直连不恢复；图谱写入、置信度计算、维度刻度和文档证据等未开通能力调用时返回明确不可用错误。
- OFD 电子签名、印章和证书验签不属于解析接口范围。
- 业务知识、指标口径、阈值、表字段和方案不由模型自行补写。

## 7. 业务假设与依赖

- 甲方提供有效业务本体（可为空以启用通用抽取）、样本文档、知识空间和验收数据集。
- 模型和 GPU 以只读挂载方式提供；模型不进入环境镜像。
- 外部接口使用 `APPLICATION_SERVICE_URL`，`FILE_SERVICE_URL` 仅作兼容回退。
- 正式业务域、数据量、并发、SLA、合规等级、保留周期和迭代日期待确认。
