# 知识图谱科研项目过程裁剪清单（交大算法团队建议）

> 依据甲方模板“产品项目过程裁剪列表/组织过程裁剪列表”。最终裁剪方式由甲方/PPQA 批准；本文件只给出算法团队建议。

## 1 产品/项目过程

| 过程活动 | 子过程/过程输出 | 建议结果 | 裁剪原因说明 |
|---|---|---|---|
| 项目策划与估算 | 评估项目级别、产品 backlog、总体计划 | 不裁剪 | 需补录已运行 8 个月的真实里程碑和当前基线 |
| 项目策划与估算 | 组织项目团队、角色职责对照表 | 替代 | 使用三方联合 RACI 和组织级岗位职责表 |
| 项目策划与估算 | 定义项目目标、迭代次数、长度 | 不裁剪 | 周报和 Sprint 评审依赖统一迭代基线 |
| 项目策划与估算 | 过程裁剪列表 | 不裁剪 | 本文件即项目级裁剪依据 |
| 需求开发和管理 | 业务需求说明书/业务需求评审 | 视甲方确认 | 算法团队提供业务价值和边界，甲方保留审批权 |
| 需求开发和管理 | 软件需求规格说明书 | 不裁剪 | 测试用例必须追溯到软件需求最小章节 |
| 需求开发和管理 | 需求跟踪矩阵 | 替代 | 采用 Markdown 追溯矩阵+Git/测试编号维护，回填模板时生成正式表 |
| 需求开发和管理 | 页面原型 | 裁剪 | 算法服务无独立业务 UI；若甲方要求应用演示，由雪浪提供原型 |
| 设计 | 系统架构设计 | 合并 | 与系统设计、数据和接口设计合并为整体设计文档，架构主责雪浪 |
| 设计 | 算法/数据/接口详细设计 | 不裁剪 | 交大负责算法部分，必须给出输入输出、边界和失败语义 |
| 实现 | 代码实现、代码评审 | 不裁剪 | 核心算法代码必须同行评审并关联 commit |
| 测试 | 测试计划、测试用例、系统/集成测试 | 不裁剪 | 由雪浪主测，交大提供算法用例和结果证据 |
| 配置管理 | Git 基线、版本和发布说明 | 不裁剪 | 代码交付需保留提交记录；模型/密钥/运行时数据不入代码包 |
| 评审 | Sprint 成果评审和回顾 | 不裁剪 | 每个迭代一个周报 Sheet 和一个 Sprint 评审 Excel |
| 风险管理 | 风险和机会计划与跟踪 | 不裁剪 | 项目已运行 8 个月，需要补录历史风险和当前状态 |
| 交付 | 交付清单、验收材料 | 不裁剪 | 需形成接口、代码、测试、文档和遗留问题清单 |

## 2 组织过程

组织级过程原则上不裁剪。若甲方允许合并，算法团队建议仅将“过程培训、评审记录、质量证据”合并到项目质量包；不得裁剪质量审计、风险跟踪、配置审计和统一验收活动。
