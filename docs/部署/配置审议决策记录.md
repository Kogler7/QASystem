## 2026-10-14 · 第二组：Backend / Agent 对外入口

用户决定：“对外入口这几个保留。”四项均保留；容器内部端口保持固定约定。

| 配置项 | 当前默认 | 建议 | 作用 |
| --- | --- | --- | --- |
| BACKEND_HOST_PORT | 8006 | 保留 | Backend 暴露到宿主机的端口；容器内部 8000 固定 |
| AGENT_HOST_PORT | 9180 | 保留 | Agent 暴露到宿主机的端口；容器内部 9180 固定 |
| BACKEND_BIND | 0.0.0.0 | 保留 | Backend 的宿主监听地址，可限制仅本机访问 |
| AGENT_BIND | 0.0.0.0 | 保留 | Agent 的宿主监听地址，可以与 Backend 有不同暴露范围 |

两服务当前默认地址相同，但作用对象不同；合并为一个开关会失去独立控制。决策模型内部监听与内部服务端口另组审议，不与宿主对外端口混在一起。

## 已讨论 · 第三组：GPU 分配与设备编号

以下是被新方案取代的最初建议，不作为新增环境变量的实现指令。用户指出按模型增加 GPU 环境配置会越来越乱，后续按第四组的统一模型记录设计落实。

| 配置项 | 当前默认 | 建议 | 作用 |
| --- | --- | --- | --- |
| GPU_DEVICE_IDS | 4,5,6,7 | 保留 | Backend 调度允许使用的宿主 GPU 范围 |
| EXECUTION_GPU_RESERVED_DEVICE_IDS | 7 | 保留手动预留，已登记常驻模型另自动加入 | 外部服务可能占卡，不能只依赖本项目模型计划推导 |
| CLEF_CUDA_VISIBLE_DEVICES | 7 | 保留宿主设备选择 | Clef 实际使用哪张宿主卡 |
| NANOJEV_CUDA_VISIBLE_DEVICES | 7 | 保留宿主设备选择 | NanoJev 可以与 Clef 同卡或分卡 |
| CLEF_DEVICE | cuda:0 | 从宿主设备选择推导，取消独立填写内部编号 | 绑定单卡后，该卡在进程中编号为 0 |
| NANOJEV_DEVICE | cuda:0 | 从宿主设备选择推导，取消独立填写内部编号 | 不应同时维护宿主卡号和进程内卡号 |

CPU/GPU 运行方式不能与 CUDA 内部编号混为一谈。如果保留 CPU 运行能力，应在模型设备选择中明确提供 CPU，而不是要求用户填写另一个 device 字符串。当前生产目标仍是 GPU 常驻，不能未经决定就删除 CPU 能力或改成自动 CPU 回退。

## 2026-10-14 · 第四组：按推理方式管理模型

用户决定：“那按推理方式划归吧。”同时要求解释与已有模型目录检查、自动启动配置的关系。

- 同类新增模型增加统一模型记录，不再增加一套专属 GPU、内部设备编号或路径环境变量。
- vLLM 与原生推理适配器（Clef/NanoJev）分类展示，只展示适用的引擎参数。远程 API 没有本地权重与 GPU 启停。
- 权重路径、设备选择、启用状态、端口与引擎参数来自同一条记录。目录检查与启动是读取该记录的执行步骤，不是另一份配置来源。
- 现有通用 vLLM 由 ops 管理；MinerU 视觉 vLLM 由 Backend supervisor/worker 管理；Clef/NanoJev 当前仍有独立环境参数。实现需迁移这些来源，不能称已完全统一。
- 保留 Backend 对解析引擎的生命周期管理，同一服务不得被 ops 与 supervisor 同时启动。旧参数迁移后不得再覆盖新记录。
- 扫描到权重不等于启用；打开 UI 不启动服务，启动须审核、检查与明确部署。完整权重校验保持独立操作。

第四组交给 config_foundation_cleanup subagent 继续核实消费者和实现边界。涉及未审议组的功能删除或接口大变更，需要另行讨论；用户尚未批准服务器实际配置变更。

## 2026-10-14 · 独立模型管理与服务路由

用户决定：“这几个独立地模型，让 ops 单独管理好了，backend 中想要访问相关服务，可以从某个集中的入口访问外部服务，由 ops 来配置路由。”

- 通用聊天 vLLM、Clef、NanoJev 的独立服务由 ops 管理启停；Backend 通过公共外部服务入口访问。
- 模型部署记录与用途路由分开：前者说明怎么启动，后者说明抽取、实体数量预测等用途访问哪个服务。本地服务地址由拓扑推导，不再另填一套地址、设备与端口。
- 远程 API 登记远程服务，凭据引用现有密钥名称，不复制密钥到任务快照。新请求使用新批准路由，在途请求保持快照。
- 每次评测仍由命令行临时选择，不恢复持久化评测默认项。显式请求覆盖与默认路由需要区分，不能静默吞掉用户模型选择。
- MinerU 的 Backend worker 生命周期仍保留；本决策不代表把解析 worker 迁到 ops。

实现由 config_foundation_cleanup 和 model_service_routes 分工。当前尚未完成测试与服务器部署。

| 配置项 | 当前默认 | 建议 | 理由 |
