## 为什么旧全量测试会失败

合并后的首次全量为 2459 通过、34 跳过、43 失败。共同原因是之前的 splitter 重写丢失了生产契约：

- 没有精确的 `__source_range`，重复文本与重叠不能可靠定位；批量文档可能混用 metadata。
- 普通文本未严格限长，或合并过程改变了原文。
- JSON 围栏与正文被拆散，文献角标被当成 JSON。
- 删除 `protect_json=False` 接口，v3 在失败后恢复切分时报错。

修复保留原文、文档边界与重叠预算，恢复明确关闭 JSON 保护的恢复窗口。公共 recursive 不再为了碎片合并突破硬上限；兼容参数的边界已写入 [文档切片算法说明](../算法/文档切片算法说明.md)。相关原有测试 225 项通过，并新增跨文档、CRLF、重复文本和大 JSON 恢复回归，没有删除或放宽失败测试。

此外，旧干净快照的两项数据哈希失败分别来自排除列表的 CRLF manifest 与 LF Git blob不一致，以及 verifier-scope 缺少固定换行属性。数据标签、候选和 JSON 内容未改变；排除列表规范到 LF，数据版本升为 1.1.1，并保留哈希与篡改拒绝测试。
