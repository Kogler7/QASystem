## 第二轮：逐项核对，不猜测删除

`BACKEND_IMAGE`、`CONFIDENCE_ES_HOSTS/INDEX`、`KNOWLEDGE_MAP_BASE_URL/TIMEOUT/TOKEN`、`NEO4J_URI/USER/PASSWORD` 不在新版声明中。需要确认它们是否只服务于旧应用、旧 Compose 或其他同机应用；不能把 qasystem 配置清理扩展成删除同机数据库服务。

`NO_PROXY`、`no_proxy`、`https_proxy` 属于网络运行环境，可能由 HTTP 客户端或第三方库直接消费，不应仅因不在业务声明中就删除。

## 第三轮：精简标准项

对剩余标准项，按部署基础、抽取模型、Agent、解析、Embedding、决策服务、队列、内部诊断逐组审核。每项需要说明消费者、是否启用、是否可自动推导、是否确需用户配置、是否支持动态更新。

“保留功能”和“允许用户配置”是两件事：某些内部路径、端口或设备映射可以由程序推导，但消费者依然存在，不能直接删掉功能参数。是否收回成内部固定约定，需要同步代码、声明新版本和测试，不能只从模板隐藏。
