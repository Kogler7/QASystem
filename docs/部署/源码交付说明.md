# 源码交付说明

本文面向接收源码的甲方团队，说明源码结构、解析 / 切片 / 抽取三部分核心算法的代码位置与对应文档，以及测试脚本、评估脚本的使用方法。

## 1. 源码结构

系统是一个知识图谱驱动的问答/求解系统：文档经解析、切片、抽取、向量化沉淀为知识图谱，再通过统一的 HTTP 接口与 MCP 工具对外提供检索、取数、画图等能力。业务实现集中在 `algorithm/`，对外只通过 HTTP（`backend/`）与 MCP（`mcp_services/`）两种入口暴露。

```text
qasystem/
├── backend/                # FastAPI 应用：v1 算法 HTTP 接口、知识沉淀接口、异步执行框架
│   ├── app/main.py         # 业务 HTTP/MCP ASGI 入口
│   ├── app/routers/        # 对外路由（算法能力、知识沉淀、执行任务、置信度）
│   ├── app/services/       # 路由对应的业务编排
│   └── app/execution/      # 异步执行框架（manager/supervisor/worker/queue/store/hub）
├── algorithm/              # 全部算法与业务实现（详见第 2 节）
│   ├── preproc/            # 文档解析：PDF/OFD/Word/图片等 → Markdown
│   ├── knowledge_pipeline/ # 切片、向量存储、产物呈现
│   ├── knowledge_extract/  # 本体驱动知识抽取（版本路由 + latest/v1/v2/v3 各版本包）
│   ├── knowledge_precipitation.py  # 知识沉淀流水线编排（解析→切片→抽取→入库）
│   ├── embedding_runtime.py        # 文本/图谱向量化
│   ├── NL_to_cypher/       # 切片器实现、NL2Cypher
│   ├── ans/QA/             # 图谱定位、实体链接与单层搜索
│   ├── confidence_calculate/       # 置信度计算
│   ├── data_access/        # 只读 SQL 执行器
│   ├── term_vector/        # Term 语义向量索引（实体链接向量召回）
│   └── visualization/      # 图表生成
├── mcp_services/           # 统一 MCP Server：各领域工具注册与返回契约
├── external_services/      # 应用团队接口与模型服务适配（唯一出网口）
├── agent/                  # AgentCode 智能体运行时（独立 ASGI 服务）
├── eval/                   # 评测编排入口与评测辅助工具（详见第 4 节）
├── tests/                  # 统一测试目录（按 backend / agent / algorithm / eval 组织）
├── test_data/              # 共享测试数据集（eval 评测集、解析器测试数据等）
├── docs/                   # 全部专题文档（统一入口 docs/文档索引.md）
├── deploy/                 # 交付打包产物目录
├── Dockerfile              # 环境镜像（仅 CUDA/vLLM/Torch/系统依赖，不含源码与模型）
├── docker-compose.yml      # Backend、Agent、Redis 拓扑
└── .env.example            # 唯一运行配置模板
```

更细的目录职责与边界规则见 [项目结构](../架构/项目结构.md)；总体框架见仓库根 `README.md`。

## 3. 测试脚本使用说明

### 3.1 运行方式

单元/契约测试统一用 pytest，在仓库根目录执行：

```bash
# Windows 开发机
.venv/Scripts/python.exe -m pytest -q

# Linux / 部署机
python3 -m pytest -q
```

### 3.2 测试范围

`pytest.ini` 固定了测试目录，无需额外参数：

| 目录 | 覆盖内容 |
| --- | --- |
| `tests/backend/` | HTTP 接口契约、执行框架、解析器选择、切片/抽取适配、观测性等 |
| `tests/agent/` | Agent 运行时、API、MCP 加载、任务存储等 |
| `tests/algorithm/preproc/`、`tests/algorithm/NL_to_cypher/` | 解析与切片算法级测试 |
| `algorithm/knowledge_extract/v2/tests`、`v3/tests` | 抽取各版本包的单元测试 |
| `tests/eval/` | 评测脚本自身的门禁、报告、续跑、清理测试 |

可只跑某个目录或文件，例如：

```bash
python3 -m pytest -q tests/backend/test_knowledge_protocol.py
```

### 3.3 维护约定

- 改动算法或服务的可观察行为时，必须在同一提交内更新对应测试；
- `tests/` 下的契约测试（如切片器 `__source_range` 元数据）被生产代码消费，不得单方面删除或改语义；
- 发布前要求单元测试全绿，见根目录 `AGENTS.md` 的「Release Quality Gate」。

## 4. 评估脚本使用说明

评测入口是 `eval/run.py`（`eval/run.sh` 仅转调），通过 HTTP 打运行中的 Backend，评测线上「解析 → 切片 → 抽取」链路并对抽取结果打分。**评测前需先启动 Backend**（默认 `http://127.0.0.1:8006`）；评测数据在 `test_data/eval/`（official 公文 10 例、standard 标准 4 例、rule 规则 1 例、simple 1 例）。

常用命令（仓库根目录执行）：

```bash
# 扫描评测集，确认能发现全部 16 个 case（不调服务）
python3 eval/run.py --dry-run

# 评测单个 case（默认：解析+切片+抽取并评分）
python3 eval/run.py test_data/eval/official/official_01

# 全量评测
python3 eval/run.py

# 发布前质量门禁（空抽取判失败 + 最低 F1 + 耗时预算，非零退出即不过）
python3 eval/run.py --match-mode llm --fail-on-empty --min-f1 0.5 \
  --max-case-seconds 1800 --max-stage-seconds parse=300,chunk=120,extract=900
```

要点：

- 退出码：`0` 全过；`1` 配置错误；`2` 有 case 失败或空抽取；`4` 门禁未过；
- 评分口径默认 LLM-judge（需配 `KG_EXTRACT_LLM_BASE_URL`），纯精确匹配加 `--match-mode identity`；
- 对比抽取版本（v2/v3/v3.1）：先固定 Backend 的 `KG_EXTRACT_ALGO_VERSION` 跑一次 `chunk-extract` 冻结切片，切换版本后用 `--mode extract --from-run <时间戳>` 复用同批切片重跑；
- 结果写入 `tmp/eval/runs/<时间戳>/`，看 `report.md`（批次报告）与 `summary.json`（总览与门禁块）。

详细文档：

- [eval/README.md](../../eval/README.md)：评测模式、全部命令、结果文件说明、加 case 方法
- [评测批次报告与记录清理](../算法/评测批次报告与记录清理.md)：批次目录结构与月度清理
