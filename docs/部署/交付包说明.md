# QASystem 环境镜像与外置源码部署

部署只使用一个 Docker 镜像 `qasystem-env-v1`。它包含 CUDA、vLLM、Torch、Python/Node/Java 依赖、LibreOffice、OFD 转换工具和其他系统程序，不包含 Backend、Agent、算法、MCP 源码、模型、密钥或运行数据。

应用源码位于交付目录的 `runtime/`，由 Compose 只读挂载到容器。模型位于 `models/`，同样只读挂载。

## 交付内容

| 路径 | 用途 |
| --- | --- |
| `qasystem-env-v1.tar` | 可选环境镜像；只有 `-IncludeEnvImage` 时生成 |
| `redis-7-alpine.tar` | 可选 Redis 镜像；只有 `-IncludeRedisImage` 时生成 |
| `runtime/` | Backend、Agent、算法、MCP、常驻模型服务、外部适配器；包含公共配置核心 `qasystem_config/`、原生推理启动器 `model_runtime/` 和 Docker 运维工具 |
| `ops.py` | 宿主运维入口；按自身位置查找 `runtime/`，可从其他工作目录执行 |
| `OPS.md` / `PROCESS_CONTROL.md` | 配置、部署、历史查询及容器内 CPU worker 局部控制说明 |
| `models/` | 外部模型目录，不纳入镜像；由 `download-models.ps1` 在联网机器填充 |
| `docker-compose.yml` | Backend、Agent、Redis 与 decisions profile 常驻模型拓扑和只读挂载 |
| `download-models.ps1` | 联网下载 Docling/Embedding/MinerU；`-Jev -Clef` 可下载两套决策模型 |
| `DECISION_MODELS.md` | 两套决策模型的环境、挂载、GPU 配置与验证说明 |
| `run-offline-validation.ps1` | 封闭网络验收脚本 |
| `.env.example` | 唯一运行配置模板（已改写为 `./runtime`、`./models` 路径） |
| `ENV_MIGRATION.md` | 环境变量迁移指引（由本文档同源的迁移说明生成） |
| `README.md` | 本说明 |
| `offline-validation/` | 离线验收辅助：验收说明 README、offline-test Compose 和解析样本 |
| `SHA256SUMS` / `交付清单.json` | 镜像、源码与部署文件校验 |

## 首次部署

```bash
sha256sum -c SHA256SUMS
docker load -i qasystem-env-v1.tar
docker load -i redis-7-alpine.tar      # 交付包包含时执行
python3 ops.py config              # 配置路径、服务、凭据和 GPU，审核差异并保存
python3 ops.py check
python3 ops.py deploy
python3 ops.py status
```

目标 8 卡 A40 主机只允许使用后四卡时保留 `GPU_DEVICE_IDS=4,5,6,7`。`QASYSTEM_SOURCE_DIR=./runtime` 和 `HOST_MODELS_DIR=./models` 分别指向外置源码和模型。

## 普通代码更新

普通发布不构建、不传输镜像，只替换完整的 `runtime/` 目录并重建应用容器：

```bash
sha256sum -c SHA256SUMS
python3 ops.py config plan        # 查看新版本声明及迁移差异
python3 ops.py config             # 有待确认的升级时审核并保存
python3 ops.py check
python3 ops.py deploy
```

不要在运行中的 `runtime/` 内逐文件覆盖。应先把新交付目录完整放好，再整体切换目录或停服务后替换，避免多个进程同时读取不同版本代码。回滚时恢复上一份完整 `runtime/` 后重新创建 Backend 和 Agent。

## 环境升级

只有 CUDA、vLLM、Torch、Python 依赖、系统程序或语言运行时变化时才重新构建并发送 `qasystem-env-v1.tar`：

```powershell
.\build-image.ps1
.\package-deploy.ps1 -IncludeEnvImage
```

模型始终不进入环境镜像。

## 配置和交付门禁

应用与运维界面统一调用 `qasystem_config`，不得恢复旧 `docker.configuration` 等入口。打包前在源码根执行 `python -m qasystem_config.config_contract`；打包脚本会主动切换到源码根执行该门禁，调用脚本时不要求当前工作目录位于仓库。容器启动同样先执行公共 guard，通过后才启动应用。

不要直接编辑部署 `.env` 或 `runtime-config/config.json`。交互界面和自动配置事务共用版本校验、差异、原因、凭据脱敏历史及回滚逻辑。自动事务的 `plan/apply` 参数见 `OPS.md`。旧 `docker/config-releases/` 仅作为不可修改的历史声明证据交付，新声明和新历史位于 `qasystem_config/`。

`ops --help` 与公共配置读取无需 Docker daemon；部署、容器状态、重启等实际容器操作仍需 Docker。CPU worker 局部排空、重启和数量应用使用 `ops runtime`，不会重新创建 Backend 容器；端口、挂载、GPU 可见范围等容器属性变化仍需 `ops deploy`。

## MinerU 权重准备

解析准备工具 `docker/download_models.py` 按有效配置选择 MinerU 后端与模型根目录，不读取旧 `config.yaml`。需要跳过 MinerU 时使用统一的 `--skip-mineru`，不要再用已删除的 `--skip-mineru-pipeline` 或 `--skip-mineru-vlm`。下载准备不等于启用解析服务；启动前仍会校验对应后端的必需模型文件及锁目录写权限。
