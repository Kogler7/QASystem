# 评测配置界面

在仓库源码目录运行：

```bash
python3 eval/configure.py
```

SSH 连接需要交互终端，例如 `ssh -t 88zjwei`。Windows 开发机可使用 `.venv/Scripts/python.exe eval/configure.py`。此入口需要现有评测依赖 PyYAML，不需要额外终端界面包，也不创建 Backend。

## 键盘操作

| 按键 | 操作 |
| --- | --- |
| ↑↓ / PgUp / PgDn | 移动和翻页 |
| ←→ / Tab | 切换数据集、抽取、裁判、门禁、执行分类 |
| Enter | 输入值；可选值和原 CLI 说明在编辑时显示 |
| Space | 切换布尔开关 |
| d / 编辑时留空 | 删除覆盖，重新继承原评测默认配置 |
| s | 检查并保存独立评测配置，不调用服务 |
| p | 预览最终命令，不执行 |
| v | 保存后执行 `--dry-run`，只扫描数据集，不调用 Backend 或 judge |
| r | 预览命令，再输入 `run` 才真正执行评测 |
| q | 退出，未保存的修改丢弃 |

键靠左、值靠右；`[覆写]` 表示本界面显式填写，`[继承]` 表示沿用原评测参数。启动配置、模型部署和评测参数是独立事项：此入口只生成评测命令，不启动 vLLM、不修改应用 `.env`、不重启 Backend/Agent。

## 默认值和配置来源

所有 `eval/run.py` CLI 参数、类型、可选值、默认值和说明直接从当前版本的参数定义读取，避免复制一套配置。参数 YAML 仍按原入口规则选择：显式 `--params` → 工作区 `params.yaml` → `eval/params.yaml`；界面显示文件中的裁判窗口、并发、超时等参数。

不填写覆盖时，最终命令就是 `python3 eval/run.py`：后台完整 `pipeline`、请求 `options={}`、LLM judge、API 裁判、抽取模型与算法沿用 Backend。界面不会自动改成 identity，也不会自动增加抽取重试或换算法。

裁判模型的继承值会考虑运行时 `settings.json`、当前进程与 `eval/.env`、根 `.env` 中的公开 `QASYSTEM_JUDGE_*` 配置。显式 CLI 值优先；Backend/MCP 地址环境变量优先于参数文件。界面不展示密钥值；`--judge-key-env` 只填写环境变量名。Backend 实际使用的抽取默认值由服务决定，未显式覆盖时不能把界面推测值当成服务当前模型。运行日志及报告是实际执行结果的依据。

## 文件和安全边界

默认 profile 写到 `tmp/eval/config/default.json`。可选择其他 profile，但输出位置必须在仓库 `tmp/` 下：

```bash
python3 eval/configure.py --profile tmp/eval/config/local4b.json
python3 eval/configure.py --profile tmp/eval/config/local4b.json --preview
```

已有 profile 打开时自动生成带时间戳的备份。保存前检查其他进程是否修改文件，发现冲突拒绝覆盖。只填 CLI 覆盖时，不复制或修改原 `params.yaml`；修改裁判窗口/并发或 Backend 地址时，在 profile 旁生成 `.params.yaml`（JSON 语法是 YAML 子集），保留原文件的 `options`、`groups` 等内容并单独覆盖指定字段。

界面禁止在 profile 或源参数文件中携带 API 密钥、密码、Authorization 字段，服务 URL 不能携带凭据、查询参数或片段。实际执行使用参数列表，不经过 shell。输出和报告仍由原评测入口写到 `tmp/eval/runs/`。

保存会检查模式复用条件、参数类型、切片重叠、F1 和耗时预算等常见冲突。数据集是否完整、Backend 是否可达、judge 凭据是否有效，最终仍由原入口的 dry-run 或实际运行校验。尚未提供图形化勾选 case、模型部署、密钥编辑或全量评测进度仪表盘；类型/case 筛选与多模式通过输入现有 CLI 字段设置。
