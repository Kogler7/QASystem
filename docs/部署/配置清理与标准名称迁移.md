# 配置清理与标准名称迁移

当前配置声明版本为 `2026.10.13.1`；下述清理发生于 `2026.10.12.2`。该轮从当前声明中删除 34 项：12 个同义别名、10 个旧单模型部署参数、6 个旧部署入口参数、4 个持久化 judge 默认项和 2 个没有业务消费者的伪配置。上一轮已删除的 22 项继续保持删除。

## 用户如何升级

运行 `ops config`。界面先备份原文件，只生成迁移计划；审核所有差异并确认保存后，才生成新版本配置。不要手工修改 `.env`。有冲突的标准项会在说明中标出，必须在界面中编辑确认最终值。凭据不会出现在冲突提示中。

抽取的旧名称统一迁到 `KG_EXTRACT_LLM_*`：

| 旧名称 | 当前名称 |
| --- | --- |
| `KG_EXTRACT_API_URL`、`KG_EXTRACT_V3_BASE_URL` | `KG_EXTRACT_LLM_BASE_URL` |
| `KG_EXTRACT_API_KEY`、`KG_EXTRACT_V3_API_KEY` | `KG_EXTRACT_LLM_API_KEY` |
| `KG_EXTRACT_MODEL`、`KG_EXTRACT_V3_MODEL` | `KG_EXTRACT_LLM_MODEL` |
| `KG_EXTRACT_MAX_TOKENS` | `KG_EXTRACT_LLM_MAX_TOKENS` |
| `KG_EXTRACT_JSON_RETRIES` | `KG_EXTRACT_LLM_JSON_RETRIES` |
| `KG_EXTRACT_JEV_NOUL_ACCEPT/REJECT` | `KG_EXTRACT_JEV_ACCEPT/REJECT` |
| `SOFFICE_PATH` | `LIBREOFFICE_PATH` |
| `FILE_SERVICE_URL` | `APPLICATION_SERVICE_URL` |

旧名称只存在于迁移规则和历史记录中，业务代码不再读取它们。`FILE_SERVICE_URL` 的旧运行时回退也已按本轮要求移除；部署升级时迁移其值。

模型启用、GPU、端口、监听地址、权重路径、上下文、显存比例、批处理和计算精度统一保存在 `config.json` 的 `models` 中。旧 `LLM_*` 参数迁入对应模型；旧全局并发、批处理和精度参数迁入各模型。不会因为发现旧配置就自动启用模型。权重仍在镜像外，挂载只读。

旧 `--legacy` 单模型向导、手写单模型 Compose、宿主 Clef systemd 模板和独立 remote-only 镜像部署链已移除。唯一环境镜像仍为 `qasystem-env-v1`。`ALGORITHM_RUNTIME_PROFILE=remote-only` 是有实际消费者的运行模式，保留。

评测只保留凭据配置。judge 地址、模型、适配器和输出上限通过每次命令行的 `--judge-*` 选项指定，旧 `QASYSTEM_JUDGE_BASE_URL/MODEL/ADAPTER/MAX_TOKENS` 不再生效。

## 删除与保留的边界

`NANOJEV_REVISION` 是包内常量，删除的是错误的配置声明。`NL2CYPHER_EMBEDDING_MODEL_PATH` 只有健康检查读取，业务不用，已删除该检查和声明。

不同服务各自的模型、端口和超时不属于同义别名。数据库的 `DATABASE_URL` 与 `MCP_DATABASE_URL` 可以对应不同连接，保留。动态凭据名称、按资源类别读取的 GPU 预算、Clef/NanoJev 的 Settings 字段和依赖库读取的参数，按实际消费者保留。

打包和部署继续执行消费者门禁：未声明读取、消费者消失、默认值变化未升级声明版本、修改历史声明文件都会报错。旧值不会写入新版本实际配置；历史声明、历史生效配置及迁移墓碑保留用于追溯。

## 本轮验证

对本轮提交的独立代码快照执行配置门禁与相关测试，171 项通过。全量单测为 2322 通过、34 跳过、45 失败。失败集合包括上一轮已记录的 43 个切片/抽取问题，以及 2 个评测数据哈希问题；后两项已在清理前的旧快照中单独复现。本轮没有新增失败。

全量门禁未绿，不 push、不部署。仅完成代码清理与迁移实现，服务器当前实际配置未修改，升级时仍须用户通过 `ops config` 审核。

2026-10-13 后续合并另登记三个有实际消费者的 v3.1 请求预算参数及 AGENT_BIND，当前声明共 274 项。Compose 已移除第二套默认值。最新检查结果见 [清理与合并检查](清理与合并检查20261013.md)，上方 45 个失败是当时的历史结果，不代表后续修复状态。
