# 小模型统一部署

模型统一放在 `${HOST_MODELS_DIR}/llm/`，容器只读挂载到 `/models`。
88 的 `HOST_MODELS_DIR=./models` 相对 `/mnt/data3/qasys`，因此实际目录是
`/mnt/data3/qasys/models/llm`。模型、下载缓存和测试结果都不进入镜像。

| 模型 | 模型目录（相对 HOST_MODELS_DIR） | 精度 |
|---|---|---|
| Qwen3.5-4B | llm/Qwen--Qwen3.5-4B | BF16 |

离线部署前加 `--verify-only` 复核，不访问外网。

## 启动

### 键盘配置界面（推荐）

在 88 登录后运行：

```sh
cd /mnt/data3/qasys
python3 qasystem/docker/configure.py --project-dir /mnt/data3/qasys
```

仓库中用 `python3 docker/configure.py`，交付包中用 `python3 runtime/docker/configure.py --project-dir .`。原 `setup_llm.py` 命令也默认打开这个界面；`--legacy` 已删除，收到此参数会报错退出。

进入界面会自动备份配置，并只读查询 Docker 容器的实际状态、非敏感配置、模型名、GPU、端口和镜像；不读取整个权重文件、不启动模型。默认“运行”分区显示已部署服务，包括不是本界面启动的模型。按 r 刷新实际状态。界面携带当前发布版本的 `.env.example`，所有配置项都展示当前值、默认值、现有模板注释和生效方式。支持中文终端宽度计算和窗口大小变化；设置 NO_COLOR 可关闭颜色。已有未知配置及未修改的凭据原样保留，凭据不回显。界面采用 Linux 终端工具布局：顶部分类标签、选中行高亮、宽屏右侧说明、窄屏下方说明和底部动作栏。键靠左、值靠右统一排列；[启动] 表示需重启，[热更] 表示新请求读取。运行分区显示真实状态，编辑分区显示配置值，选中项的说明分别展示实际值和配置值；值前的 ! 表示已明确发现两者不同。实际值以运行容器环境和其真实挂载的热配置目录为准，不把未挂载的宿主机编辑文件当成实际已生效值。←→ 或 Tab 切换分类，PgUp/PgDn 翻页，↑↓ 或 j/k 移动，空格勾选模型或切换布尔开关，回车编辑，`/` 搜索，`d` 恢复选中项的默认值，`q` 退出且不保存未保存的编辑。

勾选模型后出现 GPU 编号、宿主端口、上下文长度及显存比例，可同时配置多个模型。权重目录只检查是否存在，不自动下载。三个动作相互独立：

- `s` 保存：检查端口重复、允许/预留 GPU、同卡多模型、参数格式、模型目录及模型宿主端口占用；检查其他进程是否改过文件，然后生成 `.env`、`runtime-config/config.json` 和自动生成的 `models.compose.json`。`config.json` 的 `settings` 保存热配置，`models` 保存模型启用计划；旧 `settings.json`、`models.json` 在备份后合并并移除，热配置同时从 `.env` 移出。**不会启动、停止或重建任何容器，也不会提前预留计划中的 GPU。**
- `v` 校验权重：必须再输入 `verify`；这时才完整读取已勾选模型的文件，显示模型、文件序号、大小和文件名。较大的分片仍需时间计算 SHA256。
- `a` 部署：必须再输入 `deploy`；检查现有统一镜像/vLLM、GPU 实际占用与权重显存预算。重建现有 Backend/Agent 来应用启动配置及 GPU 预留，启动已勾选的本地模型；取消勾选并部署会停止本界面之前启动的对应模型。它不接管外部模型服务，不重新构建环境镜像，不创建另一个 Backend。**启动命令成功只表示已提交启动，实际模型就绪需看健康状态和日志。**

备份在运行时目录的 `backups/<时间>/`，保存原 `.env` 与已有 JSON 配置，目录权限 700、备份文件权限 600。备份含凭据，不要提交或分享。发现并发修改会拒绝覆盖。GPU 预留采用保守策略，停用模型后不会自动释放旧预留，确认服务完全停止后才能自行移除。

保存前需逐页审核变更、填写原因并输入指定版本确认词，才写配置和批准记录。部署前及应用容器启动时自动运行配置 guard；文件与批准版本不一致时拒绝启动。初次升级必须由用户在 UI 确认，不能由部署脚本代替。版本历史与维护规则见 `docs/部署/配置体系说明.md`。部署新增的 GPU 预留也先进入审核页面。

### 可变配置的生效方式

根 `.env.example` 提供部署配置清单、界面默认值和说明；可变配置目录固定为部署根目录下的 `./runtime-config`，只读挂载到 Backend/Agent 的 `/app/runtime-config`。必须挂载**目录**，不能只挂载 `config.json`，否则原子替换文件后容器可能仍读到旧文件。第一次增加目录挂载需要重新创建容器一次，以后修改已支持的热配置只需保存。界面只持久化明确配置的热参数，不把所有模板默认值写成覆盖项。

当前热配置支持：抽取算法版本、抽取模型地址/名称、输入输出 token 上限、并发、QPS/QPM、请求超时、thinking 开关、quota group、v3.1 请求/文档预算，以及已登记的解析、Embedding 和决策服务参数。Backend 在有本体的抽取/沉淀请求入队时读取并冻结抽取配置；修改影响新请求，在途任务和重试继续使用原快照。热配置 JSON 不接受凭据或任意环境变量。其他算法内部开关、API 密钥、队列/进程参数仍是启动配置，不能宣称都支持热更新。

评测每轮通过命令行指定参数，不再保存或加载评测 YAML/profile。judge 地址、模型、适配器和 token 上限只从这一轮命令行参数取得，不读取应用配置中的评测默认项。本地模型在 Backend 容器内使用 `http://llm_<模型名转为小写下划线>:8000/v1`，如 `http://llm_qwen_qwen3_5_4b:8000/v1`；宿主机使用对应的回环端口。两种运行位置需要相应的地址，界面不会猜测调用位置。

GPU、权重路径、模型监听端口、vLLM 上下文和缓存容量是服务启动参数，修改后必须重启对应模型进程；宿主端口映射、目录挂载和容器环境修改需要重建对应容器。界面标注“启动配置”的项只保存不立即生效，`a` 是维护窗口动作，会重建 Backend/Agent，已有任务应先结束。Clef/NanoJev 自身的启动配置需按现有部署流程重启相应服务，不由这个本地 vLLM 部署动作管理。

当前支持已登记模型的单 GPU 部署，多卡张量并行尚未提供。启用/停用计划、启动命令提交和实际模型健康是三个不同状态，不能把勾选或保存视为服务已就绪。

### 统一命令入口

```sh
ops config
ops check
ops deploy
ops status
```

模型分区内维护启用状态、GPU、端口、监听地址、权重相对路径、上下文、显存比例、并发、批处理和精度；不再维护 `.env` 的 `LLM_*` 参数，也不再手写单模型 Compose。

最大上下文是输入与输出的合计预算。压测分别记录 prefill、首 token 等待、decode token/s、总耗时和实际完成 token 数。仅请求被接受、随后取消的输出上限，不等于已经完整生成过该长度。
