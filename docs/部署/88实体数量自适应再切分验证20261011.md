对再切分结果核对每片 `text == source[start:end]`、第一/最后端点与原片相同、子片并集完整覆盖原片；二分/三分的相邻交集均为 **50 字**，与日志 `effective_overlap` 一致。JSON、围栏和修复后单列表格完整保留；回退记录不含原文或服务异常消息。

表格保护优先于数量桶，因此本版不能解决高密度结构块的单次负载。下一步应单独验证按完整表格行或 JSON 记录拆分、保留表头与局部上下文的方案，而非字符切开结构。

## API / 4B 小规模真实链路

这是使用合成可核验文本与简化 Device/Fault 本体的功能性验证，不是完整业务 benchmark。小样本有 4 个明确实体、2 条明确设备故障关系；设备名单有 30 个逐字命名设备。API 与 4B 并行执行，每个条件只运行一次，时延包含队列、解析、切片、抽取和返回，不作模型独占速度或统计显著性结论。

| 模型 | 输入/自适应 | 节点 | 关系 | 请求墙钟秒 |
| --- | --- | ---: | ---: | ---: |
| API | 短文/开 | 4 | 2 | 23.72 |
| Qwen3.5-4B | 短文/开 | 4 | 0 | 33.19 |
| API | 30 台设备/关 | 30 | 0 | 38.13 |
| API | 30 台设备/开 | 32 | 0 | 30.46 |
| Qwen3.5-4B | 30 台设备/关 | 30 | 0 | 98.92 |
| Qwen3.5-4B | 30 台设备/开 | 32 | 0 | 100.38 |

六个请求都正常返回，服务 `quality.status=succeeded`，不代表人工质量全部通过。短文的 4B 漏了两条关系。设备名单中，开/关两种条件及两个模型都保留全部 30 个预设名称；**开启后两个模型都多抽了 `控制器`、`第18号制动`，关闭后没有这些多抽**。这两个片段与字符再切分边界有关，说明即使源范围完整、overlap 保留，也不能保证切片不会诱发残缺名称实体。仅靠服务 succeeded 或只报召回，会掩盖这项退化。

本轮确认功能接入、真实模型调用、落盘和范围契约正常；没有证据声称下游质量已提升。高桶分类正确率、真实高密度表格拆分、边界实体与跨片关系仍需专项验证。保持默认关闭，仅用于显式开启的测试请求。
