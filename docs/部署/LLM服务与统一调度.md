# LLM 服务登记与调用调度

先在 `ops config` 登记服务，再给“知识抽取”“图谱检索”“Agent”“实体数量预测”选择已登记的服务。选项引用同一服务 ID，不复制地址、模型或密钥。保存仅改变计划；仍需逐页审核、填写原因和人工批准，不能由脚本代批。

## 服务和账号分别维护

API 服务登记地址、模型、凭据变量引用、实际上下文上限和最大输出上限，以及请求并发、每秒和每分钟限流。模型的真实能力需要依据供应商或实际验证填写；未填写能力代表未知，并非无限。算法维护自己的生成预算、思考选择和重试方案。公共调用层拒绝超出已登记能力的调用，不静默删除输入。

凭据字段填写已声明的变量名，例如 `AGENT_LLM_API_KEY`，不填写密钥值。配置 JSON、队列和日志不得保存真实密钥。输入上下文的检查采用 UTF-8 字节保守估算，包含消息、工具和输出预算，并非供应商计费 token 的精确值。

同一账号调用多个模型时，建立一个共享账号记录，把各服务关联到它。服务限制与账号总限制同时检查。`qps/qpm=0` 仅表示本系统不额外限制。此实现不覆盖供应商 TPM 限制。

## 统一请求排队

已登记的服务通过内部 Redis 的原子调度进入 FIFO 请求队列。Backend、Agent 的多个进程，共用同一服务并发和请求频率计数；关联同一账号的不同服务额外共用账号计数。Redis 中只有不含凭据的随机请求票据、哈希后的服务/账号标识和时间，不保存请求正文或鉴权头。

业务任务队列负责执行任务，模型调度只在调用 HTTP 前获取服务名额，当前 worker 自己发起 HTTP。模型调度不会再创建等待另一个 worker 执行的任务，避免嵌套任务占满 worker。

在途名额包含完整 HTTP 调用，流式调用直到响应流结束才释放。等待超时、等待取消、调用结束或异常都会清理票据；长调用由后台线程续期，进程崩溃后过期名额被回收。Redis 不可用时拒绝新调用，不切换为无限制调用。失去续期名额时丢弃结果并明确报错。网络分区造成已发出的供应商 HTTP 请求无法撤回时，租约过期不能证明供应商已停止处理，这一点仍需在部署观测和传输取消机制中验证。

已接入：抽取 SDK 调用、图谱检索、Agent 阻塞/流式调用、已登记的 Clef/NanoJev 判定调用。旧的未登记调用保留兼容路径，不能把它们视为已经实现服务级统一调度；迁移界面会展示原连接参数及冲突。显式评测 provider 可选择服务 ID，评测 judge 每次临时选择，不创建持久默认路由。

## 配置变更的范围

服务登记和用途路由属于已批准的热配置。新请求读取一个快照，已排队的抽取请求继续使用提交时的服务和账号额度快照。Agent 工作线程可复用 HTTP 连接，但每个新任务重新选择路由，同一任务中的后续工具规划继续保留原快照，不在执行中途改用另一个模型。

同一服务更新并发期间，新旧请求快照可能短暂并存；Redis 仍共用计数，新上限限制之后的新请求，但不会终止已开始的旧请求。部署前需执行配置门禁和相关测试；这轮实现尚未自动批准或部署到 88。

## 真实 Redis 验证

Windows 开发机可运行一个独立的测试 Redis（只绑定本机，不改应用 Redis）：

```powershell
docker run -d --rm --name qasystem-model-admission-test -p 127.0.0.1:16389:6379 redis:7-alpine
.venv/Scripts/python.exe -m pytest -q tests/test_llm_distributed.py
docker stop qasystem-model-admission-test
```

测试覆盖不同进程的共同服务/账号额度、FIFO、正常长调用续期、等待超时和取消、异常释放、进程崩溃回收与每秒限流。无测试 Redis 时这些集成测试明确跳过，不以假 Redis 的测试结果代替真实多进程验证。
