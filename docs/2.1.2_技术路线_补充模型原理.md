2.1.2.技术路线

多源数据预处理处理流程可清晰地划分为三个阶段。

（1）解析与提取
后端完成文件类型校验与临时落盘，支持 PDF、Word、PowerPoint、图片、Markdown/TXT、Excel/CSV 和 HTML。统一调度器根据文件类型、文档特征和解析器配置选择引擎：文本型 PDF 与简单 DOCX 优先使用 Docling，扫描或复杂 PDF、复杂 DOCX 和图片默认使用 VLM，MinerU 专用模型流水线用于用户明确选择或一次性 fallback；Excel/CSV 使用 Pandas，HTML 使用 Beautiful Soup，Markdown/TXT 直接读取。详细行为见[文档解析行为规范](文档解析行为规范.md)。

为提升可解释性，各处理模型原理如下：
- Docling：采用“文档结构感知 + 版面语义重建”思路，对 Word 文档中的段落、标题层级、列表、表格与图片引用关系进行统一解析，再按语义块重组为标准 Markdown。对于 .doc 文件，先经 LibreOffice 转换为 .docx，以降低旧格式二进制差异对结构抽取的影响。
- VLM：对页面图像进行整体视觉理解，输出正文、版面、表格和公式等结构化内容。
- MinerU：通过 OCR、表格和公式等专用模型流水线解析文档，支持独立控制 OCR、表格和公式识别。
- Pandas：基于 DataFrame 的表格化数据解析机制，通过编码识别、分隔符推断与列类型推断完成 Excel/CSV 的结构恢复；随后以统一二维表结构输出，便于后续标准化转换为 Markdown 表格与下游数据库入库。

（2）标准化与输出
各解析器的结果在服务层统一转换为 Markdown。解析响应只暴露精简元数据，包括最终引擎，以及按需出现的用户引擎处理结果、fallback 信息、MinerU 识别配置或文本编码；内部文件路径和底层调试信息不进入成功响应。

（3）存储与应用
最终产出的统一结构化数据，具备极强的平台适配性，可被无缝注入各类存储系统，从而激活多样化的高级应用场景。数据切片后可存入知识图谱，以构建实体、属性及其间的复杂关系网络，支撑深度推理与关联发现；也可导入向量数据库，通过将文本转化为嵌入向量，赋能基于语义相似度的智能检索、问答和推荐系统；同时，其中规整的表格数据可直接落地到关系型数据库，满足传统的统计分析、报表生成和业务系统集成需求。这一设计使得原始文档中的信息得以转化为可灵活调用、可深度挖掘的数字资产，全面服务于知识管理、智能分析与决策支持。
