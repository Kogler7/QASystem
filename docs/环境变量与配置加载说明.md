# 环境变量与配置加载说明

本文说明 QASystem 在本地开发、Docker Compose 和其他托管环境中的配置来源、加载顺序及生效方式。

## 基本原则

- `.env.example` 是可提交的配置模板，不存放真实密钥。
- 仓库根 `.env` 是本地配置文件，也是当前 Docker Compose 的 `env_file`。
- Docker、Kubernetes、systemd 和 CI/CD 等托管环境应把配置注入进程环境。
- Server 仅在未检测到托管环境时加载仓库根 `.env`。
- 配置读取统一遵循“进程环境优先”，dotenv 不覆盖已经存在的变量。

## 配置来源与优先级

优先级从高到低为：

```text
Docker/Kubernetes/操作系统注入的进程环境变量
    ↓
本地开发使用的仓库根 .env
    ↓
代码默认值
```

后端使用 `load_dotenv(..., override=False)`，因此 `.env` 不会覆盖同名进程环境变量。

## Server 的加载判断

启动入口调用 `backend.app.environment.configure_runtime_environment()`，判断规则如下：

| 条件 | 是否读取根 `.env` |
| --- | --- |
| `QASYSTEM_LOAD_DOTENV=true` | 是，显式强制加载 |
| `QASYSTEM_LOAD_DOTENV=false` | 否，只使用进程环境 |
| 未设置开关，但进程已有 `ENVIRONMENT` | 否，视为托管环境 |
| 开关和 `ENVIRONMENT` 都未设置 | 是，视为本地直接启动 |

`QASYSTEM_LOAD_DOTENV` 支持 `true/false`、`1/0`、`yes/no` 和 `on/off`；其他值会使启动快速失败，避免误用模糊配置。

需要注意：本地直接启动时，加载判断发生在读取 `.env` 之前。因此即使根 `.env` 中写有
`QASYSTEM_LOAD_DOTENV=false`，只要启动进程此前没有注入该变量，本地启动仍会自动读取根 `.env`；
Docker Compose 则会先通过 `env_file` 注入该变量，所以 Server 不会再次加载文件。

## Docker Compose

`docker-compose.yml` 使用：

```yaml
env_file:
  - .env
```

Compose 在创建容器时读取根 `.env` 并注入 backend 进程。推荐配置：

```env
QASYSTEM_LOAD_DOTENV=false
ENVIRONMENT=production
```

修改 `.env` 后，`docker compose restart` 不会重新创建容器环境。应执行：

```powershell
docker compose up -d --force-recreate backend
```

只修改环境变量不需要重建镜像；修改 Python 代码或依赖后才需要重新构建镜像。

## 本地启动

本地 PowerShell 直接运行时，如果没有预先设置 `ENVIRONMENT` 或 `QASYSTEM_LOAD_DOTENV`，后端会自动加载仓库根 `.env`：

```powershell
$env:PYTHONPATH="$PWD;$PWD\agent"
Set-Location backend
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

如需完全忽略 `.env` 并只使用当前终端变量：

```powershell
$env:QASYSTEM_LOAD_DOTENV="false"
$env:ENVIRONMENT="development"
```

本地修改 `.env` 后需要重启 Uvicorn。业务配置在模块导入时读取，不支持运行中热更新。

## LLM 配置分组

| 模块 | 环境变量前缀 |
| --- | --- |
| 知识抽取 | `KG_EXTRACT_LLM_*` |
| 图谱定位与实体链接 | `GRAPH_LLM_*` |
| Agent 运行时 | `AGENT_LLM_*` |

知识沉淀逐切片调用 LLM 时，可配置：

```env
KG_EXTRACT_LLM_MAX_CONCURRENCY=4
KG_EXTRACT_LLM_QPS=2
KG_EXTRACT_LLM_QPM=60
```

- `MAX_CONCURRENCY`：同时在途的请求数，至少为 `1`。
- `QPS`：一秒滑动窗口允许的最大请求数，`0` 表示不限制。
- `QPM`：一分钟滑动窗口允许的最大请求数，`0` 表示不限制。
- 首次 LLM 请求和 JSON 格式重试都会占用配额。

## 排查配置是否生效

容器内只检查非敏感配置：

```powershell
docker compose exec backend python -c "import os; print({k: os.getenv(k) for k in ['ENVIRONMENT','QASYSTEM_LOAD_DOTENV','KG_EXTRACT_LLM_MAX_CONCURRENCY','KG_EXTRACT_LLM_QPS','KG_EXTRACT_LLM_QPM']})"
```

不要在日志或排障命令中输出 `*_API_KEY`、数据库密码或其他密钥。

知识沉淀成功响应的 `data.stats.extraction.scheduler` 也会返回实际生效的并发、QPS 和 QPM，但不会返回密钥或 LLM 地址。

- 后端启动入口：`/backend/app/main.py`
- 知识抽取配置：`/algorithm/knowledge_extract/config.py`
- LLM 调度器：`/algorithm/knowledge_extract/scheduler.py`
