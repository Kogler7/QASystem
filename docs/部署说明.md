# QASystem 部署说明

仓库根目录是唯一部署配置入口：

- `.env.example`：唯一环境变量模板。
- `Dockerfile`：包含后端、Agent、系统程序和 Python 依赖的完整运行镜像。
- `docker-compose.yml`：唯一 Compose 配置。
- `build-image.ps1`：构建候选镜像、执行容器内验证并原子替换正式标签。
- `package-deploy.ps1`：生成独立的 Compose 交付目录，并可导出已验证的离线镜像包。

`deploy/` 默认提供自包含交付模式，包含 Compose、脱敏环境模板、部署说明、模型挂载目录、校验清单和可选的离线镜像包；`deploy/source-mounted/` 额外提供与镜像同提交的运行源码和源码挂载 Compose。

## 准备配置

```powershell
Copy-Item .env.example .env
```

Docker 与本地启动的配置来源、覆盖优先级和修改后的生效方式见
[环境变量与配置加载说明](环境变量与配置加载说明.md)。

LLM 配置按调用模块分组：

| 模块 | 环境变量前缀 |
| --- | --- |
| 知识抽取 | `KG_EXTRACT_LLM_*` |
| 图谱定位与实体链接 | `GRAPH_LLM_*` |
| Agent 运行时 | `AGENT_LLM_*` |

知识抽取会对文档切片并发调用 LLM。使用 `KG_EXTRACT_LLM_MAX_CONCURRENCY` 控制同时在途请求数，
使用 `KG_EXTRACT_LLM_QPS` 和 `KG_EXTRACT_LLM_QPM` 设置滑动窗口限流；QPS/QPM 为 `0` 时不限制。
限流对首次请求和 JSON 格式重试都生效。

## 构建并验证镜像

```powershell
.\build-image.ps1
```

脚本先构建 `candidate-latest`，验证 Python 依赖、系统程序、文档解析能力以及 Backend/Agent 入口。镜像构建还会通过 Maven 编译内置的 ofdrw OFD 转 PDF 工具，并校验 Java 运行时和转换 jar。只有全部通过后才替换 `qasystem-backend:latest`，旧镜像会在不再被引用时删除。

内网环境可先导入批准的基础镜像，再通过 `-PythonImage`、`-NodeImage` 指定本地标签；默认使用 Docker Hub 官方标签。

如需生成独立交付目录并导出离线镜像：

```powershell
.\package-deploy.ps1 -IncludeImage
```

生成目录：

```text
deploy/
├── README.md
├── docker-compose.yml
├── .env.example
├── models/
├── source-mounted/
│   ├── runtime/
│   ├── docker-compose.yml
│   └── .env.example
├── 交付清单.json
├── qasystem-backend-latest.tar  # 可选
└── redis-7-alpine.tar           # 可选
```

交付方默认在 `deploy/` 复制 `.env.example` 为 `.env`，填入目标环境的外部服务和密钥，并按需要准备 `models/`。该模式使用镜像内应用源码。需要外部源码挂载时，改在 `deploy/source-mounted/` 使用其 Compose 与环境模板；其 `runtime/` 和根目录镜像必须作为同一版本整体交付。离线交付时先在 `deploy/` 执行 `docker load -i qasystem-backend-latest.tar` 与 `docker load -i redis-7-alpine.tar`。

## 构建与启动

```bash
docker compose up -d
curl http://127.0.0.1:8006/health
curl http://127.0.0.1:9180/health
```

Compose 启动 `backend`、`agent` 和 `redis`。统一 MCP 的宿主机地址为 `http://127.0.0.1:8006/mcp`，Agent 容器通过 `http://backend:8000/mcp` 访问。MySQL、Neo4j、Elasticsearch、LLM 和文件服务均作为外部服务配置。

业务 HTTP 接口和返回协议见[算法接口协议](算法接口协议.md)，文档解析模型与 GPU 要求见[文档解析部署与依赖](文档解析部署与依赖.md)。

Agent API 默认地址为 `http://127.0.0.1:9180`。详细配置、容量规划和排障见 [`agent/docs/部署运维指南.md`](../agent/docs/部署运维指南.md)。

Backend 与 Agent 代码已经打入镜像，Compose 不再用宿主机目录覆盖 `/app`。这样代码版本和依赖版本始终一致。业务代码或依赖更新后执行：

```powershell
.\build-image.ps1
docker compose up -d --force-recreate backend agent
```
