# QASystem 部署说明

## 镜像职责

部署采用固定双镜像契约：

| 镜像 | 内容 | 更新时机 |
| --- | --- | --- |
| `qasystem-base-v1` | CUDA、vLLM、Torch、系统工具、Python/Node/Java 依赖 | 首次部署或底层依赖不兼容升级 |
| `qasystem-runtime-v1` | Backend、Agent、算法源码、入口、健康检查和运行时校验 | 每次代码发布 |

`Dockerfile` 只定义 base，`Dockerfile.runtime` 在 base 上叠加应用。base 不能直接启动服务。旧完整镜像只允许作为 `docker/make-runtime-base.sh` 的一次性迁移输入。

## 本机构建

首次构建两个镜像：

```powershell
.\build-image.ps1 -BuildBase
```

普通代码更新只构建 runtime，并复用本机 `qasystem-base-v1`：

```powershell
.\build-image.ps1
```

脚本构建候选标签、执行镜像内校验，通过后才更新正式标签。只重建 base 时使用 `-BuildBase -BaseOnly`。只有 CUDA、vLLM、Torch、系统包、Python 依赖契约、OpenCode、Java 或 OFD 工具发生不兼容变化时才应使用 `-BuildBase`。

## 生成交付包

日常发布：

```powershell
.\package-deploy.ps1
```

默认只生成 `runtime-context.tar` 和部署配置，不导出任何大镜像。首次离线部署按需加入 base 和 Redis：

```powershell
.\package-deploy.ps1 -IncludeBaseImage -IncludeRedisImage
```

不要执行 `docker save qasystem-runtime-v1`：Docker 会把 base 的全部父层一并写入 tar，重新产生约 30GB 的重复传输。目标机应保留 `qasystem-base-v1`，收到小型 runtime context 后本地构建。

## 目标机部署

首次部署若有镜像归档，先执行：

```bash
docker load -i qasystem-base-v1.tar
docker load -i redis-7-alpine.tar
cp .env.example .env
```

编辑 `.env` 后运行：

```bash
chmod +x apply-runtime.sh
./apply-runtime.sh
```

脚本校验归档、在 base 上构建候选 runtime、执行完整校验、保存旧 runtime rollback 标签、校验 Compose、重建服务并等待健康状态。失败时恢复旧 runtime 标签。日常更新仍执行同一命令，不重新加载 base。

## 环境变量

根目录 `.env.example` 是唯一模板。`docker-compose.yml` 只描述服务拓扑、端口、卷和健康检查，不重复配置算法或调度参数。部署包中的 `.env.example` 会把 `HOST_MODELS_DIR` 调整为交付目录内的 `./models`。

目标 8 卡 A40 主机仅使用后四卡时必须保留：

```dotenv
BACKEND_IMAGE=qasystem-runtime-v1
GPU_DEVICE_IDS=4,5,6,7
```

修改 `.env` 后重新创建容器即可生效，不需要重建 base/runtime。模型不进入镜像，通过 `HOST_MODELS_DIR` 只读挂载到 `/models`。完整变量说明见[环境变量与配置加载说明](环境变量与配置加载说明.md)，迁移步骤见 [ENV_MIGRATION.md](../docker/ENV_MIGRATION.md)。

## 服务与协议

Compose 只启动 `backend`、`agent` 和 `redis`。Backend supervisor 根据 `GPU_DEVICE_IDS` 自动启动 API、CPU worker、每卡一个 vLLM engine、VLM dispatch worker 及共享 Embedding/Confidence worker；无需在 Compose 中枚举进程。

默认 `EXECUTION_MODE=async`、`MCP_EXECUTION_MODE=sync`。业务接口未携带 `Prefer` 时仍等待并返回原业务结果，只新增顶层 `execution`；`Prefer: respond-async` 才立即返回 `202`。详见[算法接口协议](算法接口协议.md)。
