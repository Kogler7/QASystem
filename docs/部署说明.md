# QASystem 部署说明

## 部署模型

`qasystem-env-v1` 是唯一 Docker 应用环境镜像，只包含系统和语言运行环境、CUDA/vLLM/Torch、Python 依赖及文档转换工具。业务源码和 models 不进入镜像：

- `QASYSTEM_SOURCE_DIR`：Backend、Agent、算法和 MCP 源码根目录，Compose 只读挂载。
- `HOST_MODELS_DIR`：Docling、MinerU 和 Embedding 模型目录，Compose 只读挂载到 `/models`。

容器继续使用命名卷保存 Backend 数据、Agent 输出和 Redis 数据。

## 构建环境镜像

```powershell
.\build-image.ps1
```

脚本构建候选 env 镜像，然后把当前仓库源码只读挂载到候选容器，验证 Python 依赖、系统工具、OpenCV、Backend/Agent 入口和 OFD 工具。全部通过后才更新 `qasystem-env-v1`。

镜像不需要随普通代码发布重建。只有 CUDA、vLLM、Torch、系统包、Python 依赖、OpenCode、Java 或 OFD 工具发生变化时才重新构建。

## 生成交付目录

普通代码交付：

```powershell
.\package-deploy.ps1
```

首次部署或环境变化时附带 env 镜像：

```powershell
.\package-deploy.ps1 -IncludeEnvImage -IncludeRedisImage
```

默认生成可直接挂载的 `deploy/runtime/`，不会构建或导出其他应用镜像。详细目录与操作见 [DEPLOY_PACKAGE_README.md](../docker/DEPLOY_PACKAGE_README.md)。

## 配置与启动

仓库根目录 `.env.example` 是唯一配置模板。本地 Compose 使用：

```dotenv
QASYSTEM_ENV_IMAGE=qasystem-env-v1
QASYSTEM_SOURCE_DIR=.
HOST_MODELS_DIR=./deploy/models
GPU_DEVICE_IDS=4,5,6,7
```

交付包会自动改成 `QASYSTEM_SOURCE_DIR=./runtime` 和 `HOST_MODELS_DIR=./models`。

```bash
docker compose config --quiet
docker compose up -d
curl -fsS http://127.0.0.1:8006/health
```

普通代码升级只需整体替换源码目录并执行：

```bash
docker compose up -d --force-recreate backend agent
```

Compose 只启动 Backend、Agent 和 Redis；Backend supervisor 根据 `GPU_DEVICE_IDS` 自动管理 API、Worker 和每卡 vLLM engine，无需枚举服务进程。
