# QASystem 部署说明

仓库根目录是唯一部署配置入口：

- `.env.example`：唯一环境变量模板。
- `Dockerfile`：包含后端、Agent、系统程序和 Python 依赖的完整运行镜像。
- `docker-compose.yml`：唯一 Compose 配置。
- `build-image.ps1`：构建候选镜像、执行容器内验证并原子替换正式标签。
- `package-deploy.ps1`：生成独立的 Compose 交付目录，并可导出已验证的离线镜像包。

`deploy/` 只提供自包含镜像交付模式，包含 Compose、脱敏环境模板、部署说明、模型挂载目录、校验清单和可选的离线镜像包。目标机不挂载或复用旧版应用源码。

## 准备配置

```powershell
Copy-Item .env.example .env
```

Docker 与本地启动的配置来源、覆盖优先级和修改后的生效方式见
[环境变量与配置加载说明](环境变量与配置加载说明.md)。

LLM 配置按调用模块分组：

| 模块 | 环境变量前缀 |
| --- | --- |
| 知识抽取 | `KG_EXTRACT_LLM_*` |
| 图谱定位与实体链接 | `GRAPH_LLM_*` |
| Agent 运行时 | `AGENT_LLM_*` |

知识抽取会对文档切片并发调用 LLM。使用 `KG_EXTRACT_LLM_MAX_CONCURRENCY` 控制同时在途请求数，
使用 `KG_EXTRACT_LLM_QPS` 和 `KG_EXTRACT_LLM_QPM` 设置滑动窗口限流；QPS/QPM 为 `0` 时不限制。
限流对首次请求和 JSON 格式重试都生效。

## 构建并验证镜像

```powershell
.\build-image.ps1
```

脚本先构建 `candidate-latest`，验证 Python 依赖、系统程序、文档解析能力以及 Backend/Agent 入口。镜像构建还会通过 Maven 编译内置的 ofdrw OFD 转 PDF 工具，并校验 Java 运行时和转换 jar。只有全部通过后才替换 `qasystem-backend:latest`，旧镜像会在不再被引用时删除。

内网环境可先导入批准的基础镜像，再通过 `-PythonImage`、`-NodeImage` 指定本地标签；默认使用 Docker Hub 官方标签。

如需生成独立交付目录并导出离线镜像：

```powershell
.\package-deploy.ps1 -IncludeImage
```

生成目录：

```text
deploy/
├── README.md
├── docker-compose.yml
├── .env.example
├── models/
├── 交付清单.json
├── qasystem-backend-latest.tar  # 可选
└── redis-7-alpine.tar           # 可选
```

交付方默认在 `deploy/` 复制 `.env.example` 为 `.env`，填入目标环境的外部服务和密钥，并按需要准备 `models/`。应用源码、MinerU、vLLM、调度器及运行依赖均来自同一个 Backend 镜像。离线交付时先在 `deploy/` 执行 `docker load -i qasystem-backend-latest.tar` 与 `docker load -i redis-7-alpine.tar`。

## 构建与启动

```bash
docker compose up -d
curl http://127.0.0.1:8006/health
curl http://127.0.0.1:8006/agent/health
```

Compose 只启动 `backend`、`agent` 和 `redis`。目标 8 卡 A40 服务器默认使用 `GPU_DEVICE_IDS=4,5,6,7`；Backend supervisor 仅在选中的后四卡内自动启动 API、CPU worker、每卡一个 vLLM engine、VLM dispatch worker 及共享 Embedding/Confidence worker，并负责预热和子进程生命周期。统一 MCP 的宿主机地址为 `http://127.0.0.1:8006/mcp`，Agent API 由 Backend 反向代理，宿主机地址为 `http://127.0.0.1:8006/agent`；Agent 容器在 Docker 内网通过 `http://backend:8000/mcp` 访问 MCP。MySQL、Neo4j、Elasticsearch、LLM 和文件服务均作为外部服务配置。

默认 `EXECUTION_MODE=async`、`MCP_EXECUTION_MODE=sync`。前者表示 HTTP 业务计算由 Redis 队列和 Worker 执行，但未携带 `Prefer` 时仍同步返回原状态码和业务 `data`，只新增顶层 `execution`；`Prefer: respond-async` 才立即返回 `202`，`Prefer: wait=N` 表示显式有界等待，新增 `POST /api/v1/jobs` 默认返回 `202`。显式异步调用在 SSE `job.completed` 后通过 `execution.result_url` 获取完整最终 envelope。MCP 的 `sync` 表示队列执行后等待并返回原工具结果，只有显式改成 `async` 才返回任务句柄。Redis 不可用时返回 `503`，不会回退到 Gateway 内执行。单元测试或算法调试才使用 inline 模式。

业务 HTTP 接口和返回协议见[算法接口协议](算法接口协议.md)，文档解析模型与 GPU 要求见[文档解析部署与依赖](文档解析部署与依赖.md)。

Agent API 默认地址为 `http://127.0.0.1:8006/agent`。详细配置、容量规划和排障见 [`agent/docs/部署运维指南.md`](../agent/docs/部署运维指南.md)。

Backend 与 Agent 代码已经打入镜像，Compose 不再用宿主机目录覆盖 `/app`。这样代码版本和依赖版本始终一致。业务代码或依赖更新后执行：

```powershell
.\build-image.ps1
docker compose up -d --force-recreate backend
```
