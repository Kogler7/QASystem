# 外部应用服务与鉴权说明

QASystem 不直接访问应用团队负责的业务数据库。除暂时保留的 SQL 查询兼容能力外，文件、向量和知识图谱数据均通过应用团队统一服务访问，用户鉴权信息随调用透传。

## 配置

统一服务地址使用：

```env
APPLICATION_SERVICE_URL=http://application-server
```

旧 `FILE_SERVICE_URL` 通过 `ops config` 迁入 `APPLICATION_SERVICE_URL`，运行时不再读取旧名称；新旧值不一致时必须在 UI 中确认。SQL 仍读取 `MCP_DATABASE_URL`，缺失时回退到 `DATABASE_URL`，两者可用于不同连接。

外部能力集中注册在 `external_services/application.py`，算法和 MCP 工具不得自行拼接第三方 URL。当前注册状态：

| 能力 | 接口 | 状态 |
| --- | --- | --- |
| `files.upload` | `POST /third/files/upload` | 已接入 |
| `vectors.store` | `POST /third/vectors/store` | 已接入 |
| `graph.cypher.query` | `POST /third/cypher/query` | 已接入 |
| `graph.write` | 待应用团队提供 | 不可用 |
| `confidence.calculate` | 待应用团队提供 | 不可用 |
| `documents.evidence.search` | 待应用团队提供 | 不可用 |
| `models.embeddings.create` | `POST /v1/embeddings` | 已接入（远程向量服务） |
| `documents.parse` | `POST /v1/documents/parse` | 已接入（远程文档解析服务） |

后两者属于 remote-only 模式的远程模型服务：Base URL 分别取 `EMBEDDING_SERVICE_URL`、`DOCUMENT_PARSE_SERVICE_URL`，路径可用 `EMBEDDING_SERVICE_PATH`、`DOCUMENT_PARSE_SERVICE_PATH` 覆盖，鉴权使用各自的服务级 API Key（`EMBEDDING_SERVICE_API_KEY`、`DOCUMENT_PARSE_SERVICE_API_KEY`），不走用户鉴权透传。

未开放能力不会阻止服务启动，也不会回退到 Neo4j 或 Elasticsearch；调用时 HTTP 返回 `8002 / EXTERNAL_CAPABILITY_UNAVAILABLE` 和 `503`，MCP 返回 `3902`。

## 队列鉴权上下文

入口仅捕获 `Authorization`、`X-User-Id`、`X-User-Name`、`X-Tenant-Id` 和 `X-User-Roles`。

提交任务时，白名单头写入 Redis 独立 KV，任务和 Redis Stream envelope 只携带随机 `auth_context_id`。Worker 执行前按 `job_id` 校验并恢复上下文，外部请求结束后清除进程上下文；任务成功、取消或最终失败后删除 KV，重试期间保留。KV 默认 TTL 为 `EXECUTION_AUTH_CONTEXT_TTL_SECONDS=3600`。

这样可以避免 Bearer Token 随 Stream、任务产物、执行记录或 SSE 长期留存。日志、接口响应和顶层 `execution` 均不得输出鉴权头或其内容。

生产环境只有受信任网关可以写入 `X-User-*` 头；网关必须覆盖而不是接受客户端任意传入的同名头。Bearer Token 的实际有效期仍由应用团队鉴权服务决定，Redis TTL 不会延长已经过期的 Token。
