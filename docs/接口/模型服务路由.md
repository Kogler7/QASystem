# 模型服务路由

独立模型由 `ops` 管理。Backend 调用 `external_services/model_routes.py` 解析已批准的登记，算法不自行决定容器名、GPU 或服务地址。

## 登记与用途

`runtime-config/config.json` 中，`models` 保存模型运行记录，`services` 保存可调用的服务，`routes` 将用途指向服务 ID。GPU、宿主机端口和权重目录只放在模型记录中；本地服务地址由模型 ID、固定容器端口和 adapter 推导，不再填另一份地址。

| 用途 | 当前消费者 | 服务协议 |
| --- | --- | --- |
| `extract` | 公共抽取请求配置，适用于各抽取算法版本 | chat |
| `entity_count` | 公共切片层的实体数量预测 | clef / nanojev |
| `judge` | 可供显式指定用途的服务客户端解析 | chat / clef / nanojev |

`judge` 路由不恢复评测默认配置。评测仍由本次命令行临时选择 judge；显式地址和 provider 配置优先。

本地服务引用 `models` 的 ID。API 服务记录地址、模型名及现有凭据变量名；凭据值只由 `docker.configuration` 读取，不能写入登记、队列载荷、动作日志或结果。`backend-worker` 模型不是独立调用服务，不能通过该入口启动或调用。

## 请求如何选择

抽取未指定 provider 或指定 `default` 时使用 `extract` 路由；显式 provider 档案继续使用该档案。请求显式 model、timeout 等现有覆盖项保留原有语义。登记路由指向不存在、关闭或协议不兼容的服务时明确报错，不会悄悄改用旧环境变量或另一家 API。

实体计数未显式填写 `entity_count_model` 时使用 `entity_count` 路由。显式填写 `clef-flash` 或 `nanojev` 时，若默认路由不是该模型，则查找唯一启用的对应服务；找不到或存在多个候选时明确报错。判断显式与否采用原始请求字段，以及直接服务调用的 Pydantic `model_fields_set`，不把 schema 自动补入的默认值误认为用户选择。

默认 Clef/NanoJev 公共客户端也从登记解析对应 adapter。若有多个启用候选，需要明确用途路由。显式 `base_url` 保持优先，可用于本次评测临时指定服务。

## 热更新与在途请求

提交图谱抽取、知识沉淀或切片请求时读取一次批准登记。抽取配置与实体计数服务快照写入内部队列载荷，保留模型、地址、凭据变量名和配置 revision，不含凭据值。重试和多片处理沿用该快照，更新路由影响随后提交的新请求。

尚未迁移且登记为空时兼容原有配置。实体计数也在提交时固定兼容地址、路径、模型与超时；等待队列期间新增路由，不会改变该旧请求的目标。

实体数量预测失败仍遵守公共切片层的回退行为，保留原片并记录回退。成功决策日志额外记录实际 `model`、`service_id` 和 `config_revision`，可与批准记录对照。默认日志位置仍为 `/app/backend/tmp/chunk_entity_decisions.jsonl`。

配置只能在 `ops config` 中人工审核差异并批准；`ops deploy` 和容器启动 guard 校验批准内容。路由读取没有跳过 guard 或自动批准入口。
