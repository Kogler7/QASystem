# LLM多候选Judge对比（2026-10-12）

## 结论与口径

已完成API（DeepSeek Flash）、Qwen3.5-4B、Qwen3-8B、Qwen3.5-9B的真实多候选评测，本轮部署实测仍优先推荐API。9B在完整小窗口的语义准确率优于两款较小Qwen，但大窗口仍有索引越界、漏判和顺序敏感，未解决正式窗口的可靠性问题。之前单对测试中本地4B与API相近，不能直接用于正式大窗口选型。9B首次启动因磁盘读取阻塞失败，重试将同版本权重复制到RAM并校验后成功；其GPU6与他人任务共享，速度不能据此归因为模型本身更慢。

本轮仅通用chat LLM，不含Clef、Kev或NanoJev。复用88已保存的预测/golden，不重新抽取；API总共124次实际HTTP尝试（大窗口96、小窗口28），没有新增抽取调用。源文件和评测代码在执行前冻结并记录SHA256；不改提示词或标签来迎合结果。

## 测试链路

执行正式 `eval/run.py::_judge_collection`：自动匹配→40×20扫描→同身份属性/端点冲突补判→类型过滤→全局最大匹配。所有模型共用正式提示词、temperature=0、关闭thinking、max_tokens=8192、response_format=auto。API使用json_object，本地服务默认json_schema，是现有正式客户端的自动策略，没有强制改成单对选择题。每个模型窗口并发2。

16个大/自然尾窗口来自5份文档，6个满40×20，输入2675–44363字符；仅16个精确对应历史审核点有参考标签，其中4个可程序自动匹配。质量排名重点参考剩余12个语义点，其余未知边不假设正确或错误。6个4×4真实小子图完整复核96格，85个同类型语义标签、11个类型约束单列；除去6个自动匹配点，模型判断79点。标签均为明确标注来源的代理复核，并非独立人工真值。大窗口和小窗口质量不混为一个总准确率。

每组窗口3次同输入，再反转两侧候选顺序1次。逆映射索引后比较候选边集；另报告最大匹配数量变化，避免把等价匹配的人员分配变化误当成评分漂移。失败不算稳定，失败标签计入准确率分母。所有速度含HTTP、服务调度、响应处理和必要补判，未包含模型下载/冷启动；共享机器负载下的方案实测，不是纯模型极限吞吐。

| 方案 | 语义点首轮正确（含失败） | 误匹配 / 漏匹配 / 失败点 | 失败窗口（四轮64组） | 首轮平均整窗口耗时 | 首轮16窗口墙钟 |
| --- | --- | --- | --- | --- | --- |
| API DeepSeek Flash | 10/12，83.3% | 1 / 1 / 0 | 0/64 | 1.75秒 | 15.11秒 |
| Qwen3-8B | 8/12，66.7% | 0 / 2 / 2 | 13/64 | 8.41秒 | 68.26秒 |
| Qwen3.5-4B | 5/12，41.7% | 1 / 4 / 2 | 8/64 | 6.05秒 | 52.84秒 |
| Qwen3.5-9B（共享GPU） | 7/12，58.3% | 0 / 2 / 3 | 15/64 | 25.78秒 | 218.35秒 |

含程序自动匹配点的全16点首轮正确数分别为14、11、9、11，只作全链路补充，不拿程序贡献给模型加分。原三方案共同成功首轮窗口上，API平均1.62秒、4B5.07秒、8B5.97秒；加入9B后四方案共同成功集为10组，API1.62秒、4B4.58秒、8B6.23秒、9B12.23秒。表中整窗口平均耗时包含失败耗时，墙钟是并发2完成一轮的实际等待时间。部分本地窗口返回索引越界，正式链路明确失败；8B反序轮另出现慢请求。9B四轮失败包括3次180秒超时和12次索引越界，前者受共享资源影响，后者是输出契约错误。所有失败保留，没有静默回退identity或删除失败样本。

| 方案 | 同输入候选边漂移 | 三轮失败/不完整窗口 | 反序候选边变化 | 反序匹配数量变化 |
| --- | --- | --- | --- | --- |
| API | 3/16 | 0 | 8/16 | 4/16 |
| Qwen3-8B | 0/13 | 3 | 9/10 | 8/10 |
| Qwen3.5-4B | 2/14 | 2 | 10/12 | 8/12 |
| Qwen3.5-9B | 1/13 | 3 | 7/10 | 6/10 |

8B的0/13不意味着总体可靠：3组重复评估不完整且反序敏感很高。9B有3组重复评估不完整，首轮和反序都成功的只有10组，6组反序对比不完整；一次同输入匹配数为10/10/4，反序另有10→2。API也有漂移；一个关系窗口三轮匹配数2/0/0，另一个反序从0变6。由于大窗口未完整标注，不把这些数量直接称为正确F1，仅表明当前评分受上下文和顺序影响。

## 完整小窗口的评分偏差

| 方案 | 待模型语义点正确 | 误匹配 / 漏匹配 | 首轮平均整窗口耗时 | 相对参考F1平均绝对偏差 | 首轮评分完全一致窗口 |
| --- | --- | --- | --- | --- | --- |
| API | 79/79，100% | 0 / 0 | 0.97秒 | 0个百分点 | 6/6 |
| Qwen3-8B | 77/79，97.5% | 1 / 1 | 2.02秒 | 8.33个百分点 | 4/6 |
| Qwen3.5-4B | 75/79，94.9% | 3 / 1 | 1.69秒 | 4.17个百分点 | 5/6 |
| Qwen3.5-9B（共享GPU） | 78/79，98.7% | 0 / 1 | 5.35秒 | 4.17个百分点 | 5/6 |

四者小窗口全部24组/方案成功，同输入各3次均未观察到候选边漂移。反序后API6组仍全部一致；4B和9B各有2/6组评分变化，8B有3/6组评分变化。9B首轮漏掉一组关系匹配，造成该组F1低估25个百分点，反序后这组恢复但另一组低估25个百分点。8B首轮平均有符号F1偏差为0，但一组高估25个百分点、一组低估25个百分点相互抵消，因此选型应看绝对偏差，不能只看均值。

小窗口的高准确率不能外推大窗口；79点中67个是负例，因此同时看正例召回，API12/12、三款Qwen均11/12。小窗口无失败，F1偏差均覆盖完整6组；大窗口JSON中的positive_recall/negative_recall仅为成功判定的条件召回，不包含失败标签，选型优先看含失败的准确率和完成率。评分按原抽取项数和golden项数计算，即先最大匹配再算F1，不把候选边数量直接当TP。不同类型的11格不计模型语义准确率。

## 记录与局限

数据：`test_data/judge_windows/v1/`，来源恢复与标签映射可追溯；大窗口仅16标签，3份来源快照无法恢复的4题明确排除，不用相似同文档快照替代。小窗口是便利抽样和代理复核，不足以证明总体显著差异或全文档F1真值。

脚本：`eval/tools/judge_window_compare.py`、`judge_window_report.py`；输出：`tmp/eval/judge-windows-20261012/` 和 `judge-small-windows-20261012/`。未修改正式Judge提示词、抽取流程或部署配置。数据/流程相关6项单测通过。四模型实际HTTP尝试共470次（API124、4B116、8B117、9B113），9B重试新增API调用0次，没有额外抽取调用；未自动提交本轮实验文件。
