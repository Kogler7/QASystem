# V3 抽取质量排查与 P0 消融对比报告（2026-10-03）

## 1. 背景与结论

用户反馈"V3 抽取比 V2 差"。排查与三轮全量评测（16 case：official×10、standard×4、rule×1、simple×1）后结论：

**V3 基线差的直接原因不是抽取能力，而是发布侧的 fail-closed 闸门**：证据验证闸把 LLM 实际抽出的实体整批扣押（如 standard_01 抽出 268 个实体，被 92 个 `EVIDENCE_INVALID L2 Literal Match` 硬错误清零），叠加修复循环不收敛、重试未启用，造成 7/16 case 空抽取。

**P0 止血修复（commit `9d44bcb`）后，V3 全面反超 V2**：

- 空抽取 7 → **0**，16/16 全部成功；
- 实体 F1：**0.381**（v2 0.214，+78%；v3 基线 0.055）；
- 关系 F1：**0.180**（v2 0.074，+143%；v3 基线 0.007）；
- 占 golden 88% 的 standard 组实体 F1 达 **0.429**，是 v2（0.216）的两倍。

门禁仍未过（退出码 4，14 个 case 实体 F1 < 0.5），未达发布线，剩余差距集中在 official 公文组与关系抽取，见第 8 节。

## 6. P0 各项修复的归因

| 修复（`9d44bcb`） | 机制 | 实证效果 |
| --- | --- | --- |
| `KG_EXTRACT_EVIDENCE_ADMISSION=warn`（默认） | 证据定位失败保留候选并标 `evidence_status=unverified`，终验 EVIDENCE_INVALID 降 warning | standard_01~04、official_01/06/08 由 0 救回（基线中这些 case 实体已抽出但被证据闸清零） |
| `KG_EXTRACT_PUBLISH_BEST_EFFORT=1`（Backend 默认） | verification 未过发布 best-effort 图 + `quality.status=partial` + `graph_publishable=false` | 上述 7 case 从"发布 0 节点"变为带出质量标记的部分图，门禁空抽取归零 |
| `KG_EXTRACT_MAX_REPAIR_ROUNDS=2`（默认）+ 仅 repairable 类型进修复 | 修复循环收敛；v3 无法真实执行的关系类修复不再空转 | standard_03 extract 8m16s → 2m39s |
| `KG_EXTRACT_LLM_MAX_ATTEMPTS=3` | 实体/关系批重试恢复（基线实为 1 次） | standard_04 抽出 345 实体（基线 0），重试兜住了 MaaS 间歇性 schema 抖动 |

回退开关：证据闸设 `KG_EXTRACT_EVIDENCE_ADMISSION=reject`、发布侧设 `KG_EXTRACT_PUBLISH_BEST_EFFORT=0` 即恢复旧行为。

## 8. 遗留问题与下一步（按优先级）

1. **official 公文组抽取质量**（v3+P0 0.143 / v2 0.156，均远低于 0.5）：历史弱项，与 P0 无关，建议作为下一个专项（ prompt 抑制过度、表单字段实体策略）。
2. **关系抽取整体弱**（0.180）：official 组关系接近 0；P1 清单：关系核验门 fail-open、身份隔离 warn 化、基数超限只告警（详见 `9d44bcb` 提交说明与知识抽取算法逻辑说明的 P0 小节）。
3. **高密度 chunk 的截断/重试成本**：standard_04 extract 仍 8m25s；已查明的 S 级修复：截断类失败不重试直接分段（temperature=0 下重试必然同点截断，纯白烧）、主调用前缀恢复落袋、实体分段按失败类型门控、预估密度前置分段（机制与定量见调查记录，最坏单 chunk ~47 次调用放大）。
4. **judge 抖动**：DeepSeek MaaS 对 deepseek-v4-flash 间歇返回 `response_format unavailable`（三批分别降级 3/10/7 case），降级口径偏保守；建议 judge 调用加退避重试，正式判定时避开抖动窗口或固定重跑到非降级。
5. **运维缺口**：`QASYSTEM_ALERT_WEBHOOK` 未在 88 `.env` 配置（巡检告警不生效）；`deploy/runtime` 交付快照未同步本次修复；AGENTS.md 提及的 `docs/质量管理/` 目录在当前布局不存在（本报告归入 `docs/算法/`）。
