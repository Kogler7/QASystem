# 抽取中间记录与统一切片

本轮改动覆盖 v2/v3 的逐次结构化生成记录，以及 v3 的恢复切片和证据校验拆批。`latest`、`v3.1` 的算法实现不映射为 v3；不能据此声称它们已接入相同的逐次生成记录。

## 定位一次抽取

Backend 请求使用供应商配置创建 LLM 时，会创建独立 `trace_id`，在返回结果的 `quality.trace_id` 中提供该编号。日志也会打印 `trace_id`、`call_id`、阶段、chunk 和尝试编号。外层整篇重抽会得到新的 trace_id，不会覆盖旧轮次。

根目录由 `KG_EXTRACT_TRACE_DIR` 配置，默认 `tmp/extraction-traces`，空值关闭。相对路径基于 Backend 的工作目录；标准 Compose 中对应 `/app/backend/tmp/extraction-traces`，位于可写的 backend-tmp 卷，不写入只读源码挂载。按 UTC 日期及 trace_id 分目录：

```text
tmp/extraction-traces/YYYYMMDD/<trace_id>/
  manifest.json                 # 供应商、版本、模型和预算白名单
  input.json                    # request_id、本体、输入切片及来源范围
  000001-call.json              # 调用前的消息、schema、阶段、子片编号
  000001-call-response.json     # 完整模型文本、JSON 解码结果、用量及结束原因
  000002-http.json              # 队列等待、SDK 调用耗时和错误类型
  000003-parsed.json            # 通过生成层格式校验的候选（并非最终采纳事实）
  ...-validation.json           # 格式校验失败、截断与恢复候选
  ...-text-split.json            # 文本拆分区间、策略、重叠和深度
  ...-batch-split.json           # 任务批次父子编号、条目数量与原因
  ...-relation-split.json        # v3 关系批次拆分
  result.json                   # 未压缩的最终算法结果、候选采纳及校验追踪
  failure.json                  # 算法异常类型（异常退出时）
```

序号按事件实际发生顺序生成，示例中的文件名仅示意。子片范围相对于当前被拆的片段；调用中的文本和 parent 标识用于递归追溯。嵌套实体子片 metadata 的 `entity_segment_start/end` 则累计为原始 chunk 内偏移。

调用前先保存输入，进程异常时可通过缺少对应 response 文件识别未完成调用。每次 SDK fallback 也会记录独立 http 事件，关联同一 call_id。`http_seconds` 包含 SDK 内部工作，不等同于服务端推理时间；在入队前被输入预算拒绝的调用没有网络耗时。最终结果只有算法返回后才存在，不能把已保存候选当成功。

不保存 SDK、认证对象或 headers；配置采用白名单，结构化敏感字段、Bearer 文本和当前供应商密钥会脱敏。记录仍包含文档原文及模型输出，需要按业务数据管理访问权限与保留周期。当前不自动清理，管理员应配置卷容量和归档策略；日志写盘失败只报警，不改变抽取结果。

## 评测轮次归档

`eval/run.py` 在每轮完成（包括失败或异常）后，把用例当前 JSON 产物复制到 `attempts/01/`、`02/`、`03/`，并保存 `attempt.json`。已有目录则追加时间戳，防止再次运行覆盖。用例根目录仍保留最近一次产物，兼容现有评分工具。旧轮次文件表示该轮结束时的快照；异常早退可能包含沿用的缓存文件，必须结合 attempt.json 和日志判断是否产生了新抽取。

## 统一恢复切片

v3 首次恢复分段和递归缩小均使用上游 `split_by_characters`，统一分隔符边界、overlap 和 `__source_range` 定位契约，替代算法内部独立的换行二分实现。它与上游 chunk_type=1 使用同一个切片器；不改变用户选择的其他上游算法，也不引入 embedding 调用。

v3 恢复 overlap 默认调整为 50 字符，可用 `KG_EXTRACT_ENTITY_SEGMENT_OVERLAP` 覆盖。它仍是服务端恢复配置，不会自动读取一次上游请求的 overlap 参数。目标大小仍由恢复参数控制，递归时逐步收紧；不是精确 tokenizer 或信息密度预测。保留小尾片，不因“片段太短”直接丢弃原文。

先保护完整 JSON；若 JSON 单块超出恢复尺寸，则使用同一切片器按原始文本分隔符拆分，最后才硬切长行。此时不保证每个子片都是合法 JSON，但不重新序列化原文，来源偏移仍可追溯。

修复了上游分隔符切片器打包时未更新范围结束位置的问题；chunk_document_items 优先读取并验证来源范围，避免重复内容加 overlap 时回退匹配到错误位置。

关系、属性、修复处理的是任务列表，继续使用条目拆批；v3 证据校验也接入同一 generate_batched，输入超限或截断后重新构建子批提示词。单个核验项或公共上下文本身超预算时仍明确失败，不把缺少判定当作通过。单实体多属性尚未细拆到字段级。
