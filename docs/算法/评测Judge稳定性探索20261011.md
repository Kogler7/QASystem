# Judge 稳定性探索（2026-10-11）

## 结论与适用范围

这轮小实验显示，**直接缩小 API 窗口并不能保证更正确；单对 Clef 在诊断题上比原批量 Clef 更可信，值得用于疑难补判，尚不足以直接替换全量默认 judge。** API 的选择题协议也没有天然优于找边协议。重复一致只是稳定性，不是正确性。

全部只复用冻结预测与 golden，没有重跑抽取、审阅原文或修改评分实现。标签是 agent 审阅的 provisional 标签，不是人类 ground truth。不能据此断言抽取模型产生了幻觉，也不能把提高 F1 当优化目标。

## 数据与控制变量

- 冻结集：`test_data/judge_exploration/diagnostic-v1.json`，24 题，初始 10 正例、12 难负例、2 粒度争议；对应 official_01、trouble_mini、rule_01。
- 完整保留各样本实体/关系数组和属性。API 大窗按真实全数组的 40 golden × 20 predicted 网格选择所在窗口，**没有用少量题填充冒充大窗口**；小窗为同数组上的 4×4。只调用覆盖诊断题的窗口，不扫描其他窗口。
- 三次重复、并发 2，官方 DeepSeek `deepseek-flash`，temperature=0、关闭 thinking；最大输出固定 4096。原矩阵最大输出为 8192，本实验不是整套配置的精确重放；全部实际 finish_reason=stop，无输出长度失败，输出限制未成为本轮可见瓶颈。
- 单对找边与单对选择题使用相同的完整 pair 及其两侧端点属性。API/Clef 单对选择题使用完全相同的 state、question 和 yes/no criteria；API 多一个要求返回 answers JSON 的协议说明。这个比较隔离了题目和上下文，HTTP/输出协议仍不同。
- 大窗/小窗/单对改变了周边条目和端点表，因此是**实际方案对照**。单对找边/单对 API 选择题隔离任务协议；单对 API/Clef 选择题是**同题模型对照**。没有比较“局部 pair + 整个原窗端点表”的额外上下文变体。
- 运行于既有 `qasystem_backend`，沿用容器服务 Clef；凭据只从环境读取，不进入数据或结果。

## 实际调用与结果

实际 303 次调用：231 次 API、72 次 Clef。总墙钟 **112.735 秒**。所有调用 HTTP 200、有效解析且答案覆盖完整；API 231 次均 stop，Clef 服务未提供 token usage/finish_reason，不能视为零消耗。下表是候选边判定，**不是最大匹配后的端到端 F1**。

|---|---:|---:|---:|---:|---:|---:|---:|
|API 原规模 40×20 找边|27|23|36|23/24|21.954|0.813|273,990 / 1,773|
|API 4×4 找边|60|21|36|24/24|42.013|0.700|147,384 / 748|

累计耗时是各请求耗时相加，包含并发，不能称条件墙钟；全部条件一起实测墙钟为 112.735 秒。API 输入合计 600,084 token、输出 4,385 token，大量输入缓存命中。Clef 单对延迟略高于 API 单对，不能与 API 一窗多对的吞吐直接排名。

补判 union 是人为选中诊断题集合的上限实验，**不是已实现的生产触发器**，也没有测触发候选召回。它只增加接受边，可能扩大误接受，本集难负例未发生此问题不代表其他数据安全。

## 标签复核与敏感性分析

初始 q01 把“同名通知”标为正例，但进一步看属性，两侧来文单位、密级、联系电话、领导批示不同。当前契约同时强调“同一对象”和“共同属性不得互相排斥”，不同联系电话/批示可能是多个值，也可能是误填；只凭两张图谱无法裁定。**API 单对选择题三次拒绝可能有依据，不能简单视为 API 错误；Clef 三次接受也不是属性质量合格。**

冻结 v1 标签没有事后修改。结果同时保存排除 q01 的敏感性口径：剩余 9 provisional 正例 ×3=27 次，难负例仍 36 次。

|条件|排除 q01 后正例接受/27|难负例拒绝/36|
|---|---:|---:|
|API 40×20|20|36|
|API 4×4|18|36|
|API 1×1 找边|22|36|
|API 1×1 yes/no|21|36|
|Clef 1×1|27|36|
|原 API + 聚焦 union|24|36|

即使 Clef 在这些 provisional 题上全一致，也不能称其“100% 准确”。q03 泛称对象、q04 报送交互、q11 反馈表关系仍需要专家明确指代/属性政策。原抽查报告中“同名通知匹配支持”应据上述属性争议收窄，不能忽略属性。

## 关键题逐次结果

1=接受，0=拒绝；题目 ID 可在冻结集找到完整条目、全局索引及理由。

|题目|API 40×20|API 4×4|API 1×1 找边|API 1×1 选择|Clef 1×1|
|---|---|---|---|---|---|
|q03：OpenClaw 等开源智能体 ↔ 开源智能体|111|000|100|111|111|
|q04：报送排查反馈 ↔ 填表审核后报集团|101|000|111|000|111|
|q05：专项排查 ↔ 修订制度（负例）|000|000|000|000|000|
|q10：同一文档 CONCERNS_OBJECT 对象别名|000|111|111|111|111|
|q11：报送反馈 USES_INFORMATION 反馈表别名|000|000|000|000|111|
|q12：专项排查 ACTS_ON ↔ 研讨规范 ACTS_ON（负例）|000|000|000|000|000|
|q13：落实隔离 EVIDENCED_BY ↔ 研讨规范 EVIDENCED_BY（负例）|000|000|000|000|000|
|q15：更换 EM231 ACTS_ON EM231 的别名|111|111|111|111|111|

- q10 是最清楚的窗口敏感候选：原窗 3/3 不输出，小窗、单对全部接受，实体身份此前也被接受。可疑 API 漏判在这一题稳定复现。
- q15 在原全量评测未匹配，但本轮所有方案全部接受：**之前的漏判没有稳定复现**，不能宣称其根源仅是大窗。不同上下文负载、模型非确定性和当时输出均可能影响，需要保留原调用而非用复评覆盖历史。
- q03、q04 证明小窗可以稳定地拒绝 provisional 正例；1×1 找边和同上下文选择题又不同。减少信息量不是万能修复。
- Clef 之前批量评分误接受 q05、q12、q13，现在单对均拒绝。这是值得追查的协议/窗口敏感性，但本轮没有对 Clef 4×4 再重复三次，不能把全部改善因果归于单一因素。
- q23/q24 是一个预测规则包含两条 golden 原子规则的粒度题；Clef 单对都接受，最大一对一仍最多计 1 TP。这不能靠换 judge 解决，亦不纳入正负正确率。

## 端到端指标与工程状态

原完整五样本 API 基线：实体 micro F1 **42.22%**、关系 **5.76%**；执行成功 **1/5**、部分/失败 **4/5**，有效判分覆盖 **5/5**，总 gate=false。这次诊断实验没有重新扫描全部候选图，因此其他条件的全样本实体/关系 F1 **未测**，不能从 24 题的接受率推算。模型预测完全相同，抽取执行成功率也没有改善。

全部 303 次诊断调用成功、答案有效覆盖 100%，但 API 不输出接受边仍被当成正常拒绝，不是传输失败。格式正确和覆盖完整不等于语义正确。

## 可实施建议（尚未修改生产）

1. **暂保留 API 40×20 主扫描**，不要把默认改成 4×4，也不要把 API 全改为逐对选择题：本集没有支持这两种更正确，调用数却增加。始终保留原始候选边和窗口诊断。
2. 优先试 **Clef 1×1 疑难补判**，触发包括：两端已有可信实体别名候选但同签名同方向关系没有匹配；身份归一化相同但属性有冲突；API/Clef 分歧；组合/短标签端点。保留每侧完整端点属性，不拼接不同实体候选。生产触发器召回和误接受尚未验证，先以 shadow 诊断运行。
3. 不盲目把补判 yes 与主结果 OR 合并。先执行类型/方向硬约束，加入同组件近似名、相关活动不等价、父机构/子机构和段落/全文等难负例回归；争议属性或一对多粒度进入明确的“待审”状态。三次一致只能提高稳定性证据，不能代替正确性校准。
4. 将“实体身份 F1”与“属性完整/正确率”“schema 合法率”“冗余率”“端点映射一致关系”分开；主身份分不能既宽松接受缺字段，又被当成完整抽取质量。属性键中英文映射应有本体合同，不能依赖 judge 猜测。
5. API 无效 JSON、越界索引、缺失回答、length、HTTP 错误应标为 judge_failed/unscored，并保留已有抽取，不静默回退到身份分。Clef 的输入超限可以完整拆窗；单对仍超限明确失败，不能删属性后假装同题。
6. 先补人类复核 q01/q03/q04/q11 和原子/组合规则政策，再在独立集重复；随后复用完整五样本跑 shortlist 的全量判分，比较 F1、成功率、覆盖、分歧和成本，不能仅以 F1 上升选方案。
