# 评测 Judge 根因与修复探索（2026-10-11）

本报告由 agent 审阅 prediction 与 golden，并执行真实 Judge 请求；不访问原文，不修改 golden，不构成人类 ground truth。所有正负标签是 provisional；属性政策争议不计绝对正确率。完整五图评分采用原冻结 DeepSeek/v3 预测，不重跑抽取；新 JSON 规则结果仅作离线边界检查。没有变更生产默认 Judge。

## 结论与适用范围

Clef 4×4 的部分误接受与题目索引、周边条目绑定有关，不能仅归因于题目数量：同一批条目、同一属性与判定规则，仅移动目标位置便改变回答；将全部问题改为一题仍未消除这些错误。单题独立上下文改善了已知反例，但不是完整正确性保证。建议先采用隔离的 **1×1 yes/no + 标量冲突诊断 + 关系端点一致性约束**作为 shadow 方案，并保存原始与约束后结果，暂不推广批量提示词修复或 OR 补判。

完整五图共 3392 对，全部回答，覆盖没有按词法裁剪。单题原始实体 F1=41.69%、关系 F1=11.99%；约束后为 41.69%、9.11%。原 API 基线同图谱为 42.22%、5.76%。这些是不同任务协议/上下文/调用策略的**实际方案对照**，不能宣称模型公平排名，也不能通过 F1 上升认定 Judge 更准确。

## 修复候选实现及局限

`eval/judge_protocols.py` 是隔离评测模块，保留 raw，新增 guarded：

1. 共享属性键且值能严格解析为相同维度的不同标量时记冲突；仅 typed bool/number、完整日期、明确数值单位。单位可换算，100kPa 与 0.1MPa 不冲突。普通文本日期、自由字符串、裸数字字符串不硬拒，以免误把 ID/正文当标量。
2. 关系必须保持方向/类型签名，且两侧端点可唯一定位、对应实体对已经在**全部接受的实体候选边**中确认；不要求落在某一任意最大匹配。重名端点不拼接属性，记 ambiguous/unresolved 原因。
3. 两个集合各自最大匹配后打分；属性字段缺失/值差异另存诊断，不把字段完整性混进对象身份 F1。

official01 四条 raw 接受关系的 target 实体未被同一 Judge 确认：g15/p20、g33/p1 是“排查情况反馈信息/反馈表”；g61/p15、g63/p12 是“第1段或报送要求/通知正文”。trouble 两条 g7/p33、g22/p2 的 source 未确认。约束移除这六条，所有原因保存。其余关系保留，不盲目 OR 补判。

这些约束定义了**更保守的新评分契约**；可能误拒真正别名（例如实体 Judge 自己漏判），也无法发现双方一致地错判的身份、缺失属性、语义文本冲突或原文真实性。并非仅靠 gates 就证明 19 条都正确。推荐端点不一致触发 shadow 人工/同协议单题核查，必须将关系与端点一起确认、留原决定，不自动取并集；本轮未实现未经验证的 API 候选召回器。

可实施候选：Clef 1×1、2 并发、全兼容候选扫描，回答覆盖严格失败；保留 raw/guarded 和属性诊断。高成本全扫用于小集审计，大集先使用已有 API 协议作对照，不能以词法缩候选冒充等价全量。在独立人工标签、规则粒度政策确定之前，不切换现有全局默认。
