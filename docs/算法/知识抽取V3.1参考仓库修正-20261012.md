## 修正内容

| 原问题 | 修正后的行为 | 主要代码 |
| --- | --- | --- |
| 人名、属性值同现即视为属性成立，例如“张三出生北京，在上海工作”可能接受出生地上海 | 新值必须有可定位引文，且独立核验明确返回 yes；否定、歧义或失败移除新值。可复用同次运行未改值的有效收据 | `property_grounding.py` |
| 核验为少量属性重复输入整篇长文，易耗尽预算 | 按引文生成前后各 200 字的来源上下文，最多 12 项成批并按消息预算拆分；单项过大明确失败 | `property_grounding.py` |
| 相同属性在多个来源出现，后一个收据覆盖前一个 | 同值来源合并；属性改值不自动继承旧值收据 | `property_enrichment.py`、`property_grounding.py` |
| 名称和引文都不在源文仍保留实体 | 输出校验触发重试；后处理拒收无来源候选。最终严格核对实体及属性的 chunk、坐标、引文与 span ID | `output_contracts.py`、`candidate_generation.py`、`verification.py` |
| 自定义 JSON 校验可接受 NaN/Infinity，忽略部分大小上限 | 拒绝非有限数，执行声明的 maxItems/maxLength | `structured_output.py` |
| target_types 生成器被重复消费，调用方修改切片会影响后续证据 | 目标类型物化一次，输入切片深拷贝；输出记录 chunk ID 及内容/元数据摘要 | `split_extractor.py` |
| 修复只取前 3 片、前 24 个问题；无进展仍写 validation_complete | 遍历全部相关片段，问题不静默截断；无进展、最大轮数、缺上下文和最终硬错误有独立原因 | `split_extractor.py` |
| 覆盖缺口与硬校验结果混在一起；评分标签固定 accepted | 增加 coverage_complete，保留 valid 的硬错误语义；映射对象使用真实评分状态。硬错误不能报告成功 | `verification.py`、`split_extractor.py` |
| 冲突属性未解决却正常结束 | 记录 PROPERTY_CONFLICT_UNRESOLVED，严格模式失败，best_effort 保留部分事实并报告 partial | `property_enrichment.py` |
| 调度等待和退避可超出文档时限，拿到名额后仍发请求 | 并发、速率等待与退避受同一 deadline 约束，入槽后再次检查，过期不再递归拆分/调用 | `scheduler.py`、`request_budget.py`、`candidate_generation.py` |
| 提供方异常可能将请求头/请求体带到日志和结果 | 仅输出经过分类的错误消息，仍保留超时、上下文超限等重试判断 | `candidate_generation.py` |
| 属性核验失败可能让 Backend 丢弃已经提取的实体；输入预算错误未纳入失败切片 | 属性核验作为非致命实体阶段保留事实与 partial 诊断；实体输入预算错误按失败切片归因 | `backend/app/services/knowledge_extract_adapter.py` |

`run_trace.stop_reason` 保留整体执行结果语义，失败情况下可能为 `best_effort_partial` 或 `required_pass_failed`；新增 `run_trace.repair_stop_reason` 与 `profile.repair_stop_reason` 记录具体修复原因。覆盖完整性是程序检查到的缺口状态，不证明真实召回率。来源摘要用于核对本次输入，不宣称完全冻结环境配置或保证模型可重复。
