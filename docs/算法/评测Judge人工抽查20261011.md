# 评测 Judge 的 agent 人工式抽查（2026-10-11）

本报告由独立 subagent 审阅，**不是独立人类标注或新的 ground truth**。按用户最终要求，只比较冻结的 golden、最终抽取图谱和判分明细；没有审阅原文，因此不能判定源文事实支持、golden 是否遗漏或 FP 是否幻觉。以下“接受/拒绝”是按照当前评分契约提出的审阅意见，不替代业务专家裁定。

## 结论

当前指标可以描述“相对于这份 golden 的类型与身份覆盖、冗余”，但不能单独代表抽取质量。已经发现 API 的疑似漏判、Clef 的明显过宽匹配、golden/预测的粒度差异和属性评分盲区。两种 judge 均不能作为真值。**暂不建议用本轮 F1 排名作模型选型或默认 judge 的依据。**

## 实际评分实现与含义

审阅的是随运行保存的 `kit/eval/run.py` 及本地相应实现，而非推断 API 调用数量。

1. 按样本最终图谱评分，不逐片评分。节点/关系归一化后分别建立候选边；最终在全局求一对一最大基数匹配，避免逐窗贪心抢占造成 FN。相同名不保证同身份，关系用两侧各自端点属性辅助判断。
2. 本地 `type/name` 或关系五元组一致、同名非空属性无冲突时自动接受。自动匹配饱和较小侧就跳过 judge；计数已达到这种口径的最大值，但自动规则自身有误时不会再被 judge 检查。缺失属性兼容不是属性质量认证。
3. 未饱和时 API 全组合 40 golden × 20 predicted 分窗；Clef 默认 4×4 分类每个候选对，超长进一步完整拆窗。类型签名最终由程序剔除跨类型候选，属性语义冲突和端点同一性主要交给模型。**完整覆盖只说明候选出现过，不保证 API 找出了所有接受边。**
4. 聚焦补判仅覆盖归一化身份一致但属性/上下文冲突的候选；03、06、18 这类别名关系不一定触发补判。这可以解释为何大窗漏判仍会保留，尚未做小窗 API 复判实验，不能声称已证明大窗是唯一原因。
5. 顶层 evidence 不评分；属性完整率、必需字段合法性、单位精度和证据真实性均非主 F1。simple 中 golden 英文字段/预测中文字段大部分不重名，自动规则不进行字段翻译；即便同名实体缺少所有属性，也可能计 TP。
6. 关系评分不受选定实体一对一映射的硬约束；`aligned_relations` 只是诊断。这有利于别名关系独立判定，但上表 07/08 显示关系主体语义可以被错配。简单把它改成硬约束也会把实体误判传播给关系，须保留两套诊断并审定政策。

## 计数、失败与指标展示

API 的整数汇总一致：实体 80 TP / 56 FP / 163 FN，golden 243、预测 136；关系 12 / 47 / 346，golden 358、预测 59。micro F1 为 42.22% / 5.76%，算术没有发现错误。

- **成功执行 1/5，4/5 为 partial/failed，有效判分覆盖 5/5。** `quality.score_scope=conditional_on_valid_scores`，不代表端到端通过；总 gate 为 false。局部 quality gate 的 true（阈值 0）不能拿来宣称质量合格。
- case macro：实体 F1 39.47%；关系 F1 4.94%，只含 3 个有关系任务的样本，rule/simple 的 golden 与预测均为零关系，标为不适用而非完美或零分。这是合理的空任务处理，报告应显示分母。
- simple 的 golden 关系为 0、最终预测也为 0，关系不适用；不能用它判断关系抽取成功。修复中间关系被清空的生产失败仍必须显示。
- 字段 `accuracy` 实际与 Jaccard 相同（TP/(TP+FP+FN)），没有 true negatives，**不是常规二分类 accuracy**。应标注“集合 Jaccard”，避免用户误读。
- 231/358 条 golden 关系来自两个 official；整体关系 micro 很受这两类失败影响。micro 与按组/按 case macro 应同时显示，不能从整体低 F1 推断每类都差。

## 建议优先级

1. 冻结上表争议对作为 judge 回归样例，补专家复核；先让 API 在同上下文小窗/逐对复判 06、18，并让 Clef 复判 04、07、08。验证后再确认修复，不能用“多数 judge 投票”当真值。
2. 把主指标命名为“相对 golden 的实体/关系身份匹配 F1”，并同时列成功率、部分结果率、判分覆盖、schema 合法率、属性覆盖、冗余率、端点对齐关系诊断。当前 F1 不负责检测事实来源。
3. 单独定义集合粒度契约：原子规则/组合规则、单件/组合维修方法、段落/全文 DocumentUnit、泛称/具体对象是否允许包含匹配。未确定前报告为“粒度争议”，不盲目改最大匹配成多对一提高分数。
4. 扩展聚焦复核至别名端点关系矛盾与模型分歧对，并控制预算；候选筛选如果加入，先测候选召回，不能用筛选遗漏换取速度。
5. API 和 JEV 的能力实验改为相同候选对与上下文；现有 40×20 找边 vs 4×4 分类仅可称“判分方案对照”。不宜直接归因于模型速度或准确率。

本次没有修改评分规则、生产抽取或 golden，仅增加只读工作表工具和对应测试（2 项通过）。
