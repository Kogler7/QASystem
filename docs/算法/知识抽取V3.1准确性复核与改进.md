## 实际发现

1. **已接受关系在修复时丢失。** 新 simple 基线里，目标 Problem → 需要方案 → Solution 已被主 LLM 接受。三个已接受关系任务的端点 ID、类型、名称、属性与最终对象完全一致，却被全量标记 `superseded`。随后主调用预算 14/14 用尽，重扫未完成，最终为 0 关系。不是模型从未发现目标关系。
2. **陈旧关系可以错误复活。** 两片段隔离复现：修复把源实体改成不满足关系签名的新类型后，另片修复仍引用旧任务，可能把已失效关系重新加入并报告成功。应同时修复失效范围和旧任务重新接受的边界。
3. **身份信息被隐藏。** 实体发现目录只保留 `@identity` 属性。没有该声明但原文明示的业务标识，即使已由模型选为语义上下文，也被删掉。simple 中相同业务 ID 的显示名与对象符号分别成为节点。
4. **类型改判后使用旧身份。** 从无身份声明类型改为有 `@identity code` 类型，旧代码只换类型前缀，没有按最终类型重算身份。同一 code 可生成两个节点。
5. **跨片记录缺上下文。** simple 的一个术语标题位于前片末尾，定义位于后片开头；初次发现只看当前片，容易形成两个对象。邻片需要提供原文并保持主片段与文档边界。
6. **程序拒绝合法映射属性。** `Map<…>` 被 `typed()` 当未知标量，拒绝模型返回的 JSON 对象，制造补全和修复任务。
7. **未声明关系污染生成。** 历史 simple 的 37 条无效关系中，36 条使用未正式声明的关系名，包括本体注释里的未来/后处理关系。原始本体有解释价值，但需要同时提供正式声明的闭集。
8. **延期属性支持绕过冲突处理。** 初次未决属性在修复中被支持后直接覆盖当前已接受值。应复用类型、身份与冲突提交路径。
9. **未知条件引用可触发 KeyError。** `unconditional` 配未知 condition ID 时没有完整验证。应明确保留协议问题，不能整篇崩溃。
10. **预算与缓存边界。** 提示构造和响应消费未完整计入绝对 deadline；Clef 相同共享 state 下的不同任务投影可能共用缓存答案。已用无模型的确定性测试复现。

V2 的可借鉴部分是编译签名、全局对象池和缺口驱动修复。其在线路径是 `__init__ → harness_extractor → split_extractor`；某些策略文件或 probe helper 并不位于这条在线路径。也确认 V2 有不宜照搬的行为：属性 quote 逐字命中可绕过语义支持核验；给对象 A 填入对象 B 的数值，引用 B 的原句，离线复现仍被接受。代码证据与复现保存在 `tmp/eval/v3_3/review-candidate/v2_offline_reproductions.json`。

## 本轮实现原则

相关自动化测试：第一轮 919 项通过；第二轮集成后 **1007 项通过（3.78 秒）**，覆盖 V2、V3.2、V3.3、Backend 适配、Clef 和评测器。日志 `tmp/eval/v3_3/review-round2/related-tests.log`。这不是全仓库单测或发布门禁通过的声明。

代码管理正式 schema、JSON 形状、稳定引用、来源区间、任务依赖及预算；LLM / Clef 判断类型含义、独立对象、身份等价和事实支持。没有新增业务黑名单、关键词筛选、按 golden 数量截断或评分宽松规则。

生成时加入正式 `schema_context`，列出每个关系签名及类型兼容的端点 ID；不做笛卡尔积枚举，也不把类型兼容当关系成立。Prompt 区分对象、属性、引用和解释性提及，保留显式身份上下文，处理跨片完整记录。关系的 `fact` 是待核验命题，原文 `evidence` 才是依据。

修复仅使语义依赖已变化的关系任务失效；新增端点仍会触发必要搜索。延期结果重新验证当前类型、身份与引用，不允许过期任务恢复旧事实。这里按模型判断时实际见过的端点属性快照保守判依赖，不用字段名猜测业务影响。

第二轮继续采用以下通用机制：

- **无损来源引用。** 原文按完整行提供稳定 `span_id`，模型只返回行 ID，程序从原始 chunk 还原 quote、字符位置和来源。多行事实引用多个 ID，不拼接成伪造的连续引文；空格、换行、数字和否定保持原样。旧 quote 输入兼容，公开输出结构不变。
- **精确复用已完成审核。** 复用键包含完整命题、原始定位证据、选项、schema、本体、anchor 和文档；LLM 裁决还要求实际读取的来源内容一致。不同属性、条件、证据、上下文和过期任务不能共用结论；同批未决任务不互相借用答案。轨迹保留 `reused_from`，不伪造新模型调用。
- **先复核已有关系。** 普通属性变更不再无条件重复补属性，而是用完整当前端点及条件快照、原事实和原证据重新审核受影响关系。只有新支持结论才能恢复；未决保持 partial。每轮最多一次专用 resolve，仍计入 `6 × 非空 chunk 数 + 2` 的原总预算，随后再搜索新增关系。新增对象、类型、身份或名称变化仍触发必要属性补全。
- **语义映射与来源边界。** 不要求原文使用本体类名、正式逻辑语法或编号才承认对象；同时逐条核实关系谓词与作用域。裁决只能引用本次实际读过的来源，拒绝未读片段或其他文档的引文。重复的已接受属性值不再消耗审核，也不附加未经审核的新引文；JSON 类型不同仍视为变更。

剩余限制：Clef 的窗口为 2048 tokens，超长输入继续有限拆分并回退主 LLM。其概率未经过本数据集校准；当前编译契约不能完整表达原本体所有自由文本类/关系说明，主 LLM 仍读取完整本体。独立的全局语义身份审计、完整 schema 语义卡片和以关系抽取为目标的全流程重排尚未实现；不应把它们写成已验证收益。
