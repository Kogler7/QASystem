## 2. 评测口径

### 2.1 受测版本算法说明

本次测试版本为 **v2.1**。v2.1 是在 V2 流水线之上拉出的独立副本：**抽取主链路（候选生成、候选选择、切片抽取、属性补全、图谱组装、本体解析与编译、LLM 客户端）与 V2 保持一致**，更新点集中在**规则类文档的识别路由**与**规则抽取提示词**，并已接入请求与评测链路。

**算法链路**

输入为「文档 + 领域本体（PlantUML）」，输出与本体对齐的实体、属性与关系（每条带原文证据）。链路与 V2 一致，共 6 步：

| 步骤              | 做什么                                                                                                                     |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 1. 解析与切片     | 文档解析为 Markdown，按标题/段落/表格结构切分为带原文范围的 chunk（表格保持完整，不跨片切断）                              |
| 2. 文档路由       | 按本体词表与 chunk 内容判定文档类型（公文`official_document` / 标准 `standard` / 规则 `rule`），选用对应的提示词扩展 |
| 3. 实体与属性抽取 | 逐 chunk 抽取候选实体，`type` 取本体 stereotype、`name` 取原文 mention，并补全本体声明的属性                           |
| 4. 候选筛选       | 按证据充分性与「高密度同类枚举」等护栏淘汰不合格候选，抑制表格逐行建实体                                                   |
| 5. 关系抽取       | 在候选集合上抽取本体声明的关系，并做层级、复合条件、标准语义等后处理归并                                                   |
| 6. 图谱组装与核验 | 跨 chunk 合并去重，按本体做覆盖率与一致性核验，输出最终图谱 JSON                                                           |

### 2.2 指标定义

实体与关系分别统计；`P = TP/(TP+FP)`、`R = TP/(TP+FN)`、`F1 = 2PR/(P+R)`。
批次报告分两层：**分类型（按数据集目录）**、**单个文件（每个 case）**。
