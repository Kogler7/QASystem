## 新规则 0TP 的补充边界

API 对 rule01 为 0TP，Clef 单题为 5TP：电源板异常、RTU重启恢复、CPU850/屏蔽门、RM降级无法动车、对标超范围/屏蔽门对应条目。此前报告已列 g0/p7、g2/p2、g18/p5 的身份与逻辑字段差异。这说明部分主题/规则内容保留在属性中，可以得到不同身份判定；不意味着 5 个预测都符合完整条件→结果契约。

例如电源板规则的完整 RuleName/RuleTemplate 有结果，但 consequent 缺失；RTU 把执行重启动作放在结果侧；屏蔽门规则有组合原因/扩展结果。必须区分对象身份、完整逻辑等价、部分内容覆盖与属性必填完整性。当前 raw/guarded 主要审对象身份及硬冲突，未补齐逻辑属性校验，因此不能通过 Clef 增加 5TP 就关闭规则抽取问题。

## 建议与限制

新图谱再次支持保留独立的 raw/guarded 与属性诊断：它能曝光“关系通过但证据单元不等价”的矛盾，同时避免把更高 F1 当正确性保证。单题本身仍有漏判，guard 的实体确认也可能漏别名，不能自动 OR 合并 API/Clef。

暂时不切换生产默认。先明确 RuleType 完整逻辑、DocumentUnit 粒度和属性冲突政策，在独立人类标签上验证，再考虑 API 原批量与单题 shadow 的补判触发。少量审阅揭示双向问题，尚无可支持总体精度结论的标签规模。本报告完成当前一组五图；主矩阵其他切片/4B 图不在本次 Judge 对照范围内。
