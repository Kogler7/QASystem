# 知识抽取 V3.1：统一消息、Skill 装配与文档路由

更新于 2026-10-14。当前代码为 `knowledge-extract-v3.1-all-entity-admission-v35`，保留请求级 Skill 选择、逐行恢复与独立核验，新增完整表格行识别、歧义引文隔离与同实体属性组合核验。v33 增加编号完整 token 边界检查，避免把完整文号的前缀误当属性值；不同完整编号之间的冲突仍如实保留。v34 补充检修表格名称、编号、位置与缺值的语义边界。当前 Skill 为 official_document@12、rule@8、trouble@8。公文规则基于工作区原有 @9 补充签阅姓名、表单标题的准入边界；`KG_EXTRACT_V31_ENTITY_VERIFICATION_BATCH_SIZE` 可单独限制实体准入核验批次，默认仍沿用通用批次。v3.1 只抽取实体与属性，关系固定为空。历史真实模型样例不能作为当前准确率、耗时或发布证明。

## 1. 发给 LLM 的消息

所有阶段固定发送两条消息：

```text
system = 阶段职责与公共资料边界
user   = 应用生成的 JSON 对象
```

实体抽取、属性补全、实体修复使用公共抽取 System 加各自阶段约束；证据核验使用独立核验 System。正式入口先增加一次请求级 `skill_selection` 调用，从技能目录描述、调用方本体和原文样本选择精确技能版本；后续阶段复用固定选择。显式 skill_refs 绑定时省略选择调用，不构造 assistant/tool 历史。

User 字段按下表顺序序列化。重试追加 `retry_feedback`；原文、规则、本体和 System 不变。补全/核验重试将目标输入及 Schema 同时收窄到缺失集合，最终按原始完整集合验收。字段顺序用于维护与检查，未证明优于其他顺序。

| 字段 | 内容与约束 |
| --- | --- |
| `task` | `operation` 与 `discipline` 定义本轮操作及允许范围；按阶段附带精简后的补全目标、核验候选或修复问题。候选不是新证据，校验反馈另放 retry_feedback。 |
| `domain_policy` | 适用规则正文字符串，完整规则段以两个换行连接；没有适用技能时为 `""`。 |
| `ontology` | 直接为文本字符串。抽取阶段为裁剪后的本体目录；属性核验为逐项类型、属性标识及字段说明，不再包装 `catalog` 或 `property_definitions`。 |
| `documents` | 原文字符串。单来源逐字保留，多来源用匿名标签保留片段、非连续性及文档边界；标签不作为引文。完整表格窗口保持可读语法。 |
| `output_contract` | `format`、`success_schema`、`constraints`；实体阶段另含 `empty_result`。`success_schema` 为单行结构；本地另检查完整集合及键唯一性。 |
| `retry_feedback` | 仅重试时出现的程序反馈字符串。它不能提供新事实或扩大任务范围。 |

原文通过 JSON 序列化传递；引号、换行或伪造标题不会改变外层消息结构。System 明确原文、本体注释和任务输入里的指令不是执行指令。提示词边界不能保证模型不受误导，因此最终仍执行本地 Schema、键集合、来源定位及证据核验。

实现：[prompt_templates.py](../../algorithm/knowledge_extract/v3_1/prompt_templates.py)、[prompt_router.py](../../algorithm/knowledge_extract/v3_1/prompt_router.py)、[semantic_evidence.py](../../algorithm/knowledge_extract/v3_1/semantic_evidence.py)。

## 2. 各阶段怎样衔接

| 阶段 operation | 装配的 Skill 阶段 | task 中的必要输入 | 模型输出 |
| --- | --- | --- | --- |
| `entity` | all + semantics + entity | 容量拆分续扫可携带 saved_entity_keys | JSONL：每行 `type / mention / properties / evidence`；兼容省略 properties |
| `property` | all + semantics + property | `known_entities`，精确实体键、已有属性与出现记录 | JSONL 属性变更提案，每个键恰好一次；无变更 properties={}，不要求 evidence |
| `repair` | 漏实体：entity/repair；属性：property/repair；均含 all/semantics | `repair_issues`；属性修复另含精确 known_entities/requested_properties | 漏实体输出候选，属性修复输出精确键的变更提案 |
| `evidence_verification` | 仅 all + semantics | `items`：实体名/类型或属性、值、引文，以及必要的 previous_value / conflicting_values | JSONL：每行 `item_id / supported / reason`，每个 item_id 恰好一次，supported 为 yes/no/uncertain |

所有抽取阶段不发送 `stage_context`、`document_sources` 或内部来源引用。请求仍为普通 chat 文本，不发送 `response_format`。实体发现/漏实体修复的无候选结果为单独一行 `{}`；补全/属性修复必须覆盖给定键，无变更返回空 properties。核验使用 JSONL，不使用 verdicts 包装；请求级 Skill 选择使用单个 JSON 对象。

`task.known_entities` 包含精确 type/name、已有属性、待补字段和候选属性/引文；属性修复新增 requested_properties。`task.items` 包含 item_id、type/name、可选 property/value、evidence_quotes、previous_value/conflicting_values。无 property 的项核验实体名与类型是否获支持。`task.repair_issues` 保留业务目标与待补字段，required 修复显式携带 target_name；删除 path、severity、gap_id、span_id 等内部诊断。saved_entity_keys 只用于续扫排除已有键，不是证据。

属性核验先在程序内定位引文，保留引文前后各 200 字、主体定位片段、旧值支持原文及表头。冲突项还携带全部冲突支持原文，超预算时明确失败，不静默裁掉。原文合并为 documents 字符串。chunk/document ID、章节、页码、元数据、窗口起点、坐标和 source_refs 不发给模型。字段解释进入 ontology，待核验值进入 task.items；两者均不能替代原文证据。JSON 表格、JSONL 和 Markdown 表格按完整行分窗口，表头以可回映原文的独立片段重复提供，单行超预算明确失败。

属性项也携带 `candidate_properties`：本次提案与已保留属性组成的候选上下文，用于判断前后件方向、对象、单位及阶段是否一致。它不提供事实证据，核验结果仍仅授权该项的 `property`。完整请求预算及拆分规则照常生效。调用方声明的身份属性若未允许上下文推导，其值必须出现在原文中，并继续通过独立字段语义核验；不能由日期、名称、序号拼造标识。

工作表标题后的 JSONL 开启围栏可以在后续 chunk 才闭合：当前 chunk 内的完整行保持行边界与原始坐标；不补闭合字符或丢弃损坏原文。相同短引文在不同表格行出现时，以整行检查主体歧义，不能因短句一致借用另一行证据。

核验的 `item_id.enum` 从本轮待核验集合生成并出现在单行 Schema 中；本地再检查集合大小、ID 集合和唯一性。缺项、重复项或新增 ID 都进入有界重试。仅完整且独立校验通过的 yes 接受新属性，no/uncertain/缺失项不接收新值。截断不抹掉其他完整有效的核验行。

逐行恢复：损坏行、截断尾行、未知类型/属性及无来源候选不接收，其他完整有效行保留。实体候选恢复后仍经过属性语义核验，不因 JSON 合法直接发布。重试成功按完整契约返回；重试耗尽保留已验证事实并报告 partial/failed，不能把截断当完整成功。已有有效记录时不让后续空输出覆盖；同一次响应的重复核验 ID 不选择其中的 yes。恢复计数及核验缺失 ID 进入 attempts 和 run_trace。源文本超长且无可恢复记录时继续原有拆分机制。

实现：[output_contracts.py](../../algorithm/knowledge_extract/v3_1/output_contracts.py)、[property_grounding.py](../../algorithm/knowledge_extract/v3_1/property_grounding.py)。

## 3. Skill 规则的完整性与一致性

每个请求读取一次 Skill 文件快照，完成语义选择或配置绑定后编译阶段规则。选中技能在本次同领域请求的全部实体和切片间共享；候选、补全、核验和修复共用规划器，运行期间改文件不影响当前请求。

模型可见文本字段示例（规则与本体仅展示部分正文）：

```json
{
  "domain_policy": "公文领域抽取规则：重点识别文件标题、文号。",
  "ontology": "- `公文` -> type `OfficialDocument`\n  - `文件标题` -> `documentTitle` (String)",
  "documents": "关于开展设备检查的通知\n文号：设备〔2026〕1号\n设备管理部负责组织设备检查。"
}
```

三个值均为 JSON 字符串，不能写成只有文本而没有键值对的 `{正文}`。应用内部仍编译结构化规则块，发送时只连接其正文；来源索引留在程序内部。

合并依据是 `skill_id + version + section`；相同 all/semantics 段只发送一次，不对不同规则段逐行去重。`rules:semantics` 放类型粒度与字段解释，阶段操作放对应 entity/property/repair 段。候选不装配 property 操作，核验只使用 all/semantics；修复按漏实体或属性任务装配。自定义旧 Skill 应将共享语义迁入 semantics，避免把操作放进 all。当前工作区版本为 official_document@12、rule@8、trouble@8；公文 Skill 在用户已有 @9 上补充准入边界，原有内容保留，没有以历史 @11 覆盖。

## v15 共享语义与通用路径

抽取与核验 System 复用 `FACT_EVIDENCE_RULES`：逐字事实、忠实概括、本体分类映射分别判断，核对主体、对象、时点、条件、否定、数值和效果归属。核验 System 与 output_contract 复用同一判定定义：yes 要求关键主张均有支持；no 表示明确矛盾、错归属、类型/字段不符或明确新增事实；uncertain 表示缺证、指代或范围不明、冲突未解。仍只有 yes 接受。

| 范围 | 当前提示词约束 |
| --- | --- |
| 公文 | 结构、活动、交互和约束按本体允许的视角判断，不默认互斥；正文与表单按文件身份及字段归属结合；不凭附件标题补正文，不无依据修复 OCR 顺序 |
| 规则 | 保留因果方向、复合条件、否定和适用范围；仅处置不推出恢复；分类或记录序号不自动是规则身份；不同属性可合法同值 |
| 检修 | 区分动作、实验、结果、建议与实施；预防性只修饰对应动作；前后观察分别归属，不从数值猜健康状态，不因恢复措辞补独立实验 |
| sample/simple | 不新增 Skill；公共规则处理实例标签与业务名、术语同义词、引用与内嵌模板；本体及输出 schema 仍决定允许的字段与值形状 |
| 补全与修复 | 精确键、属性增量、省略不删除；不能在修复中重命名或拆分已有实体，身份错误不能靠拼接属性掩盖 |
| 重试 | 只处理剩余目标；已保存仅表示通过当前格式与局部契约检查，不等同语义支持或全文覆盖 |

选择提示词版本为 `request-skill-selection-v2`，先判断 task.allowed_types 的语义目标，原文主题辅助；多个 Skill 必须同时适用且不冲突，无适用技能返回 no_match。sample/simple 使用公共提示词，调用算法时 `skill_refs=[]` 可明确跳过选择；未加入目录名或文件名判断。显式固定旧技能 ref 的配置须随版本更新，程序不静默替换。此次没有修改 golden、身份归并算法、覆盖审计或其他抽取版本。方案与尚待解决的数据争议见[严格评审](抽取Skill与System提示词严格评审及修改方案20261013.md)。

## v14 恢复与验收

完整合法 JSONL 行先保留，再按本体、来源及证据核验决定事实准入。补全/核验只续补缺失实体键或 item_id；输入、单行 Schema 和集合计数同步改变，已采用判定不会被越界重试覆盖，同次重复键不选择其中的 yes。候选格式续补允许正常结束的 `{}` 表示无新增；供应商明确标记 length/incomplete 时不能凭空结果证明未知候选全集完整。容量不足继续拆小来源/类型范围，已核验候选不重生成，其属性扫描仍继续；预算耗尽保留事实及 partial/failed。

属性 properties 是本轮变更，省略不删除旧值；已经结合全部冲突证据核验通过的值不会被后续无变更提案删除。未解决冲突仍失败。核验区分事实并存、条件/时间差异、明确新旧替代和未解决矛盾，不强求保留已失效旧值。本体注释不截断，最小完整定义超预算则明确失败。引文多次出现且主体/条件不同，需更长的消歧引文；不默认绑定第一处。

候选准入可使用受文档/章节边界约束的短原文上下文；只从当前窗口发现候选，不从辅助片段发现新实体。匿名标签不进入原文坐标匹配，原始 chunk/range/metadata 不改写，表格表头/完整行/表尾的坐标仍指向原切片。

规则身份、版本、章节、文件 SHA-256、路由原因和加载集合保留在 `profile.prompt_assembly` 审计中，模型只接收规则正文。完整消息在现有调用追踪中记录。

本体决定允许的类型与属性，output_contract 决定本轮输出结构。Skill 只补充领域解释与粒度，不能覆盖硬约束、扩大范围或将无来源内容变成事实。核验共享领域解释，但独立判断原文支持程度。

v5 删除公共提示词中凭外部编码表补全名称的例外，所有编码/名称对应关系都要求所提供原文支持。适配器收到独立消息与 schema 副本，不能改写本地准入规则；修复范围另有程序约束，不能仅凭提示词限制扩展候选。

实现：[skill_registry.py](../../algorithm/knowledge_extract/v3_1/skill_registry.py)、[skill_planner.py](../../algorithm/knowledge_extract/v3_1/skill_planner.py)。技能格式和维护方式见 [README](../../algorithm/knowledge_extract/v3_1/README.md)。

## 4. 文档路由

旧 V2 兼容文档分类只作诊断，保留在 profile.document_route，不再决定可加载技能。正式入口将已注册技能的 name/version/description、本次完整调用方本体、目标类型和有界原文样本交给选择模型；原文从请求起、中、末等位置选取最多 8 个非空切片，长切片保留头尾样本，实际范围和是否完整采样进入审计。

选择结果为 selected、no_match 或 ambiguous，选中的标识必须带目录中存在的精确版本，不允许未知技能、路径、重复项或额外字段。generic/simple 不阻断选择，rule/trouble 可以依据本体与描述被加载。新增领域维护 Skill 即可，不修改固定领域枚举。算法入口支持 skill_refs 显式配置绑定，空列表明确只使用公共规则，不新增 HTTP 字段。

profile.skill_selection 记录最终决策；profile.prompt_assembly.mode 为 request_skill_selection，plans 保存一次请求的固定选择和规则摘要，calls/attempts 保存真实选择调用。no_match 是正常空策略；选择歧义、超时、预算超限或响应无效终止抽取，保留失败与未扫描状态。选择使用现有 LLM、调度器、文档 deadline 和输入预算，不静默截断本体或伪装成无匹配。

技能目录缺失、为空或没有匹配技能时使用空规则正文；技能文件有无效元数据、重复 ID、重复/空规则段或跨目录符号链接时显式报错，不能回退成空抽取。
