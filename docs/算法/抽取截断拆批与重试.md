# v2/v3 输出截断拆批与重试

## 行为

- `finish_reason=length` / `status=incomplete` 与网络超时分开处理。v2/v3 结构化调用层首次截断即返回不完整，不再对同一批原样尝试三次；上层有拆分机制则继续拆分，否则明确失败。网络错误沿用有限重试。
- v2/v3 属性补全按实体分批，每个子批重新生成实体 ID 枚举、属性 schema 和实体目录。初始大小依据当前模型 `max_tokens`、待补字段数估算，预留 35% 输出余量。截断后二分，已经成功的子批保留，仍走原来的证据校验与属性准入。
- v2/v3 修复按 verifier issue 分批（每批最多 4 条），不要求单次输出全部修复。v3 不再直接丢弃第 12 条以后的 issue；未处理任务由总预算与最终 verifier 明确报告。
- v2 关系候选使用相同拆批机制；v3 关系候选继续使用原生二分机制，首次截断就拆，最多 6 层、每个 chunk 最多 128 次批次生成。v3 实体阶段已有文本分段回退，现在首次截断即可进入回退。
- 通用拆批最多 6 层、63 次批次生成，每次生成内部仍有有限网络重试。当前调用观察到截断后，尚未开始的兄弟批次也采用更小大小；不使用共享可变的全局批大小，避免并行评测互相改变配置。
- 所有子调用复用原来的模型对象、配额池和文档截止时间，不重置超时，也不创建新的限流池。文档截止时间耗尽后不再启动通用拆批调用。

## 完整性与日志

拆批父任务的失败会标为被子任务接替；子任务全部成功才不再有该分支的终止失败。任何叶子仍失败、或预算耗尽，都保留 terminal 失败，成功兄弟的结果仅作为部分结果返回。截断 JSON 的前缀不作为这些批次已经完整的证明。

模型调用日志继续记录 pass、chunk/part、usage、finish_reason。新增拆分日志记录原批大小、两个子批大小与深度；调用指标保留每次实际模型请求。属性阶段汇总 `calls` 计入拆分子批。

单个实体、单个 repair issue 仍可能超过输出限制，此时明确返回不完整。当前改动没有把一个实体的长属性值或一个问题继续拆成语义片段，也没有实现跨请求的供应商吞吐学习。估算系数是保守初值，真实效果须用评测验证。

## 评测重试

同一次运行自动重试时，`partial` / `failed` 抽取产物不能充当成功缓存，需要重新调用抽取。已成功的非空抽取可以复用，因此仅裁判评分失败时不用再次抽取。切片原始字节保持不变。

显式 `--reuse-extract-from` 仍是用户指定的只读复用/重新评分，包括部分结果；不会擅自发起新抽取，也不会把部分结果标成成功。

## 验证

`tests/test_output_batching.py` 使用真实 v2/v3 结构化调用与属性阶段，模拟输出截断、瞬时超时、叶子失败、拆分预算与文档截止时间。`tests/eval/test_retry_timing_integrity.py` 验证失败抽取重新请求、成功抽取复用、切片保持不变，以及裁判异常后的复用语义。

88 上正在运行的旧代码 v2/v3 对比必须结束后才能更新 Backend，否则会污染对比基线。
