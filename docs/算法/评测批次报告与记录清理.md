# 评测批次报告与记录清理

统一评测入口 `eval/run.py` 的批次记录约定：每批次一个独立文件夹、附 benchmark 详细报告（`report.md`）、历史批次按月自动清理。用法细节见 `eval/README.md`，本文记录设计与保留策略。

## 批次目录

每批次写入 `tmp/eval/runs/<时间戳>/`（run_id 形如 `20260929-233444`，已 gitignore）：

```
20260929-233444/
├── params.yaml / params.resolved.json   # 评测参数快照
├── summary.json                         # 全量结果与门禁数据（报告的唯一数据源）
├── report.md                            # benchmark 详细报告（每批次结束自动生成）
└── <group>/<case>/
    ├── backend_extract.json / chunks.json / match_details.json / scores.json
    ├── parse_<case>.json                # 解析模块原始返回
    └── document.md                      # 解析后的整篇 markdown（保留，见下）
```

### document.md 为什么保留

评测批次**不保存源文档副本**（原始文档在 `test_data/` 数据集内，无需重复）；`document.md` 是解析产物而非源文档，且有两个真实消费点：

1. `--from-run` 跨批次复用时跳过昂贵的重新解析（`eval/run.py` chunk-extract 分支）；
2. 同批次 case 失败重试时复用，第 2/3 次尝试免重解析。

judge、报告生成、`tests/eval/` 均不读它。

## report.md 结构

每批次结束（含 `--from-run`/resume、Ctrl+C 中断分支）在批次根生成，生成逻辑为纯函数 `eval/report.py: render_report(summary)`，失败只告警不影响评测：

- **运行信息**：run_id、起止时间、总耗时、backend、阶段/模式、评分口径（含 judge 降级 identity_fallback 摘要）、抽取版本、case 计数。
- **门禁**：退出码（0 通过 / 2 有失败或空抽取 / 4 门禁未过 / 130 中断）、空抽取清单、实体 F1 阈值与实际最低值、耗时预算违规逐项（数据源为 summary 的 `gate` 块，含 `gate.budgets`）。
- **指标结论**：三层 P、R、F1，实体与关系分开。整体来自 `overall` 的 micro；分类型来自 `quality.modules.*.by_group.*.micro`（`official`、`rule`、`simple` 等）；单个文件是每个 case 的主模块分数。system/plugin 有数据时并列；有 identity 对照时附在整体下。
- **逐 case 明细**：状态、实体与关系 P/R/F1、parse/chunk/extract 各阶段耗时、总耗时、抽取版本、备注（失败原因/重试耗尽/judge 降级）。
- **问题清单**：失败 case、空抽取、judge 降级（含 judge_error 摘要）、耗时超预算、F1 低于阈值。
- **最慢 case Top 5**。

旧批次（无 `gate` 块）报告"门禁：未配置"，属预期向后兼容。

## 历史批次清理

- 每次启动 `eval/run.py`（含 `--dry-run`）在跑 case 前执行一次清理。
- 保留期配置（优先级从高到低）：CLI `--runs-retention-days` > `eval/params.yaml` 的 `runs_retention_days` > 默认 30 天；`<=0` 不清理。
- 只删 `tmp/eval/runs/` 下匹配 `^\d{8}-\d{6}$` 的目录；批次时间取目录名时间戳，非法日期回退 mtime。
- `--from-run` 引用的批次即使过期也跳过并打日志；单目录删除失败只记 error 不中断。
- 启动日志固定打印摘要：`历史批次清理：保留 30 天，删除 N 个过期批次，释放 X MB`。

## 与发布门禁的关系

`AGENTS.md` 发布质量门禁要求：改解析/切片/抽取/沉淀流水线后，以 `eval/run.py --match-mode llm --fail-on-empty ...` 的当批结果做判定并与上一基线对比。当批的 `report.md` + `summary.json` 即基线留档；月度清理只清 30 天前的批次，做基线对比时注意保留期，需要长期留存的基线请另行归档。
