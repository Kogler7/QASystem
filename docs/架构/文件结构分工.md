# 文件结构分工

本文约定仓库根目录下各一级目录的职责与边界，避免算法代码、评测数据、测试代码和运行产物混放。

## 一级目录职责

| 目录 | 职责 | 是否进入交付镜像/源码包 | 说明 |
| --- | --- | --- | --- |
| `backend/` | HTTP / MCP 服务与异步执行框架 | 是（runtime 源码包） | 只放运行时服务代码 |
| `agent/` | AgentCode 智能体运行时 | 是 | 只放运行时服务代码 |
| `algorithm/` | 算法实现 | 是 | 各算法子目录只保留算法代码与必要 README |
| `mcp_services/` | MCP Server 与工具注册 | 是 |  |
| `external_services/` | 应用团队接口适配 | 是 | 唯一出网口 |
| `tests/` | 统一单元/集成测试 | **否** | 按 `backend/`、`agent/`、`algorithm/` 组织 |
| `test_data/` | 共享测试数据集与 golden | **否** | 含 `parse/`、`eval/`、`eval-v2/` 等 |
| `eval/` | 评测编排脚本与历史评测工具 | **否** | `run.py` 为统一入口；`tools/` 放造 golden/调试脚本（旧版 legacy 脚本已清理） |
| `agentic_graphrag/` | Skill+MCP GraphRAG 实验骨架（未接入主干） | **否** | 独立 `AGENTIC_GRAPHRAG_*` 前缀，接入主干时应并入根模板 |
| `tmp/` | 运行时输出 | **否** | 评测结果、临时文件，已 gitignore |
| `docs/` | 设计/接口/部署文档 | **否** | 不参与运行时镜像 |
| `deploy/` | 构建/打包产物目录 | **否** | 由 `package-deploy.ps1` 生成 |
| `docker/` | Docker 构建与离线验收辅助 | 部分 | `verify_runtime.py` 等进入 `runtime` 包，其余不参与镜像 |
| `ofd_converter/` | OFD→PDF Java 转换器 | 构建期参与 | 镜像构建期 `mvn package` |

## 算法目录内部边界

- `algorithm/knowledge_extract/` 下按版本分 `v2/`、`v3/`、`latest/`：
  - 只放抽取算法源码（`*.py`）、版本内单元测试（`tests/`，见下文"测试目录组织"）与版本 README；
  - **不得** 放 benchmark 数据、评测脚本、golden 任务脚本、调试脚本或历史归档代码。
- `latest/` 是**实体目录**，包含完整代码副本，不是 `v3` 的软链或运行时映射。已于 2026-09-30 同步为现行 `v3`（sxm-dev 流水线）的全量副本（含单元测试，仅做包名改写）；此后 v3 的实验性改动不会自动进入 latest，需再次显式执行同样的全量复制 + 包名改写 + 全量测试验证。
- 各版本包自包含：`v2`、`v3`、`latest` 之间**无**跨版本代码引用（早期 latest 经 `..v2.llm_client` 复用的方式已随 2026-09-30 同步移除）。

## 评测数据与脚本边界

- 新 canonical 评测集：`test_data/eval/`（原始文档 + 类型/Case 级本体 + golden）。
- V2 开发评测集：`test_data/eval-v2/`（预切分 Markdown + Case 级本体 + golden）。
- 统一评测入口：`eval/run.py`，输出到 `tmp/eval/runs/<时间戳>/`。
- 评测辅助工具：
  - `eval/tools/v2_golden_task/`
  - `eval/tools/v2_scripts/`

## 输出隔离规则

- 任何脚本/评测的运行时产物必须写入 `tmp/`，按算法、版本、时间做子目录隔离。
- 不得向 `test_data/`、`algorithm/`、`backend/`、`agent/` 写入运行产物或覆盖 golden。
- `tmp/` 已加入 `.gitignore`，不允许提交。

## 测试目录组织

- `tests/backend/`、`tests/agent/`、`tests/algorithm/<子系统>/`
- 与算法源码强耦合、需要动态加载版本内模块的测试，可暂时保留在 `algorithm/<子系统>/tests/`，但应尽量迁移到 `tests/`。

## 与 `AGENTS.md` 的关系

`AGENTS.md` 从交付镜像角度约束「哪些东西不能进镜像」；本文从开发维护角度约束「东西应该放在哪里」。两者共同保证：

1. 算法版本目录干净、只含算法；
2. 测试/数据/评测/产物不污染运行时源码包；
3. `latest` 是可独立演进的生产版本包。
